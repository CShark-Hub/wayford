Notes per step:

- **Order.** Step 1 comes first. Steps 2, 4, 5, 6 and 9 then fan out. Step 3 waits for 2, since its route calls `runner.cancel`. Step 7 waits for 5 and 6. Step 8 waits for 7. Parallel steps share one worktree, so each runs only its own files' tests. Package typechecks wait for each phase's end, when no step is mid-edit.
- **Step 2.** `lives` holds the writers so `cancel` can end a stream. `job` returns when `await slot` answers `false`, before the step-cap read, and never calls `slots.free()`. Build the terminal event with `RunEvent.parse`, as `ownFailure` does, never through `closeOut`. Keep agent imports type-only (`packages/io/src/index.test.ts`).
- **Step 3.** Load the race (awaited), then read `raceStatus`, then call `runner.cancel`, with no `await` in between. Write the record only when the stop dropped runs. One way to make the write fail in a test is `PRAGMA query_only = ON` on the store's SQLite connection once the race is stored. If `packages/io/src/test-app.ts` needs a helper for it, add it there with its line in the file's header list. The file is not in the spec's Files, but it is the only home io's tests have for helpers.
- **Step 6.** `waiting` is required in web's schema, so every race answer a test or a fixture serves must carry it. Grep for `status: "running"` and `status: "finished"` beside `runs:` in `packages/web`.
- **Step 7.**
  - The mutation stays out of `RaceView`, whose tests have no `QueryClient`.
  - Build the dialog on `AlertDialog` from `radix-ui` with the settings dialog's overlay and content classes, no animation classes, and no `destructive` class (`--color-destructive` is fault red).
  - Test the body as a pure component, since a Portal renders nothing statically.
  - `pending` is `isPending || isSuccess` in `LiveRace`.
- **Step 8.** `demo-race.ts` is the check-safe fixture self-check reads. A variant with a run still waiting goes there; it is web's fixture for races, which the spec's last Files row covers. The waiting-run entry joins `self-check.browser.test.ts`'s fit table. If axe flags Radix's focus guards in the open-dialog entry, stop and report it rather than excluding them.

The last step is always verification: `pnpm lint`, `pnpm typecheck`, `pnpm test` and every acceptance command in the task file.
