## Notes

- **Step 1** is the orchestrator's: it changes the lockfile and the two shared files (`router.tsx`, `shell.tsx`), so steps 3 and 4 then each own only their own files and can run at once. `runs.tsx` gets `validateSearch` in step 4, once `RunsSearch` exists; `run-detail.tsx` gets `RunDetailSearch` in step 3. The skeleton routes take no search params until then.
- **Step 2** also exports, from `src/runs/fixture-runs.ts`, the list the later tests share: `runResultFixture` itself, plus variants for Ada, Milo, Vera, Zoya and an unknown persona on both fixture tasks, mixing `success`, `gave_up`, `budget_exceeded` and `error`, each re-parsed with `RunResult`.
- **Steps 3 and 4** render screens as `router.test.tsx` does: `createAppRouter` on a memory history, `await router.load()`, `renderToStaticMarkup`, with a `QueryClient` seeded through `setQueryData(runsQuery().queryKey, …)` and the matching keys, so no fetch runs. Each formats only its own files (`pnpm exec biome check --write <files>`), never the whole repo, since the other runs at the same time.
- **Step 5:** `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm --filter @wayford/web test`, `pnpm --filter @wayford/web build`. Then the click boxes in the browser against a scratchpad stub of the s4-03 routes on port 3000 (not committed): `/runs`, filter by persona, reload, open a run, step through, screenshots and the video and trace links. The `pnpm dev` box stays open until s4-03 merges; the task file says so in an `Outcome` line.
