## Decision log

| Question | Taken | Why |
|---|---|---|
| Fit the whole page, or crop at a fixed scale as `lens.html` does | Keep fitting the whole cropped canvas, and give the stage back the height the scale is bound by | The page is measured at 1280 × 720 and drawn at its measured boxes, so its aspect is 16:9. In a stage box about 900 × 380, the height binds. "Order archive" sits at y 603 to 639, so any crop that keeps the page's top in view must show about 650 measured px, which allows a scale of about 0.59 against the whole fit's 0.53. Fixed-scale cropping gains ~10 % and hides elements perceive returned, such as Kai's list in beat 3 or a footer. `lens.html`'s 16 px text is a redrawn layout, not the measured one, and no crop that keeps the top reaches it at 1280 × 720 |
| Where the URL row goes | Behind an icon button in the header row, open on demand | The header row has about 200 px between the page picker and the View control, too narrow for a URL field. On demand, the beats on the target app never pay for it, and the finals' Lens opens a URL from the Target screen's link anyway. The form itself is unchanged |
| Open by default on a URL page | No, closed everywhere | The finals show the Lens on our pick, a URL page, and need the height there too. The page's URL is on the `Live:` line under it |
| Where the `Live:` line goes | The caption's second line | DESIGN keeps it in the stage, beside the data. The caption is already two lines tall in both views and the perceived sentence fills one, so the `Live:` line costs no height there; the evidence sentence is shortened to one line so the two views stay the same height and flipping them never moves the page |
| The axe card's note | `Scanned once per page, on desktop.` under a live page's `Live:` line; where no `Live:` line stands (a stored page, the illustration view, a failed URL page), the parameters stay in the note (review) | The card wraps its note onto two lines and is the strip's tallest cell. The parameters it named, the target app's default or as given, are the same page's and stand on the `Live:` line directly above. The first cold review found the short note named no parameters where that line is absent |
| The measuring surface's padding | 8 px top and bottom, 16 px at the sides | The corner ticks are inset 8 px and 12 px long. A height-bound frame is centred across, so it stays clear of them, and 16 px goes back to the page |
| The button's name | `Open a URL` (build) | The form it shows is already named `Open a page by URL`; two controls with one name would read the same to a screen reader |
| The URL row after a page link and Back | Hidden: a navigation to another page clears the page it was shown on, during render (review) | The cold review found Back brought the row back with its field focused, costing the stage its height again |
| The page title beside the new button | It truncates on the demo's pages at 1280 × 720 ("Deliveries · Q…"), its whole text in its `title` (review) | The header row has no other width to give: the page picker and the View control are fixed, and the title is the one flexible item. The page's own title is the least read thing on the stage, and the picker names the path |
