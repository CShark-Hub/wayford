## Notes per step

**Step 2.** `runner.ts` imports agent as types only: `RunActorOptions`, `ActorBackendFactory`, `TargetAppParams`. `test-app.ts` gets `fakeRun` and `tempDatabase()` here, and `testApp()` in step 3. `fakeRun(script)` takes a function from a run's options to its script: gate, step, throw before or after the start, the end (`runFinished` with an outcome, or `runFailed`), and stored paths. It records each call's options. Its `runStarted` uses `startUrlFor(task, params)` and `modelIds: { actor: "fake" }`. The files it names are written under `<runsDir>/<runId>/` as `<label>-seed<seed>-<runId>.webm`, `.trace.zip` and `-step-0.png`.

**Step 3.** `AppOptions = RunnerOptions & { llm, replaySpacingMs? }`. `testApp(overrides)` builds a temporary folder `<tmp>/` holding `runs/` and `wayford.sqlite`. Its defaults are the fake extractor `Llm`, `fakeRun()`, an `actor` that throws if called, `TARGET_APP_DEFAULTS`, a silent pino logger and `replaySpacingMs: 0`. It returns `{ app, db, dir, runsDir, close }`. `app.test.ts` and `extractor.test.ts` switch to it. Their tests stay as they are, except that `POST /tasks` now also stores.

The SSE route waits with `Promise.race([live.changed(), aborted])`, where `aborted` resolves on `stream.onAbort`, so a client that disconnects frees its handler. If a cancelled reader does not abort `streamSSE` under `app.request`, the disconnect test serves the app on port 0 with `@hono/node-server` (spec, Risks).

**Step 4.** `playwright` is added at agent's range, `^1.63.0`. `pnpm install` must change only io's importer entry in `pnpm-lock.yaml`, with no new package. A launch failure carries run-one's message (Chromium did not launch; install it with `pnpm --filter @wayford/agent exec playwright install --only-shell chromium`) and its cause.

**Step 5.** The browser test serves the app with `serveTargetApp()` and stores a task built from `task_next-parcel` with `startUrl` set to the served origin. `actor` is `llmActor({ settings, llm: () => fakeLlm({ actor: [answer, answer, answer] }) })`, where `answer` is a function entry that reads the page from the request: it clicks link "Delivery address" when shown, else link "Your account", else gives up. `settings` uses the model id `fake`, as agent's loop test does, so no real adapter can be built. `fetch` is stubbed to throw once the app is up. The server boot check uses a temporary `DATABASE_URL` and `PORT`, so it touches no developer database.

**Step 6.** The real-key box needs `LLM_API_KEY` in the worktree's `.env`. That file is not in git; the user provides it or allows a copy of theirs. The run is `pnpm dev`, then `POST /tasks` for the easy goal, `POST /runs` for `prof_ada`, `prof_vera` and `prof_zoya` with one seed, `curl -N` on each stream and `GET /runs`. The output goes in the task file's Outcome and the PR.
