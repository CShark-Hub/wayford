## Notes

**Step 1.**
- Add `zod@^4.6.5`, `yaml@^2.8.1` and `pino@^10.3.1` as dependencies, and `@types/node@^24.19.0` and `tsx@^4.23.13` as dev dependencies. The first two versions are the ones core already uses, and pino 10.3.1 dates from February 2026, so the release-age policy passes.
- Add `"smoke:llm": "tsx src/smoke-llm.ts"`.
- In `tsconfig.json`, add `"compilerOptions": { "types": ["node"] }`, as filter has it.
- If pnpm writes a `minimumReleaseAgeExclude` into `pnpm-workspace.yaml`, revert both files and pick an older range. Do not keep the exclusion.

**Step 3.**
- `models.yaml` holds the four entries from the spec: Luna, Sol, Opus 5.5, and a local Ollama model, quoted as `"llama3.1:8b"`, with `jsonSchema: false`.
- The header names the source (OpenRouter's list, 2026-09-30) and the ladder doc by title, author and date.
- Comments: on Luna and Sol, their 272k-and-up rates; on Opus, no seed, reasoning always on, temperature only on Azure.
- `loadModelPrices` reads the file from `new URL("../models.yaml", import.meta.url)`.

**Step 4.**
- **Injected dependencies.** The tests pass `fetch`, `sleep` and a small `timeoutMs` through `deps`. The global `fetch` is stubbed to throw (`vi.stubGlobal`), so a test that forgets to inject fails.
- **Logger.** A real pino instance writes to an in-memory stream, so the tests can assert the log lines.
- **Settings.** The per-role test builds its own settings with a different model, temperature and effort per role. The model ids it uses must be priced; it may pass the three priced ids and the Ollama id.
- **Timeout test.** The fake `fetch` honours `init.signal` and rejects when it aborts. The test expects exactly one call and `llm_request_failed`.

**Step 7.**
- The script is the only reader of `process.env`.
- It loads the root `.env`, resolved from `import.meta.url`, with `process.loadEnvFile` when the file exists.
- It builds a pino logger and runs the two calls from the spec. It prints each object and a cost line with the effort and the elapsed ms.
- It exits non-zero with the error's message on failure, and never prints the key.

**Step 8.**
- Remove `LLM_BASE_URL`, `LLM_API_KEY` and the loopback rule from `config.ts`, with their tests.
- Change the `.env` comment to "the only place io reads `.env`".
- Keep everything else as it is.

**Step 9.**
- `.env.example` is denied to the Read tool in this session. If writing it is denied too, the step hands the user the exact new content instead.
- STACK's Env row gains the clause that agent's smoke script reads the same root `.env` with Node's `process.loadEnvFile`.
- PLAN's "AI access" line gains "and an optional reasoning effort".

**Step 10.** The last step is verification: `pnpm lint`, `pnpm typecheck`, `pnpm test` and every acceptance command in the task file. `smoke:llm` needs a real key in the root `.env`. The key holder runs it and pastes the output in the PR.
