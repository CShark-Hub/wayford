## Notes

**All steps.**
- Paths under `src/` and `public/` are in `packages/web/`. Every command runs in the worktree, `/Users/tomasz/Developer/cshark/promptozaury/.claude/worktrees/s3-01-task-42dffe`.
- Steps 2, 3 and 4 run at the same time. Each runs its own test file and `biome check` on its own files; a typecheck error in another step's file is reported, not fixed.
- The orchestrator reads each diff, runs its done-check, and commits it as `s3-01: <step>`.
- Tests read fixtures from `@wayford/core/fixtures` (Node), never from `bundled-fixtures.ts`, except the deep-equal test and the screen tests, which go through the app.
- UI strings follow the spec's copy rules: sentence case, no em or en dash, at most one middle dot per line, no uppercase eyebrow labels.

**Step 1.**
- `pnpm --filter @wayford/web add @wayford/filter@workspace:* zod@^4.6.5 framer-motion`. zod 4.6.5 is already locked for core. Take `motion` instead if `npm view framer-motion deprecated` says the old name is deprecated. If pnpm writes a `minimumReleaseAgeExclude` into `pnpm-workspace.yaml`, revert and pin the newest version it accepts.
- Fonts, each family in its own folder with its licence:
  - `public/fonts/inter/inter-latin-wght-normal.woff2` and `OFL.txt`, copied from `packages/target-app/public/fonts/`;
  - `public/fonts/jetbrains-mono/jetbrains-mono-wght.woff2`, downloaded from `https://raw.githubusercontent.com/JetBrains/JetBrainsMono/master/fonts/webfonts/JetBrainsMono%5Bwght%5D.woff2` (113 672 bytes, starts with `wOF2`), and `OFL.txt` from the same repository's root.
- `index.css`: two `@font-face` rules (`font-weight: 100 900` and `100 800`, `font-display: swap`) and a `@theme` block setting `--font-sans` to Inter and `--font-mono` to JetBrains Mono, each followed by the stack Tailwind uses today.
- `bundledMeasurement` follows `bundledProfiles`: an eager glob of `@core-fixtures/measurement.json` with `import: "default"`, exactly one entry or throw, `PageMeasurement.safeParse`, an `Error` naming the file. The header comment's "s3-01 adds" sentence becomes a description of what is there.

**Step 2.**
- `search.ts` imports `bundledProfiles` for the persona ids and the persona lookup; `zod` for `PreviewSearch`; `Seed`, `Probability`, `METRIC_NAMES`, `MetricName`, `Profile` from core.
- Softness keys are `contrastSoftness`, `fontPxSoftness`, `targetPxSoftness`.
- `resolvePreview` throws a plain `Error` if the validated persona is not bundled: only a bug reaches it.
- `edited` compares the effective `perception` with the persona's own, metric by metric (threshold, and softness with absent read as 0), never the raw search, so a softness under an off threshold is not an edit.

**Step 3.**
- One element per drawn box, with no nested `<div>`; a checkbox's or radio's name is a nested `<span>`. Attributes: `data-ref`, `data-state`, and a `style` with `left`, `top`, `width`, `height` and `font-size`, each `calc(<px> * var(--px))` with the measured number as given.
- The evidence outline is a `<div data-removed>` with the same box style, an `sr-only` name, a `title` with the full decisions, and the tag.
- Motion: drawn and outline boxes are `motion.div`s inside one `AnimatePresence initial={false}`, keyed by their index in `observation.elements`, with the spec's enter and exit (opacity, 2 px blur, scale 0.98, 160 ms). The degraded colour change is a `motion-safe:transition-colors`. The component does not set `MotionConfig`; the screen does.
- Tests parse each style property, since Motion adds its own inline keys.
- Tests build observations by calling `perceive` on `measurementFixture` with chosen profiles and seeds, and check that the chosen cases include visible, degraded and invisible elements.

**Step 4.**
- `SearchSlider({ id, label, value, min, max, step, format, disabled, tick, onMove, size })`: `tick` is the persona's own value or `undefined`; `size` is `"default"` for a threshold and `"sub"` for softness.
- Local `moving: number | null`: set in `onChange` from `valueAsNumber`, cleared during render when it equals `value`, and on blur.
- `--fill` is `(shown − min) / (max − min)` as a percentage, clamped to 0 to 100; `--tick` the same for `tick`. Both are inline custom properties, read by `.wf-range` and the tick element.
- `.wf-range` in `index.css` covers `::-webkit-slider-runnable-track`, `::-webkit-slider-thumb`, `::-moz-range-track`, `::-moz-range-progress` and `::-moz-range-thumb`, and colours from `var(--persona, var(--foreground))`, so the slider works outside the screen too.

**Step 5.**
- `previewRoute`: `createRoute({ getParentRoute: () => rootRoute, path: "/preview", validateSearch: (raw: Partial<PreviewSearch> & SearchSchemaInput) => PreviewSearch.parse(raw), component: PreviewScreen })`.
- `router.tsx`: `rootRoute.addChildren([indexRoute, eventsRoute, personasRoute, previewRoute])`. `shell.tsx`: a "Preview" item between Personas and Events.
- The screen root sets `--persona` from `personaColour(state.persona)` and wraps everything in `MotionConfig reducedMotion="user"`.
- Persona panel: `Avatar` for `{ ...state.persona, perception: state.perception }`, the switcher pill as a `motion.span` with `layoutId="preview-persona-pill"`.
- Navigation from a slider or the `View` control: `replace: true, resetScroll: false`. Persona links: `resetScroll={false}`.
- Redraw timing as the spec says, behind `import.meta.env.DEV`.
- `screens/preview.test.tsx` starts with `vi.mock("@wayford/filter/perceive", async (importOriginal) => { const actual = await importOriginal<…>(); return { ...actual, perceive: vi.fn(actual.perceive) }; })`, clears the spy before each render, and has its own render helper through `createAppRouter` with a memory history, as `router.test.tsx` does.
