**Who builds what.** Steps 1 and 3 each go to one subagent. Steps 2 and 4 are a single command and a single sentence, so the orchestrator runs them, as the skill allows when handing them out costs more than doing them. Step 2 is the only step that touches `pnpm-lock.yaml`.

**Step 1.**
- `newId` reads `crypto` through the local cast from the spec, inside the function, never at module load.
- `strippedPathsIn` keeps `wholeTerm` private. `Task`'s `superRefine` calls the new function in place of its inline filter, and its message stays word for word.

**Step 3.**
- **Fake.** Tests import `fakeLlm` from `@wayford/agent/fake` and `LlmError` from `@wayford/agent`, and build the app with `createApp({ llm: fake, replaySpacingMs: 0 })`.
- **The `400` hook.** If `@hono/zod-validator`'s `result.error` is not accepted by `z.prettifyError`, format `result.error.issues` instead (spec, Risks). Do not add a cast that hides the type.
- **`server.ts`.** It builds the `Llm` after `loadConfigFromEnvFile()`, so `.env` is merged into `process.env` first. No other file reads the environment.
- **Done-check.** Run vitest directly: `pnpm --dir <worktree>/packages/io exec vitest run --reporter=verbose`. `pnpm test -- <flags>` ignores its flags.

**Step 5, the real-key box.**
- **The key.** The user places a `.env` in the worktree root, or runs the `curl` themselves. The agent does not copy or read `.env`.
- **The stack.** Start it with `env -u PORT pnpm dev` as a background task. Afterwards stop the `tsx` and Vite node processes by PID.
- **Credit.** If the default model answers `402`, retry that one command with `LLM_EXTRACTOR_MODEL=qwen/qwen3.8-27b:free` and `LLM_EXTRACTOR_EFFORT=medium`, and record that in the PR.
- **Probes.** The spec's three stories, each through `curl`, with the outputs kept for the PR.

The last step is always verification: `pnpm lint`, `pnpm typecheck`, `pnpm test` and every acceptance command in the task file.
