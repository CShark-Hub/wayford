# s4-03 — Runs API: start, stream, store, list: spec

Task: `tasks/s4-03-runs-api.md` · Branch: `feature/s4-03-runs-api` · Date: 2026-10-02
Status: approved 2026-10-02

## Goal

`POST /runs` starts persona × seed runs inside the io process, each run streams its events live, every run is stored when it ends, and the web app can list, open and download runs.

## Constraints that bind

- "One Node process: no queue, no workers. One browser, one context per run (F6 AC1), at most 5 runs at once" (task; `docs/PLAN.md`, "Architecture").
- "Every persona in one request gets the same seed list (A20)"; "a repeated seed is a 400" (task).
- "io mints each `RunId` before its run starts and passes it to `runActor`" (task; F7 AC4: the run id is the run's only number).
- SSE keeps m0-07's framing: `event:` the type, `data:` the event as JSON, `id:` its index in the run, `Last-Event-ID` resumes, 204 once the client has seen the last event (`packages/io/src/routes/runs.ts`).
- "The stored `RunResult` is `runResultFromEvents` of exactly the events streamed. A run that crashes is stored with outcome `error` and does not stop the others; a client that disconnects does not stop a run" (task).
- "Validation at the edge with `@hono/zod-validator` and the core schemas. Responses are core shapes" (task; `docs/STACK.md`, "API").
- "Downloads name persona, seed and run id (F12 AC3) and serve only files under the runs directory" (task). From s2-03: "resolve stored paths against `<runsDir>/<runId>` and serve only what stays inside it". From s2-02: "encode non-ASCII persona labels in download headers".
- "Tests use a fake runner behind the same interface as `runActor`; one test runs the real `runActor` with the fake LLM adapter against the target app" (task). No test calls a real LLM (`docs/CONVENTIONS.md`).
- Out of scope: UI, several runs over one connection, live video, cancelling or retrying runs, Scout before the runs (task).
- io's library imports agent as types only; only `server.ts` loads agent's runtime at boot (`docs/specs/2026-10-01-s4-01-extractor.md`, decision log).
- One error class, `WayfordError`, branched on `code` (`docs/CONVENTIONS.md`, "Errors").

## Design

### What `runActor` already guarantees (s2-03)

A run that emitted `runStarted` ends with exactly one terminal event. `onEvent` is called synchronously with every event, the terminal one last, after `result.json` is written. Files go under `<runsDir>/<runId>/`, and the stored paths are relative to that folder. `runActor` rejects before any event only when no run can start. io builds on these guarantees and checks them where a fake could break them.

### Modules (all in `packages/io/src/`)

**`runner.ts`: the in-process job runner.** Agent is imported as types only.

```ts
/** `runActor`'s interface without the browser, which belongs to whoever builds the function (`chromium.ts`). */
export type RunFn = (options: Omit<RunActorOptions, "browser">) => Promise<RunResult>;

export interface RunnerOptions {
  db: Db;
  run: RunFn;
  actor: ActorBackendFactory;      // one backend per run, built by runActor
  params: TargetAppParams;         // the target app's parameters for every run
  runsDir: string;                 // absolute
  logger: Logger;
}

export interface StartedRun { id: RunId; profileId: ProfileId; seed: Seed }

export interface LiveRun {
  /** Published so far, in order. The terminal event comes last, and only once the run is stored. */
  readonly events: readonly RunEvent[];
  readonly ended: boolean;
  /** Resolves at the next publish or at the end. */
  changed(): Promise<void>;
}

export interface Runner {
  /** Mints one id per seed × persona, in seed-major order, and queues the runs. Returns at once. */
  start(task: Task, profiles: readonly Profile[], seeds: readonly Seed[]): StartedRun[];
  /** The run with this id, started by this process, or `undefined`. */
  live(id: string): LiveRun | undefined;
}

export const MAX_CONCURRENT_RUNS = 5;
export function createRunner(options: RunnerOptions): Runner;
```

Each run's job:

1. Waits for one of the 5 slots, held in a FIFO in memory shared by every request.
2. Calls `run({ profile, task, seed, params, runsDir, backend: actor, logger, runId, onEvent })`. `onEvent` publishes each event as it arrives and holds back the terminal event.
3. When `run` settles (resolved or rejected), frees the slot and closes the run out:
   - **Terminal held:** fold `[...published, terminal]` with `runResultFromEvents`.
   - **`runStarted` published, no terminal:** a fake broke the contract, or `runActor` hit a bug. io builds its own `runFailed`: the rejection as `code: message` for a `WayfordError` and as a string otherwise ("Error text on the stream" below), the last observed step's index (0 if none), the duration since `runStarted`, and the cost summed over the run's `actionPlanned` and `stepWasted` events. Then it folds as above.
   - **No `runStarted`:** the run never started. io publishes a bare `runFailed` so the stream ends, logs the error, and stores nothing (decision log).
4. `saveRun(db, result, runStarted.timestamp)`. If the fold or the save throws, io logs it at `error` and does not retry.
5. Publishes the terminal event and marks the run ended. The stream therefore ends only after the save has been tried, and a client that saw the end finds the run in `GET /runs`, unless the save failed (decision log, "Storing fails").

The stored record is io's own fold of the published events, not the value `run` returns. "Stored = fold of what was streamed" then holds by construction, for a fake too. The live map is the `Runner`'s, so concurrent apps share nothing. Live runs stay in memory for the life of the process.

**`chromium.ts`: `runActor` on one shared Chromium.** Loaded only by `server.ts` and the tests.

```ts
/** `runActor` on one Chromium for every run: launched by the first run, reused, launched again after a disconnect. */
export function sharedChromium(launch?: () => Promise<Browser>): RunFn;
```

It holds one launch promise, not a browser. Runs that start together await the same promise, so five first runs still launch one browser (F6 AC1). The promise is cleared when the browser disconnects or the launch rejects, so the next run launches again. The `RunFn` is `(options) => runActor({ ...options, browser: await shared() })`, and `runActor` opens one context per run. Playwright's default signal handlers close the browser when the process gets SIGINT or SIGTERM. (build) The first build also returned a `close()`; the branch review cut it, since nothing in production called it.

**`run-files.ts`: a run's files, served safely.**

```ts
/** `stored` resolved against `<runsDir>/<runId>/`, or `undefined` when it lands outside that folder (`..`, absolute) or `runId` is no `RunId`. */
export function runFilePath(runsDir: string, runId: string, stored: string): string | undefined;
/** `attachment` with an ASCII `filename` (accents stripped, any other non-ASCII as `_`) and an RFC 5987 `filename*`. */
export function attachment(fileName: string): string;
```

**`routes/runs.ts`** (mounted at `/runs`):

| Route | Answer |
|---|---|
| `POST /` | Body `RunsRequest = { taskId: TaskId, profileIds: ProfileId[] (min 1), seeds: Seed[] (1 to 10) }`, strict. A repeated seed or profile id is a 400. 400 `{ error }` for any invalid body; 404 `{ error }` naming an unknown task or profiles; 415 `{ error }` for a body not sent as `application/json` (`app.ts`). On a 400, 404 or 415 no run starts. Otherwise 202 `{ runs: StartedRun[] }`. The task comes from `loadTask`, the profiles from core's `profileFixtures`. |
| `GET /` | Query `{ taskId?, profileId?, outcome? }` (`TaskId`, `ProfileId`, `RunOutcome`), strict, else 400. `listRuns(db, filter)` returns `RunResult[]`. |
| `GET /:id` | `loadRun`, or 404. |
| `GET /:id/events` | `fixture` keeps m0-07's replay. Any other id streams its live run: buffered events from the resume index, then each new one as it is published, closing after the terminal event. 204 when `Last-Event-ID` is at or past the last event of an ended run; 404 for an id this process has not started. |
| `GET /:id/video`, `GET /:id/trace` | The stored run's `videoPath` or `tracePath` through `runFilePath`. 404 when the run or the path is missing, the path lands outside, or no file is there. Otherwise the bytes as `video/webm` or `application/zip`, with `Content-Disposition: attachment(basename)`. |
| `GET /:id/steps/:index/screenshot` | That step's `screenshotPath`: from the live run's `actionPerformed` while it runs, so the ring shows the latest screenshot live (s3-03), otherwise from the stored run. `:index` is digits. Same 404 rules; `image/png`. |

**`routes/tasks.ts`:** `POST /` now runs `saveTask` before answering 201. The other answers are unchanged. `GET /` returns `listTasks(db)` as a `Task[]`.

**`routes/profiles.ts`:** `GET /` returns `profileFixtures` as a `Profile[]`.

**`app.ts`:**

```ts
export type AppOptions = RunnerOptions & { llm: Llm; replaySpacingMs?: number };
export function createApp(options: AppOptions): Hono; // mounts /health, /profiles, /runs, /tasks; builds one Runner
```

(build) Its `onError` answers every error as `{ error }`. Hono's own 400s, such as a JSON body that does not parse, keep their status and message; anything else is a logged 500. (review) A `POST` whose body is not `application/json` is a 415 before any route runs (decision log).

**`server.ts`:** reads the config and builds the logger and the Extractor's `Llm`, as before. It then runs `migrateDatabase(DATABASE_URL)` and `openDatabase`, sets `runsDir` to `<repo>/runs/` (the folder `run:one` writes to, which is gitignored), and builds `actor` as `llmActor({ settings })`, `params` as `TARGET_APP_DEFAULTS` and `run` as `sharedChromium()`.

**`test-app.ts` (tests only, not exported):** an app on a temporary database and runs folder, plus `fakeRun`, a `RunFn` scripted per run. A fake run emits a real `runStarted` built from its options. Then it can wait on a gate, emit one step from `observationFixture` with a screenshot it writes to disk, or throw before or after starting. Otherwise it ends with a terminal event of its own: a `runFinished` of a chosen outcome, or a `runFailed` as `runActor` sends for a crash. Either one names a video and a trace it writes as `<label>-seed<seed>-<runId>.webm` and `.trace.zip`, or paths it is given. It returns the fold of its events.

**The barrel (`src/index.ts`) is unchanged.** The new modules are io-internal, as the Extractor is (s4-01). `chromium.ts` must stay out in particular: it loads agent's runtime and Playwright, and the barrel would then load them for every io importer.

### Data flow

`POST /runs` → validate → `loadTask` + profile lookup → `runner.start` → 202. Each job then runs: slot → `run(…, onEvent)` → publish → `GET /runs/:id/events` streams. At the end: close-out → fold → `saveRun` → publish the terminal event → the stream closes → `GET /runs` lists the run.

## Risks

- **This machine's Chromium draws no frames.** The baseline's `settle` animation test fails here and passes in CI. Target-app pages do not animate, and s2-03's loop tests pass locally, so the browser test should pass. CI is the reference.
- **The list's size.** Each `RunResult` carries every step's full observation. A few hundred runs make a list of several MB. A summary route would be a follow-up.
