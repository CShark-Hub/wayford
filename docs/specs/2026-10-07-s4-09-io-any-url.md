# s4-09 — io on any URL: the Lens's measurement and axe: spec

Task: `tasks/s4-09-io-any-url.md` · Branch: `feature/s4-09-io-any-url` · Date: 2026-10-07
Status: approved 2026-10-07 (auto)

## Goal

`GET /measure` and `GET /axe` take any http(s) URL as well as a target-app path, everything io stores or caches about a page is keyed by its whole URL, the Analyst tells the target app by its origin and scans the pages a foreign run visited, and io refuses a request addressed to another host or sent from another site.

## Constraints that bind

- ADR 0003 D2: "The Lens decides by its own link: `page=` is a target-app page, `url=` is any page." D4: off the target app a failed font is logged, not an error, and an endless animation is not waited on; on the target app `settle` stays strict. D5: "What it stores and caches is keyed by the whole URL, origin included." D7: refuse a foreign `Host` and `Sec-Fetch-Site: cross-site`; the dev proxy sets `changeOrigin`. D10: a report scans at most ten distinct pages, those the most runs visited.
- Task, Constraints: axe stays a measurement and never a filter input. A scan that did not run says so, never "0 violations". No URL from a request is fetched by anything but the Chromium io already runs. The target app's pages give the same measurement and scan as before.
- Task, Interface: `page` keeps working, so web's app code does not change. A failed load off the target app names the page and its URL, never "the target app". Dropping the old `axe_results` rows is fine.
- Out of scope: the Lens's URL field (`s3-16`), Scout over HTTP and the sweep (`s4-10`), measuring a page again without a restart, iframes, shadow DOM, cookie banners, logins.
- `docs/STACK.md`: io imports core, filter and agent; web imports core only; no new dependency. `docs/CONVENTIONS.md`: one `WayfordError` with a `code`; barrels get one added line.

## Design

### The page: `PageRef` (io, new `page-ref.ts`)

```ts
/** A page io opens for the Lens or axe-core (ADR 0003 D2). */
export interface PageRef {
  /** Its whole URL as `new URL(…).href` spells it: the key of everything io keeps about it. */
  url: string;
  /**
   * A target-app page, named by `page=` or by a run on the target app's origin: opened as runs on
   * the app are, with the strict `settle`. Any other page is opened as given, with the lenient one.
   */
  onTargetApp: boolean;
}

/** `path` with `search` on the target app at `origin`: `targetAppPage(origin, "/deliveries", TARGET_APP_DEFAULT_QUERY)`. */
export function targetAppPage(origin: string, path: string, search: string): PageRef;

/** What messages and findings name a page by: a target-app page's path, any other page's URL. */
export function nameOf(page: PageRef): string;

/** A `url=` query value: trimmed, spelled as `new URL(raw).href`, then checked as an `AxeUrl`. */
export const pageUrlParam: z.ZodType<string, string>;

/**
 * The `page` and `url` keys of a `/measure` or `/axe` query, and their transform into one
 * `PageRef`: `page` on `targetAppOrigin` at the app's defaults, `url` as given. Both is a 400, and
 * so is neither unless `defaultPage` names one.
 */
export function pageQuery(targetAppOrigin: string, options?: { defaultPage?: string }): { keys; pageRef };
```

`pageUrlParam` takes `https://example.com` and gives `https://example.com/`, so two spellings of one page share one key. What `new URL` cannot parse gets its own message; the rest is core's `AxeUrl`, so a `url=` and a stored key share one rule: no `file:`, `data:`, `javascript:` or `chrome:`, no single-label host, no user or password. The hash is kept: on a hash-routed app it names another page.

A URL on io's own host passes the query. io's Chromium reaching io, by a `url=` naming it or by a page that redirects into it, is refused by the middleware in `app.ts` (`Sec-Fetch-Site: none` with `Sec-Fetch-Mode: navigate`), and the request ends as a 502 `page_unavailable … answered 403`.

### core: `AxeUrl` (`packages/core/src/axe.ts`)

`AxeUrl` becomes the whole URL: core's `HttpUrl`, the rule `RunStep.urlBefore` and `PageMeasurement.url` follow, with no user or password, and equal to its own `new URL(url).href`, so one page has one key. The target app's pages carry the app's query: `http://localhost:5174/settings/data?contrast=2&fontPx=16&targetPx=36`. `AxeScan` is unchanged apart from what `url` accepts. The doc comment says why the origin is in the key now (D5) and that the target app's rows are keyed on the target-app origin io is configured with.

The fixture `axe-scans.json` gets `http://localhost:5174` in front of both URLs, the origin core's task fixtures start on. `axeScanFixture(page)` finds a scan by `new URL(scan.url).pathname`. `axe.test.ts` keeps its fixture test with the new URLs and turns the refusals around: a path alone, a protocol-relative URL, `ftp:`, credentials and a non-canonical spelling are refused; an origin and a hash are accepted.

### io: one page loader (`live-measure.ts`)

`withOwnContext` takes `lenient?: boolean`, absent on the target app, as agent's `settle` takes it. `openTargetAppPage` becomes `openPage(page, url, path, work, lenient)`:

1. `page.goto(url, { timeout })`. A failure, or a response that is null or not OK, is `target_app_unavailable` worded as today on the target app, and `page_unavailable` off it, worded "the page at `<url>` did not load: …" and "the page at `<url>` answered `<status>`".
2. `settle(page, { lenient })` from `@wayford/agent`. Strict, it waits for what `FONTS_SOURCE` waits for today (the `load`, `document.fonts.ready`, no failed face) and for no running animation, which the target app never has. Lenient, it skips failed faces and endless animations and still waits for the `load`, the fonts and every finite animation, as a run off the target app does. What it skipped is dropped: no run reads it, and the Lens's measurement is no run's evidence.

After the load, the settle and the caller's work run together inside agent's `retryOnNavigation`, with the work's own deadline as each attempt's, on every page, as the Actor loop settles and collects for every run. A navigation that cuts them off, or that commits between the two, has them run again on the new document instead of failing as `browser_failed`. One that commits after they end is not seen, so a page that redirects itself a while after its `load` is taken where it was.

Load times follow a run's. On the target app nothing changes: 10 s to load, and the deadlines of 15 s to measure and 30 s to scan. Off it a page gets Playwright's default 30 s to load, as `run-context.ts` opens a start URL, and each deadline grows by the 20 s that adds: 35 s to measure, 50 s to scan.

`FONTS_SOURCE`, `FONTS_TIMEOUT_MS` and the font check in io go: the s3-05 follow-up, "use `settle` once agent exports it". Agent's barrel gets one line, `export * from "./settle.js";`, which brings `settle` and `retryOnNavigation`.

`liveMeasure({ browser, targetAppOrigin })`: the route hands it a `PageRef`, whose URL is already whole. A page on `targetAppOrigin` loads strictly, every `page=` and a `url=` that can share a `page=` key alike, so one cache key is filled one way.

```ts
export type MeasureFn = (device: MeasureDevice, page: PageRef) => Promise<PageMeasurement>;
// liveMeasure: (device, page) => withOwnContext({ browser, device, url: page.url, path: nameOf(page),
//   work: "measuring", timeoutMs: MEASURE_TIMEOUT_MS,
//   lenient: new URL(page.url).origin !== targetAppOrigin }, collect…)
```

Messages name the target-app path on the target app, as today, and the whole URL off it. `live-illustration.ts` is untouched: it passes no `lenient`, so it loads strictly through `settle` too.

### io: `GET /measure` (`routes/measure.ts`)

Query: `device` (default `desktop`), and `page` or `url`, not both, read by `pageQuery(targetAppOrigin, { defaultPage: "/deliveries" })`.

- `page`, checked against `TARGET_APP_PATHS` as today, is `targetAppPage(targetAppOrigin, page, TARGET_APP_DEFAULT_QUERY)`.
- `url` is `{ url, onTargetApp: false }`, read by `pageUrlParam`.
- Neither is `page=/deliveries`, as today.
- Both is a 400, and nothing is measured.

`measureRoute({ measure, targetAppOrigin })` takes the origin from `AppOptions`, which already holds it for the runner. The map's key is `${device} ${page.url}`. It is kept until io restarts, as today; a failure is dropped.

### io: axe (`axe.ts`, `axe-scan.ts`, `routes/axe.ts`, `db/`)

```ts
export type AxeScanFn = (page: PageRef) => Promise<AxeScan>;
export type AxeLookup = (page: PageRef) => Promise<AxeScan>;
```

- `axeLookup` keys its store and its in-flight map by `page.url`. `axeUrl(page, search)` goes: callers build a `PageRef`.
- `axeScanner({ browser, targetAppOrigin, servedOrigin = targetAppOrigin })`:
  - on the target app: `page.url` must be an `AxeUrl` on `targetAppOrigin`, its path in `TARGET_APP_PATHS`, its query the app's three parameters spelled as `startUrlFor` spells them, or it is `invalid_axe_url`, as today plus the origin check. It is opened at the same path and query on `servedOrigin`, which serves the same build: the `analyse` CLI serves its own on a free port. Strict load, then the stylesheet wait (`styled`), then axe, as today.
  - any other page: `page.url` must be an `AxeUrl`, or `invalid_axe_url`. It is opened as given and scanned, with the lenient load and no stylesheet wait: the wait refuses a page with no stylesheet at all, which a real site may be. A stylesheet that failed to load does not hold the wait up, since Chromium gives a failed link a `sheet` too.
  - one rule for both: a key on `targetAppOrigin` is loaded strictly and scanned once its styles apply. That covers every target-app page and a `url=` on the app's own origin, whose key can be exactly one `page=` uses, so neither an unstyled nor a fallback-font scan is stored as the app's.
  - the scan's `url` is `page.url`, the key it was asked by.
- `servedAxeScanner(targetAppOrigin)`: builds and serves the target app on its first target-app scan only, as today, and scans any other page on the shared browser without serving anything.
- `GET /axe`: `page` or `url`, exactly one, else 400 and nothing scanned, read by `pageQuery(targetAppOrigin)`. `axeRoute({ axe, targetAppOrigin })`.
- Migration `0006_axe_results_by_origin.sql`, written with `drizzle-kit generate --custom`: `DELETE FROM axe_results;`. Every stored row is keyed by path alone and would never be asked again; the next request scans afresh. The table's shape does not change. `db/schema.ts` and `db/axe.ts` say the key is the whole URL.

### io: the Analyst (`analyst-axe.ts`, `analyst.ts`)

`AnalystDeps.targetAppOrigin: string`, the origin io hands its runner. `axeDrafts` takes it.

- A run is on the target app when `new URL(run.startUrl).origin` equals `new URL(targetAppOrigin).origin`, port included. `TARGET_APP_HOSTS` goes. Its pages are found as today (a step's `urlBefore` on the run's origin, in `TARGET_APP_PATHS`) and asked as `targetAppPage(start.origin, path, start.search)`. Its findings read as today.
- Any other run: every step's `urlBefore` that is `http:` or `https:`, its hash dropped, is a page, on any origin: a site that redirects `example.com` to `www.example.com` keeps its pages. Each is asked as `{ url, onTargetApp: false }`.
- Off the target app at most ten pages are asked per report: those the most runs stood on, ties to the page stood on first. Their findings keep the order a step first stood on each. The rest are logged once, as a warning naming each URL and how many runs stood on it.
- A foreign finding names the URL: title `axe-core: <help> (<rule>) on <url>`, detail "axe-core 4.13.0 reports `<rule>` on `<url>`, scanned on desktop: …", fallback "Fix what axe-core's `<rule>` rule reports on `<url>`: …". No "app's parameters".

Callers pass the origin: `reportsRoute` gets it from `AppOptions`; `analyse.ts` and `seed-demo-cli.ts` pass `http://localhost:${TARGET_APP_PORT}`, the origin their runner is handed. `seed-demo-cli.ts` builds its scanner as `axeScanner({ browser, targetAppOrigin, servedOrigin: app.origin })`.

### io: refusing other hosts and other sites (`app.ts`)

`AppOptions.hosts: readonly string[]`, the `Host` values io answers to, lowercase. One middleware, first in the chain, before the 415 check:

- every `Host` the request names, its `host` header and the host of its URL, must be in `hosts`, or 403 `{ error }`. `@hono/node-server` builds the URL from the header unless the request line holds an absolute URL, so both are read;
- `Sec-Fetch-Site: cross-site` or `same-site` is a 403 `{ error }`.

Nothing behind a refused request runs. `server.ts` passes `localhost:<PORT>`, `127.0.0.1:<PORT>` and `[::1]:<PORT>`. `testApp` defaults to `["localhost"]`, the host `app.request` gives a bare path.

### web: the dev proxy (`vite.config.ts`)

`changeOrigin: true` on `/api`, so io sees `Host: localhost:3000`. The page calls its own origin through the proxy, so the browser sends `Sec-Fetch-Site: same-origin`, which the proxy forwards.

## Risks

- The two browser tests start more servers and pages; they stay inside the existing 120 s limits.
- This machine's headless Chromium draws no animation frames (`settle.browser.test.ts`'s animation test). The fixture page's animation is infinite, so the lenient `settle` sets it aside without waiting for a frame. No finite animation goes on it.
- `drizzle-kit generate --custom` writes a snapshot and a journal entry; if it refuses with no schema change, the SQL file and journal entry are written by hand in the same format.
- `example.com` must be reachable for the `pnpm dev` box. It answered 200 from this machine on 2026-10-07.
- The web test helpers are the only web change; s3-12's open PR #181 does not touch either file.
- A report on a foreign task scans up to ten fresh pages one after another, each allowed up to 50 s, inside `POST /reports`. A site that loads slowly can hold the report for minutes on its first build; scans are stored, so a second report reads them. The finals rehearsal (`s4-08`) times it on our pick.
