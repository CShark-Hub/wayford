# s1-05 — Filter: vocabulary (K2): spec

Task: `tasks/s1-05-vocabulary.md` · Branch: `feature/s1-05-vocabulary` · Date: 2026-10-05
Status: approved 2026-10-05

## Goal

`perceive` replaces a jargon term the persona does not know with `[unfamiliar term]`. Kai reads "Fulfilment ledger" as `[unfamiliar term]`; Ada reads it whole.

## Constraints that bind

- **The persona is a filter, not a prompt** (`AGENTS.md`). K2 changes only the observation. The vocabulary never reaches the Actor's prompt template (PLAN F5 AC6, PLAN A12).
- **Deterministic, no dice** (`docs/RULES.md` stage 4).
- **K2 applies only when the profile sets `domainVocabulary`**, as K1 reads only `unknownPatterns`. Today only Kai does (`kai.yaml:26-43`); Zoya has K2 off (`docs/RULES.md:195`).
- **The jargon list:**
  - one per target app;
  - provenance `folk`;
  - a data file;
  - `perceive` reads no file and stays browser-safe. The `./perceive` import test allows only `@wayford/core` and relative modules (`perceive-imports.test.ts:24`).
- **Matching:**
  - terms are whole words or phrases, compared case-insensitively;
  - a term is known when the vocabulary holds it, or holds every word of it;
  - each unknown term becomes one `[unfamiliar term]`, and a word inside a masked phrase is not masked again;
  - the rest of the name stays.
- **K2 renames through `renamedName`** and leaves the state alone (`docs/RULES.md`, "Several rules"). When K1 or K4 also renames, one of them wins, and RULES says which.
- **Speed:** `perceive` stays under 5 ms per call on `measurementFixture`.
- **Out of scope:** K3, detecting jargon automatically, a list written by a model, jargon lists for other sites.

## Design

### The jargon list: a core fixture

- **`packages/core/src/fixtures/jargon.json`:** `{ "provenance": "folk", "terms": ["Fulfilment ledger"] }`.
  - The target app's list sits next to its `tasks.json`, which core's fixtures already mirror.
  - The list holds one term on purpose. "Fulfilment ledger" is the one label on the app a team member would call shop jargon: fulfilment is back-office logistics, and a ledger is bookkeeping (s1-04: "one jargon label among plain ones").
  - Candidates left out: "Order archive", "in transit", "Sign-in activity". Decision 2 gives the reasons.
- **The schema** is `JargonList` (`{ provenance: "folk"; terms: string[] }`, with terms non-empty and distinct), exported from the core barrel in a small module, `packages/core/src/jargon.ts`. Both loaders parse with it, since web cannot import the Node-only `fixtures/index.ts`. It is a helper schema, not one of the seven contracts.
- **`@wayford/core/fixtures`** (Node) exports `targetAppJargon: readonly string[]`, the parsed file's `terms`.
- **`packages/web/src/bundled-fixtures.ts`** bundles the same file through its existing `import.meta.glob` on `@core-fixtures`, parses it with `JargonList` and exports `bundledJargon`. A test checks it equals `targetAppJargon`, following the existing `bundledProfiles` test.

### `perceive`

```ts
export type PerceiveProfile = Pick<Profile, "perception"> & {
  knowledge: Pick<Knowledge, "unknownPatterns" | "domainVocabulary">;
  behaviour: Pick<Behaviour, "maxElements">;
};
export interface PerceiveOptions {
  /** The target app's jargon list (`@wayford/core/fixtures` `targetAppJargon`). Without it, K2 never fires. */
  jargon?: readonly string[];
}
export function perceive(measurement: PageMeasurement, profile: PerceiveProfile, runSeed: Seed, options?: PerceiveOptions): FullObservation
```

- The fourth argument is optional, so every existing call keeps working.
- K2 fires only when the profile sets `domainVocabulary` and `options.jargon` is non-empty.

### `packages/filter/src/vocabulary.ts` (new, pure, imported only relatively)

```ts
/** The K2 replacement of `name`, or undefined when no listed term in it is unknown. */
export function vocabularyRename(name: string, jargon: readonly string[], vocabulary: readonly string[]): { terms: string[]; renamed: string } | undefined
// As built (decision 11): vocabularyMatcher(jargon, vocabulary | undefined): VocabularyMatch | undefined,
// built once per perceive call; it holds all of K2's gating, and VocabularyMatch is (name) => { terms, renamed } | undefined.
export const UNFAMILIAR = "[unfamiliar term]";
```

- **Known terms.** A term is known when the vocabulary, case-folded, holds the whole term, or holds every word of it. Words are split on whitespace.
- **Matching.**
  - Each unknown term is matched whole and case-insensitively, with a word boundary at each end that is a word character. As built (decision 9), the matcher uses core's `wholeTerm`, now exported, rather than a local copy.
  - Terms are tried longest first, and replaced text is never matched again. So a word inside a masked phrase is not masked again. As built (decision 10), the name is read left to right in one regex: at each place in the name, longer terms are tried first.
- **The result.**
  - `terms` holds the list's own spelling of each masked term, in order of first occurrence in the name.
  - `renamed` is the name with each occurrence replaced by `[unfamiliar term]`.

### Stage 4 in `perceive.ts`

- **Placement.** Pass 1 adds the K2 decision on every element, invisible ones included, as K1 and K4 do. The decisions are listed K1, K2, K4, the order `decisionOrder` requires (`observation.ts:197-201`, `:246-255`). K2 goes between `knowledgeDecisions`' K1 and K4, never appended after them.
- **The K2 decision:** `{ stage: "knowledge", rule: "K2", terms }`. Its state stays visible, and A1 is unchanged, since salience reads no name (`attention.ts:21-23`).
- **`renamedName`.**
  - The element's bare role when K1 or K4 decided. **K1/K4 win**: the bare role holds no jargon, so it already covers K2. K2 is still recorded, since "every rule an element fails is recorded" (RULES "Several rules").
  - Otherwise, K2's `renamed` text.
- **Masking.** A K2-renamed degraded element reads its replacement whole, with no `maskedName`, following the existing rule that a rename wins over a mask. The task asks for this ("never as partly legible").
  - **Known understatement:** when the term is only part of the name, the name's other words reach the model unmasked, so knowledge undoes part of perception's degradation. With K1/K4 nothing leaks, because the bare role replaces everything.
  - No fixture and no preview slider reaches it today: "Fulfilment ledger" is the link's whole name, so a degraded ledger has no other word left to leak (as RULES says).
  - RULES "Several rules" states the case, and `perceive.test.ts` pins it with "a degraded element K2 renames reads its replacement whole".

## Risks

- **PR #158 slips.** The last step waits. The PR can still open without real-run wiring, if the user chooses. It must then say that the preview and real runs disagree for Kai until the wiring lands: the preview shows `[unfamiliar term]`, while a run's evidence reads "Fulfilment ledger".
- **Spelling.** "Fulfilment" is the British spelling, and a vocabulary entry "fulfillment" does not make it known. That is accepted: matching is whole-term by design.
- **The marker's brackets** echo the observation's `[e1]` ref syntax. The renderer quotes names, so it reads `link "[unfamiliar term]"`.
