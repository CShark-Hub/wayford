# s2-05 — Jev decision call in the adapter: spec

Task: `tasks/s2-05-jev-adapter.md` · Branch: `feature/s2-05-jev-adapter` · Date: 2026-10-01
Status: approved 2026-10-01

## Goal

`decide({ role, state, question })` next to `complete`: one Jev Choice question over a block of text, sent through OpenRouter's System One API, returning a probability per offered key, the confidence, Jev's own pick, the model id and the cost. A fake `decide` with the same signature backs it, so s2-06 only builds the question and draws.

## Constraints that bind

- "The persona is a filter, not a prompt" and "the Actor must be our own loop" (`AGENTS.md`). Jev is one call inside our loop. The body holds "the state, the instructions, the options and the model id … and nothing else" (task, reviewer notes).
- Plain `fetch` on the LLM's key and base URL, no SDK. The module comment states the wire shape and cites the docs.
- Choice questions only; no Score or Noul, and no use outside the Actor (ADR 0001, task Out of scope).
- The answer is parsed with zod. The probabilities must cover exactly the offered keys, and the pick must be one of them; anything else is a typed failure and is never retried. Retries follow `complete`: at most 3, on network errors, 429 and 5xx only, every attempt logged with role, model, attempt and outcome.
- `decide` never samples. s2-06 draws with the run seed (`docs/CONVENTIONS.md`, "Determinism rules").
- Config: an actor backend (`llm` by default, or `jev`) and the Jev model id, both parsed with the other LLM settings. The adapter never reads `process.env`. `~typesafe/jev-latest` and `typesafe/jev-router` are rejected (ADR 0001 §5).
- Cost comes from `models.yaml`. The fake reports zero cost. No change to `packages/core`.

## Design

### The wire, as found (OpenRouter docs, 2026-10-01)

The sources are the task's Jev guide, `openrouter.ai/docs/guides/community/jev`, and the two pages it links: `…/community/typesafe-sdk`, which documents the System One API, and the Decisions API reference, which documents the same body. The module comment cites all three. `POST {baseUrl}/systemone`, so `https://openrouter.ai/api/v1/systemone` with the default base URL, sent with `authorization: Bearer <key>`:

```json
{ "model": "typesafe/jev-1.13", "state": "<text>",
  "questions": { "question": { "type": "choice", "instructions": "<text>",
                               "criteria": { "<key>": "<description>" } } } }
```

```json
{ "id": "gen-dec-…", "model": "typesafe/jev-1.13-20260917", "provider": "TypeSafe",
  "answers": { "question": { "type": "choice", "choice": "<key>", "confidence": 0.75,
                             "probabilities": { "<key>": 0.84 } } },
  "usage": { "input_tokens": 476, "output_tokens": 70, "cost": 0.000019992 } }
```

The System One API "accepts TypeSafe's bare … IDs and maps them onto OpenRouter's `typesafe/` namespace". It routes `jev-latest` as `~typesafe/jev-latest`, and uses an id with a prefix as it is. A Choice question takes up to 255 options, and its probabilities sum to 1 (`docs.typesafe.ai/primitives/choice`).

### `llm.ts`: types and `decide`

```ts
export type ChoiceQuestion = {
  instructions: string;
  /** Option key → what the option means. Sent as `criteria`; Jev answers with these keys. */
  options: Readonly<Record<string, string>>;
};
export type DecideRequest = { role: LlmRole; state: string; question: ChoiceQuestion };
export type Decision = {
  probabilities: Record<string, number>; // exactly the offered keys, each in [0, 1], as Jev sent them;
                                         // key order is Jev's: iterate the offered options for any order
  confidence: number;                    // [0, 1]; stored by s2-06, never acted on (ADR 0001 §6)
  choice: string;                        // Jev's own pick, one of the keys; reported, not used to decide
  model: string;                         // the configured id, the one priced
  cost: Cost;                            // core's Cost; tokensOut as reported, priced at 0
};
export type Llm = { complete: …; decide(request: DecideRequest): Promise<Decision> };
export function choiceAnswer(options: ChoiceQuestion["options"]): z.ZodObject; // shared with the fake
```

`choiceAnswer` builds `z.object({ choice: Key, confidence: P, probabilities: z.record(Key, P) })` with `Key = z.enum(Object.keys(options))` and `P = z.number().min(0).max(1)`. zod 4's record keyed by an enum is exhaustive: it rejects both a missing key and an unrecognised one (checked on the installed zod). A refine also rejects probabilities that are all zero, which leave nothing to draw from. The sum is not held to 1 (build, see the decision log). The values come back unnormalised, as Jev sent them.

The data flow of one `decide`:

1. Before sending, read the model from `settings.jevModel`, its price from `models.yaml`, and the answer schema from the keys on offer.
2. Build the body above, serialise it once, and `post` it through the transport `complete` uses. The attempt-and-retry loop becomes generic over a per-endpoint classifier: chat completions for `complete`, System One for `decide`. Usage is normalised to `{ tokensIn, tokensOut }` before it is priced. Nothing about `complete`'s behaviour changes, and its tests stay as they are.
3. Classify each attempt. A non-2xx, or a 2xx whose body is a top-level `{ error }`, is retried on 429 and 5xx and fails otherwise. As in `complete`, an error in a 2xx counts as its own code, or as 502 when it carries none. A 2xx that is not `{ answers, usage: { input_tokens, output_tokens } }` is `llm_bad_response`, not retried. An ok attempt adds its cost and logs `{ role, model, round: "decide", attempt, outcome, status, tokensIn, tokensOut, served, host, reportedUsd }`, where `reportedUsd` is OpenRouter's `usage.cost`. That puts our price table next to OpenRouter's bill in the smoke output.
4. Parse `answers.question` with the answer schema. A failure throws `LlmError("llm_invalid_output")` carrying the cost already billed, with no retry. On success, return `{ probabilities, confidence, choice, model, cost }`.

`createLlm` prices `settings.jevModel` at boot, as it prices every role, whatever the backend. `role` names the call in log lines and error messages. There is one Jev model.

### `llm-settings.ts`

| Variable | Field | Default | Rule |
|---|---|---|---|
| `LLM_ACTOR_BACKEND` | `actorBackend` | `llm` | `llm` or `jev` |
| `LLM_JEV_MODEL` | `jevModel` | `typesafe/jev-1.13` | rejects `jev-latest` and `jev-router`, bare or under any prefix (`typesafe/`, `~typesafe/`); the message names ADR 0001 and never echoes the value |

`variableAt` today special-cases only `baseUrl` and `apiKey`, and maps every other path as a role's. It gains `actorBackend` → `LLM_ACTOR_BACKEND` and `jevModel` → `LLM_JEV_MODEL`, so an error line names the variable to fix. The tests check that line and that the value is not echoed.

### `fake-llm.ts`

`decide` takes its entry from the role's existing queue, the one `complete` takes from. An entry is Jev's answer, `{ choice, confidence, probabilities }`, checked with `choiceAnswer`: one that misses throws `LlmError("llm_invalid_output")` at zero cost, and an `Error` entry is thrown. The fake returns `model: "fake"` and zero cost, and records each request, copied, in `decideCalls`. The `fakeLlm(answers, temperatures?)` signature is unchanged.

### `smoke-jev.ts` and `smoke:jev`

It loads the root `.env`, as `smoke-llm.ts` does. The state is `Goal: you want to see what you ordered three months ago`, then `renderObservationForModel(toActorObservation(observationFixture))`. The options are one per ref, `Click the <role> "<name>"`, plus `back`, "Go back to the previous page", under one plain instruction. It prints every option with its probability, highest first, then the confidence, Jev's pick and a cost line (tokens, USD from `models.yaml`, model, ms).

## Decision log

| Question | Taken | Why |
|---|---|---|
| Endpoint | `{baseUrl}/systemone` | The task asks for the System One endpoint under the base URL. The Decisions API, `/api/alpha/decisions`, sits outside it. |
| Where `decide` lives | on `Llm`, in `llm.ts`, sharing `complete`'s transport | The task's "next to `complete`". One retry loop, not two copies that drift. |
| Where the settings live | top-level `actorBackend` and `jevModel` | `RoleSettings` stays one shape for all four roles. Jev's model is not a role's chat model. |
| Which ids count as floating | `jev-latest` and `jev-router`, bare or under any prefix | System One maps a bare `jev-latest` onto `~typesafe/jev-latest`. A separate rule for a leading `~` caught nothing more (build, from the branch review). An unpriced alias fails at boot anyway. |
| The question's key on the wire | the fixed name `question` | It is internal; one question per call. |
| A sum check on the probabilities | (build) only "not all zero"; the values are returned raw | The approved spec had a band of ±0.05 around 1. The branch review showed it rejects valid answers. The real answer is rounded to two decimals (`e1` came back as 0.000), so a tail of values under 0.005 rounds to zero. On 15 or more options, which s2-06 offers on the target app, the sum then falls below 0.95. A rejected answer is a lost step, never retried. s2-06 draws `roll × sum` over the cumulative probabilities instead (follow-up in the PR), and the same line closes the float tail. |
| A check on the option count | none | Jev's own 400 for zero or more than 255 options is a typed failure, never retried. |
| Confidence or probabilities absent | `llm_invalid_output` | The docs promise both, and s2-06 stores both. |
| Error codes | reuse `llm_request_failed`, `llm_bad_response` and `llm_invalid_output` | Callers already branch on them, and the meanings are the same. |
| Scripting the fake | the role's existing queue, an entry being Jev's answer | No signature change for io's tests. Validated as the real answer is. |
| Logging | the same "llm attempt" line with `round: "decide"`, plus `reportedUsd` | One log shape. The smoke checks our price against OpenRouter's bill. |
| Timeout | 30 s by default for `decide`, `complete` keeps 300 s; `deps.timeoutMs` overrides both | Jev answers in 70 to 500 ms. A hang must not stall a run for five minutes, since a timeout is never retried. |

## Risks

- Early access. Jev may answer 403 on an account without opt-in, and its real answer may differ from the docs, such as confidence being absent. The smoke run is the first contact. A mismatch is a schema fix in this task; a 403 is a blocker on the smoke box alone.
- The transport refactor touches `complete`'s code path. Its 21 KB of tests guard it, and they must pass unchanged.
