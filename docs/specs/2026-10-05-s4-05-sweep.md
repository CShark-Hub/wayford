# s4-05 — Sweep: the boundary value on one capability axis: spec

Task: `tasks/s4-05-sweep.md` · Branch: `feature/s4-05-sweep` · Date: 2026-10-05

## Goal

One command runs a task for one persona across a range of one capability, the same seeds at every value, and stores the success rate, the route-open share and the boundary value per value.

## Constraints that bind

- **Untouchable core, point 3:** the capability-axis sweep. "A `while` loop, one slide."
- **F9:**
  - AC3: the same seed set at every value.
  - AC4: the swept value is a profile threshold or cap, never an app parameter. Its softness stays fixed, and the app parameters stay fixed and are recorded in every run's start URL.
  - AC5: the boundary is the first value from the laxest whose success rate falls below 50%.
- **A20:** the same seeds, so every value is compared on the same dice.
- **RULES:**
  - "Monotone per perception rule" holds per rule only: A1 is not monotone in the perception thresholds.
  - The calibration row "Sweep on contrast" gives the bound, for Vera, whose B and C entrances P4 closes: at each value, hard-goal successes never outnumber the seeds where the contrast rules leave the hard link visible or degraded.
  - "The mask": a degraded name always has at least one character masked.
- **The task's Constraints:**
  - the axes and the fields each sets;
  - the laxest end decided by the axis;
  - the boundary rule;
  - route-open from `routeOpenSeeds` with the swept profile;
  - sweep runs out of `GET /runs` unless asked for by `sweepId`;
  - the cost guard as `calibrate` does it, with `--max-usd` defaulting to 2.
- **Out of scope:**
  - the sweep screen (`s3-09`);
  - two axes at once, or any target-app parameter;
  - resuming after a restart. A cut-off sweep stays incomplete and says so.
- **Import rules** (`docs/STACK.md`):
  - io imports core, filter and agent;
  - agent imports core and filter;
  - a module that loads agent's runtime or Playwright stays out of io's barrel (s4-03, "The barrel"). `runner.ts` imports agent as types only.
- **Determinism** (`docs/CONVENTIONS.md`): no `Math.random`. The swept values come from `from + i × step`, never from a running sum.

## Design

### 1. Core: `Sweep` and its helpers (`packages/core/src/sweep.ts`, at rest)

It is an eighth contract at rest beside the seven. It is new, so no frozen contract changes. It is flat and discriminated on `axis`:

```ts
export const SWEEP_AXES = ["contrast", "maxElements"] as const;
export const SweepAxis = z.enum(SWEEP_AXES);
export const SWEEP_STATUSES = ["complete", "incomplete"] as const;
/** The Actor backends a sweep can run on; agent's `ActorBackendName` has the same names (pinned by a test in io). */
export const SWEEP_BACKENDS = ["llm", "jev"] as const;

const sweepValue = <V extends z.ZodType>(value: V) => z.object({
  value,
  runIds: z.array(RunId),                 // one per seed, in seed order
  successes: z.int().nonnegative(),       // stored with outcome `success`
  errors: z.int().nonnegative(),          // stored as `error`, or never stored (decision log)
  routeOpenSeeds: z.array(Seed).nullable(), // seeds with ≥ 1 route open; null: the task has no route table
}).strict();

const base = {
  id: SweepId, taskId: TaskId, profileId: ProfileId,
  backend: z.enum(SWEEP_BACKENDS),
  seeds: z.array(Seed).min(1).max(10),
  startedAt: z.iso.datetime(),
  status: z.enum(SWEEP_STATUSES),
};

export const Sweep = z.discriminatedUnion("axis", [
  z.object({ ...base, axis: z.literal("contrast"),
    from: ContrastRatio, to: ContrastRatio, step: z.number().positive(),
    values: z.array(sweepValue(ContrastRatio)), boundary: ContrastRatio.nullable() }).strict(),
  z.object({ ...base, axis: z.literal("maxElements"),
    from: z.int().positive(), to: z.int().positive(), step: z.int().positive(),
    values: z.array(sweepValue(z.int().positive())), boundary: z.int().positive().nullable() }).strict(),
]).superRefine(/* below */);
```

The refine:
- the seeds are unique;
- per value:
  - `runIds.length ≤ seeds.length`;
  - `successes + errors ≤ runIds.length`;
  - `routeOpenSeeds ⊆ seeds`;
- `values` equals a prefix of `sweepValues(axis, from, to, step)`, the laxest-first grid;
- `boundary` equals `boundaryOf(values, seeds.length)`, so a stored boundary always agrees with its own numbers;
- a `complete` sweep has every grid value.

Pure helpers, exported for io and `s3-09`:
- **`sweepValues(axis, from, to, step): number[]`:**
  - the range laxest first: ascending for `contrast`, descending for `maxElements`, whatever order `from` and `to` come in;
  - each value is `start ± i × step`, counted in whole thousandths for `contrast`;
  - the far end is kept when it falls on the grid, and clipped otherwise;
  - `step ≤ 0`, a non-integer `maxElements` end or step, a `contrast` end or step off the thousandths, an empty range, or more than `MAX_SWEEP_VALUES` (50) values throws `WayfordError("invalid_sweep_range", …)`. The count is checked before the grid is built.
- **`boundaryOf(values, seedCount): number | null`:** laxest first, null at the first value with any error (nothing past it is claimed), else the first value with `successes / seedCount < 0.5`, strict. A dip that recovers still wins (the errors rule: decision log).
- **`sweptValueOf(profile, axis): number | undefined`:** the field an axis names, `perception.contrast?.threshold` or `behaviour.maxElements`.
- **`sweptProfile(profile, axis, value): Profile`:**
  - copies the profile with that one field set and checks it with `Profile.parse`;
  - softness, provenance and the id stay as they are;
  - `contrast` on a profile without a contrast threshold throws `WayfordError("sweep_axis_unset", …)`: there is no softness to keep (AC4);
  - `maxElements` on a profile without a cap is allowed: no cap means unlimited, the cap has no softness or provenance, and the sweep's laxest end approaches it (decision log).

Agent's private `sweptField` in `actor-loop.ts`, from #165, is replaced by core's `sweptValueOf`, so the mapping from axis to field lives once.

**Fixtures:** `packages/core/src/fixtures/sweeps.json` holds two, exported as `sweepFixtures`:
- **Vera on `contrast`,** 1.5 to 4.5 by 0.5, seeds 1 to 10, complete, boundary 3. Its numbers keep the RULES bound at every value (successes ≤ route-open seeds).
- **Kai on `maxElements`,** 16 down to 4 by 2, complete, with `routeOpenSeeds` set. It is the descending axis `s3-09` has to draw.

`references.test.ts` checks their task and profile ids.

### 2. io: the runner takes a sweep stamp

#167 merged with an options object, `start(task, profiles, seeds, options?: RunSetOptions)`, so `sweep?: RunSweep` is a field of `RunSetOptions` beside `backend` (build). `job` passes `...(sweep === undefined ? {} : { sweep })` to `run`.

Nothing else in the runner changes, and the five slots and the FIFO are shared.

### 3. io: the engine (`packages/io/src/sweep.ts`, no agent runtime, no Playwright)

```ts
export interface SweepInput {
  task: Task; profile: Profile; axis: SweepAxis; from: number; to: number; step: number;
  seeds: readonly Seed[]; backend: ActorBackendName;
}
export interface SweepDeps {
  db: Db; runner: Runner; logger: Logger;
  /** Seeds with a route open for this profile, or undefined when the task has no route table. */
  routeOpen: (profile: Profile, seeds: readonly Seed[]) => readonly Seed[] | undefined;
  /** Stop before the next value once the stored runs have cost this much (USD). */
  maxUsd?: number;
  now?: () => Date;
  /** Each value as it settles, for the CLI's progress line. */
  onValue?: (row: SweepValue, spentUsd: number) => void;
  /** The stored row before the first value, for the CLI's header (build). */
  onStart?: (sweep: Sweep) => void;
}
export async function runSweep(deps: SweepDeps, input: SweepInput): Promise<Sweep>;
```

`runSweep` is a `for` loop over `sweepValues(...)`:
1. It checks the input with core's `sweepPlan`, which is `sweepValues` for the range and `sweptProfile` once for the axis; the CLI calls the same helper (build). It mints `newId("sweep")` and saves the row at once as `incomplete` with no values, so a sweep cut off at any point is stored as incomplete.
2. Per value, laxest first:
   - build `sweptProfile` once;
   - `runner.start(task, [swept], seeds, { backend, sweep: { sweepId, axis, value } })`;
   - wait until every run's `live(id).ended`;
   - `loadRun` each id;
   - count `success`, and count `error` or missing as errors;
   - `routeOpen(swept, seeds)`;
   - append the value, recompute `boundary` with `boundaryOf`, and save the row.

   Values run one after another, never queued at once. The next value starts only when the last has settled.
3. **Spend.** After each value it sums the stored runs' `cost.usd`. Once that reaches `maxUsd`, it stops before the next value, leaves the row incomplete and throws `WayfordError("sweep_over_budget", …)`. This is the in-flight half of `calibrate`'s guard; the up-front estimate is the other half (§5).
4. At the end it sets `status: "complete"` and saves. A thrown error leaves the row as last saved, still incomplete, and rethrows.

There is no early stop at the boundary. F9 AC2's chart wants every value.

### 6. The CLI: `pnpm --filter @wayford/io sweep -- …` (`packages/io/src/sweep-cli.ts`)

```
--task <id>            a stored task or a fixture task (task_past-order)
--persona <id|label>   prof_vera or vera
--axis contrast|maxElements
--from <n> --to <n> --step <n>    in any order; the axis decides which end runs first
--seeds <n|a-b>        at most 10, as POST /runs allows
[--backend llm|jev]    default LLM_ACTOR_BACKEND, as POST /runs
[--max-usd <n>]        default 2
```

Order, cheapest first:
1. Read the arguments. Usage errors exit 2.
2. Load the env and settings, migrate and open the database, and find the task (`loadTask`, falling back to `taskFixtures`) and the persona.
3. Every refusal before anything is built:
   - `sweepValues` for the range;
   - `sweptProfile` for the axis on this persona;
   - the cost estimate.
4. Serve the target app on 5174 with `serveTargetApp({ port: 5174 })` from `@wayford/filter/serve-target-app`, as `calibrate` does. A busy port, such as a running `pnpm dev`, fails with a message saying to stop it.
5. Walk the routes once: `walkRoutes([profile.device])`. Then `routeOpen = (p, seeds) => routesFor(walks, task.id, p.device)`, mapped through `routeOpenSeeds(routes, p, seeds, { jargon })` to the seeds whose `open` is non-empty.
6. Build the runner as `server.ts` does:
   - `sharedBrowser` and `sharedChromium`, plus `actorBackends(settings)`;
   - `TARGET_APP_DEFAULTS` and `targetAppJargon`.

   Then run `runSweep` with `maxUsd`.
7. Print to stdout; logs go to stderr:
   - a header: task, persona, axis, backend, model, seeds, sweep id;
   - one row per value: value, successes/seeds, rate, route-open seeds or "—", and errors;
   - the boundary line: "boundary 3.0 (rate 30%)", or "no boundary up to 4.5";
   - wall time, and the spend summed from the stored runs.
8. Close the browser, the app and the database in `finally`.

Exit codes:
- 2 for a usage error;
- 1 for a refusal, a failure, a stop for spend, or any errored run (after printing the table);
- 0 otherwise. A boundary is a measurement, not a failure.

The module is the second, after `server.ts`, that loads agent's runtime, and it stays out of the barrel. The comments in `server.ts` and `chromium.ts` that say "the only one" are updated.

**Tying the share to the runs.**
- **Parameters.** The walk measures at filter's `TARGET_APP_DEFAULT_QUERY`, and the runs use agent's `TARGET_APP_DEFAULTS`. A test pins `startUrlFor(task, TARGET_APP_DEFAULTS)` to end with that query, so the route-open share is about the page the runs saw.
- **Task lookup.** The task comes from `loadTask(db, id)`, falling back to `taskFixtures`. Fixtures are not seeded into the database, and the real-key box uses `task_past-order`.

### 7. Tests, by file

**`packages/core/src/sweep.test.ts`:**
- both fixtures parse;
- each refine rejects its own break:
  - a boundary that disagrees;
  - values off the grid or out of order;
  - `routeOpenSeeds ⊄ seeds`;
  - duplicate seeds;
  - `successes + errors > runIds`;
  - a complete sweep missing a value;
- `sweepValues`:
  - contrast 1.5 → 4.5 by 0.5 gives 7 values, and 4.5 → 1.5 gives the same order;
  - maxElements 4 → 16 by 2 runs 16 down to 4;
  - a step of 0, a negative step, a non-integer `maxElements` step and an empty range all throw;
  - a contrast end or step off the thousandths throws, and so does a range of more than 50 values, a cap range of billions included;
  - 1.5 → 4.4 by 0.5 clips at 4.0;
- `boundaryOf`:
  - 5/10 is not a boundary, and 4/10 is;
  - a dip that recovers is still the boundary;
  - with no dip it gives null;
- `sweptProfile`:
  - keeps Vera's softness 0.5 and her provenance;
  - refuses `contrast` on Kai;
  - sets a cap on Ada;
  - changes only the swept field.

**`packages/core/src/fixtures/references.test.ts`:** the sweep fixtures' task and profile ids exist.

**`packages/io/src/sweep.test.ts`** (fake backend: `fakeRun`, injected `routeOpen`):
