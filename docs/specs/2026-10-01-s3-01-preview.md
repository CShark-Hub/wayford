# s3-01 — Preview screen on the measurement fixture: spec

Task: `tasks/s3-01-preview.md` · Branch: `feature/s3-01-preview` · Date: 2026-10-01
Status: approved 2026-10-01

## Goal

A `/preview` screen: sliders for a persona's perception thresholds on the left, the stored `/deliveries` page as that persona perceives it on the right, redrawn from the same `perceive` the Actor uses every time a slider moves.

## Constraints that bind

- **One filter.** "Preview uses the same filter package as the Actor. There is no second visual approximation" (F2 AC3). The browser runs `perceive` from `@wayford/filter/perceive`. "The screen never decides visibility: it draws what `perceive` returns."
- **Drawn from the `FullObservation` alone**, each element at its bbox: `visible` as is, `degraded` with its masked name, `invisible` not at all. A toggle shows removed elements as outlines with the rule that removed them, "labelled as evidence, not perception".
- **Sliders**: contrast, font size and target size thresholds, the softness of each, and the seed. Thresholds and softness start from the chosen persona. "The seed stands in for a run seed: it starts at 1, never at the profile's seed, and stays when the persona changes" (A20).
- **The URL is the state.** "All of it lives in the URL through TanStack Router search params, so a preview state is a link."
- **Register.** Sober, monochrome, monospace for seed and measurements; the persona colour is the one accent that crosses registers (`docs/PLAN.md` "UI"). Every slider and every icon-only control has an accessible name.
- **Look (user, 2026-10-01).** "Modern, like a professional app, with a fun hackathon touch."
- **Package rules.** web imports core, and filter only through `@wayford/filter/perceive` (`docs/STACK.md`). No dependency `docs/STACK.md` does not list. Files: `packages/web/**`, `pnpm-lock.yaml`.
- **Out of scope.** The live target app, an io endpoint, the screenshot layer and CDP emulation (s3-05); the profile builder (F1); knowledge, attention and memory sliders (s1-03).

### URL contract: `src/preview/search.ts`

| Param | Value | Absent or invalid means |
|---|---|---|
| `persona` | a bundled profile id | `prof_vera` |
| `seed` | `Seed` (uint32) | `1` |
| `contrast` | `[1, 21]`; `1` means no contrast threshold | the persona's threshold, or none |
| `fontPx` | `[0, 48]`; `0` means no font threshold | likewise |
| `targetPx` | `[0, 96]`; `0` means no target threshold | likewise |
| `contrastSoftness`, `fontPxSoftness`, `targetPxSoftness` | `[0, 1]` | the persona's softness, or `0` |
| `evidence` | `true` | off |

```ts
// Superseded (simplify): there are no PREVIEW_DEFAULT_* exports, and `persona` and `seed` are
// optional in PreviewSearch like every other field. resolvePreview defaults them to Vera and 1
// (decision log, "Defaults").
export const PREVIEW_DEFAULT_PERSONA = "prof_vera";
export const PREVIEW_DEFAULT_SEED = 1;
/** Slider bounds per metric. `off` is the lowest position and means "this metric does not gate". */
export const CUT_SLIDERS: Record<MetricName, { off: number; max: number; step: number }>;
//   contrast { off: 1, max: 21, step: 0.1 }, fontPx { off: 0, max: 48, step: 1 },
//   targetPx { off: 0, max: 96, step: 1 }; softness step 0.05; seed slider 0 to 100, step 1
export const PreviewSearch: z.ZodType<PreviewSearch>;   // z.object, every field `.catch`
export type PreviewSearch = {
  persona: string; seed: Seed;
  contrast?: number | undefined; contrastSoftness?: number | undefined;   // and fontPx…, targetPx…
  evidence?: true | undefined;
};
export type Cut = { threshold: number; softness: number };
export type PreviewState = {
  persona: Profile; seed: Seed;
  cuts: Record<MetricName, Cut>;        // what the sliders show
  perception: Profile["perception"];    // what perceive gets
  edited: boolean;                      // perception differs from the persona's own
  evidence: boolean;
};
export function resolvePreview(search: PreviewSearch): PreviewState;
/** The search a persona link navigates to: the new persona, the same seed and evidence toggle. */
export function personaSearch(search: PreviewSearch, personaId: string): PreviewSearch;
```

- **Validation.** `PreviewSearch` is a `z.object` whose every field ends in `.catch`: ~~`persona` to `prof_vera` when it is not one of `bundledProfiles`' ids, `seed` to `1`, the rest to `undefined`~~. So a broken link degrades to the persona's values instead of an error screen. ~~The route's `validateSearch` is `(raw: Partial<PreviewSearch> & SearchSchemaInput) => PreviewSearch.parse(raw)`, so links may omit any key while `useSearch` always has `persona` and `seed`.~~
  - **Superseded** (simplify, then PR review): every field catches to `undefined`, and `resolvePreview` defaults an absent `persona` to Vera and `seed` to 1. The route's `validateSearch` is the schema itself, a Standard Schema, with no wrapper and no `SearchSchemaInput`, so `useSearch` may lack any key.
- **Why every key comes back.** TanStack merges a route's validated search over its parent's, and the root route passes the raw query through: a validator that dropped `seed=abc` would let `"abc"` reach `useSearch` (spiked). zod 4 returns a present-but-invalid key as `undefined`, which overrides the raw value (spiked).
- **Resolution, per metric.** `threshold = search[metric] ?? persona.perception[metric]?.threshold ?? off`; `softness = search[metricSoftness] ?? persona's softness ?? 0`. `perception[metric]` is set only when `threshold > off`, as `{ threshold, softness, provenance }`; `emulation` is copied from the persona. `perceive` never reads `provenance`, but the type needs one: it is the persona's when the threshold equals the persona's own, and `folk` otherwise, since a slider value cites nothing.
- **Off is exact.** A contrast ratio is at least 1:1 and a pixel size above 0, so the lowest slider position fails nothing. Leaving the threshold out instead of passing `1` or `0` keeps Ada's preview identical to `perceive(measurement, ada, seed)` and keeps `0 px` out of a `PixelThreshold`.
- **Edited.** `edited` is true when, for any metric, the effective threshold or softness differs from the persona's own (an absent softness reads 0, an off threshold reads absent). A softness moved under an off threshold changes nothing and is not an edit. The screen uses it so it never calls an edited bundle by the persona's name alone.
- **Persona switch.** `personaSearch` returns `{ persona, seed, evidence }`: the thresholds and softness fall back to the new persona's, the seed and the toggle stay (A20).

### Drawing: `src/preview/perceived-page.tsx`

```ts
export function PerceivedPage(props: {
  observation: FullObservation;
  evidence: boolean;
  /** Whose thresholds, from the screen: "Vera's thresholds, seed 1" or "Vera's thresholds, edited, seed 1". */
  subject: string;
  // Superseded (simplify): no `colour` prop. The frame reads `--persona`, which the screen sets
  // from `personaColour(profile)` (decision log, "Persona colour").
  /** `personaColour(profile)` from `src/avatar/parts.ts`: no second colour mapping. */
  colour: string;
  // Superseded (second human review): no `source` prop. The frame's bar was cut with the look.
  /** Where the measurement came from, shown in the frame's bar: "Stored measurement" here, live in s3-05. */
  source: string;
}): JSX.Element;
```

- A `<figure>` with a `<figcaption>` and a frame. The frame is an `@container` wrapper around a `relative overflow-hidden` canvas with `--px: calc(100cqw / {viewport.width})` and height `calc({viewport.height} * var(--px))`. Every drawn box is positioned in measured CSS px times `--px` (`left: calc(24 * var(--px))`), so the drawing scales to the pane with no script and the markup carries the measured numbers. The frame's top border is the persona colour.
- Elements are drawn in `observation.elements` order. An element with a `ref` (visible or degraded) is one `<div data-ref data-state>` at its bbox, with font size `metrics.fontPx` (16 when absent) times `--px`. Its state, box and font size come from the `FullObservation`; its text is the name `toActorObservation(observation)` gives that ref: the masked name for a degraded element, the real one otherwise, the renamed one once s1-03 lands. So the preview draws what the Actor reads, by core's own projection, joined by ref.
- Drawing by role, which changes how an element looks and never whether it is drawn: `link` underlined; `button`, `textbox`, `searchbox`, `combobox` boxed; `checkbox` and `radio` as their small box, with the name beside it to the right, where the label sits on the page; `heading` semibold; every other role plain text. `degraded` uses the muted foreground. Nothing else varies with state.
- An element with no `ref` is not drawn. With `evidence` on, it is a dashed outline at its bbox with a monospace tag listing the decisions whose `decisionState` (core) is `invisible`: `P1 2.005 < 3`, `P4 27 < 32`, `V2 below`; the element's name rides along as `sr-only` text, and the full decisions, rolls included, in its `title` (**superseded**, second human review: no `title`). A V2-removed box lies outside the viewport and so outside the clipped frame; the fixture has none.
- The caption names the view and says what was computed, never what a person sees ("claim less"). Perception: "The page as perceive returns it for {subject}." Evidence: "Evidence, not perception: dashed outlines mark the elements perceive removed for {subject}, each with the rule that removed it." The screen builds `subject` and adds "edited" whenever `state.edited`, so a moved slider is never presented as the persona.

### Screen: `src/screens/preview.tsx`

`previewRoute` at `/preview` under `rootRoute`, added to `routeTree` in `router.tsx`, and a "Preview" link in the shell's nav between Personas and Events.

`PreviewScreen`: `state = resolvePreview(previewRoute.useSearch())`, then `observation = perceive(bundledMeasurement, { perception: state.perception }, state.seed)` on every render, and `subject = "<label>'s thresholds, seed <seed>"`, with ", edited" after "thresholds" when `state.edited`. No memo: renders happen when the URL changes, and `perceive` on the fixture averages well under its 5 ms budget (`bench:perceive`). s3-05 swaps `bundledMeasurement` for io's measurement at this one line.

Layout: a two-column grid from `lg` up, stacked below. The look is in "Look" below.

- Left, the input side:
  - The current persona: its `Avatar`, name and description, and, when `state.edited`, an "Edited" badge and a "Reset to <label>" button that navigates to `personaSearch(search, persona.id)`. **Superseded** (second human review): its name and description only. The caption still says "edited", and the current persona's own link goes to `personaSearch(search, persona.id)`.
  - `<nav aria-label="Persona">`: one TanStack `Link` per bundled persona, with its mini avatar (`aria-hidden`) and its name, `search={personaSearch(search, id)}`, `resetScroll={false}`. ~~TanStack marks the current one `aria-current="page"` and `data-status="active"` because the validated search always carries `persona`.~~ Superseded (simplify): the switcher sets `aria-current="page"` on the resolved persona's link itself, so a URL that names no persona still marks Vera.
  - "Thresholds": for each metric a threshold slider and a softness slider; the softness slider is `disabled` while its threshold is off.
  - "Seed": the seed slider, and one muted line saying it stands in for a run seed and that the profile seed only draws the avatar.
- Right, the output side: a toolbar with the measured page's title; a `View` group of two buttons, "Perceived" and "Evidence", each with `aria-pressed`, that set `evidence` (`replace` navigation); three counts read off the `FullObservation`, "shown" in core's sense (visible or degraded): `18/19 shown`, `1 degraded`, `1 removed`; then `PerceivedPage`, and a legend. **Superseded** (second human review): no counts and no legend.

`SearchSlider({ id, label, value, min, max, step, format, disabled, onMove })` is a native `<input type="range">` with a `<label htmlFor>`, an `<output htmlFor>` showing `format(value)` in monospace (`off`, `3:1`, `16 px`, `0.5`, `7`), and `aria-valuetext` with the same text.

- Native, not Radix's slider: it renders its value in a static render, which the tests read, and it is the most robust accessible slider there is. shadcn's `Slider` renders its thumb only after mount.
- **Smooth dragging.** TanStack Router commits a navigation's matches inside `React.startTransition` (`Transitioner.js`). A range input held to the URL alone would be set back to the old value after each input event until that commit lands, which React's docs name as the failing case ("Updating an input in a Transition doesn't work"). So the slider keeps one piece of local state, `moving: number | null`, set synchronously in `onChange`, and shows `moving ?? value`. It is cleared when the URL value catches up with it, or on blur, so a persona switch or a back navigation always shows the URL's value again.
  - **Superseded** (PR review): a Back from the keyboard or a mouse button does not blur the slider. Every slider is keyed by the history entry, so Back, Forward and a persona link remount each one on the URL's value.
- `onMove(next)` marks the redraw timer and calls `navigate({ search: (prev) => ({ ...prev, [key]: next }), replace: true, resetScroll: false })`. Replace, so a drag leaves one history entry. A persona link pushes, so Back returns to the previous persona.
  - **Superseded** (simplify, then PR review): `onMove` queues the value, and the queue is written with that `navigate` at most once per 150 ms, and at once when the slider loses focus. A queued value belongs to the history entry it was moved on and is dropped once the URL is on another one (decision log, "URL writes").

**Control panel (input register).** One surface, `rounded-xl border bg-card`, `lg:sticky lg:top-6`. Sections are separated by spacing, not nested cards.
- Persona block: the persona's `Avatar` at `size-16`, drawn from the persona with the screen's edited `perception`. So the glasses thicken as the contrast slider rises, and vanish when it is off: s3-02 draws them from the contrast threshold. The name is `text-2xl font-bold`, the description muted with `line-clamp-2`.
- Switcher: a segmented row, `rounded-lg bg-muted/50 p-1`, four equal columns. Each link holds a `size-6` avatar and the name. The active link sits on a raised `bg-background` pill with a 1 px ring in the persona colour, and the pill slides between links (Motion `layoutId`).
- Sliders: a custom-styled native range, the `.wf-range` rules in `index.css`, for WebKit and Firefox:
  - a 4 px track in `--muted`, filled in the persona colour up to the value (an inline `--fill` percentage);
  - a 16 px thumb in `--foreground` with a 2 px persona-colour ring;
  - the base focus-visible outline, and 40% opacity when disabled;
  - a 2 px tick on the track, `aria-hidden`, at the persona's own threshold;
  - the label row holds the name and, right-aligned, the readout in mono with `tabular-nums`. "Softness" is a smaller, muted sub-row of each metric group.

**Stage (output register).**
- Toolbar: the page title (`font-medium`) on the left; the `View` segmented control on the right, styled like the switcher.
- Counts: three plain stat items, the number in `font-mono text-lg tabular-nums`, the label `text-xs` muted. No cards, no dots.
- The frame: `rounded-xl border overflow-hidden`, with a 2 px top edge in the persona colour. A 36 px bar holds the URL in a mono pill (truncated) and, on the right, the `source` label and `1280 × 720` in mono. Below it is the canvas, the page ground `bg-background`. A drawn element is monochrome: foreground when visible, muted when degraded. Evidence outlines are dashed `muted-foreground/70`, with a 10 px mono tag on `bg-background/90`.
- Empty state: when nothing is shown, the canvas centres one muted line: "Nothing on this page passes these thresholds."
- Under the frame: a legend in `text-xs` muted (a visible sample, a degraded sample with ▒, and, in evidence view, a dashed sample), then the caption.

**Motion.** Framer Motion, for state changes only:
- An element that leaves (shown to removed) fades to 0 with a 2 px blur and scale 0.98 in 160 ms. One that arrives does the reverse. This is the demo's "elements vanish live" moment (`KONCEPCJA.md`, demo step 2), and it shows which element the slider just changed. Visible to degraded is a 150 ms colour transition; the text swaps at once.
- A persona switch slides the switcher pill (spring, stiffness 500, damping 40) and swaps the big avatar with a 150 ms scale-fade.
- Nothing loops. Nothing moves on scroll or hover beyond the standard colour transitions.
- `MotionConfig reducedMotion="user"` wraps the screen, and CSS transitions sit behind `motion-safe:`. With reduced motion every change is instant, which matters in a tool about accessibility.
- `AnimatePresence initial={false}`: the first render, and every static render in the tests, is the final state.

**Type, colour, shape.**
- Inter (variable, Latin, OFL) for the UI, copied from `packages/target-app/public/fonts/` with its `OFL.txt` into web's `public/fonts/`, with `@font-face` (`font-display: swap`) and `--font-sans` in `index.css`. It applies app-wide, as `docs/STACK.md` "Fonts" asks.
- Mono: JetBrains Mono, which `docs/STACK.md` also names, for seeds, readouts, counts, the URL and evidence tags. The repo had no copy; at gate 1 the user agreed to download the official `JetBrainsMono[wght].woff2` and its `OFL.txt` into web's `public/fonts/`.
- Colour: shadcn's neutral dark tokens. The one accent is the current persona's colour, set once as `--persona` on the screen root. It is used for the slider fill and thumb ring, the persona tick, the switcher ring, the "Edited" badge and the frame's top edge. No gradients, no glows. The persona colour is at least 7.5:1 on the card (s3-02), and muted text is about 6.9:1.
- Shape: surfaces `rounded-xl`, controls `rounded-lg`, tags `rounded-sm`, and one shadow, `shadow-sm`, on the active pills.
- Copy: no em or en dash in any UI string, at most one middle dot per line, no uppercase eyebrow labels.

**Redraw timing (box 4).** In dev only (`import.meta.env.DEV`): `onMove` sets the mark `wayford:preview-input` unless one is pending. An effect in `PreviewScreen`, after each commit, returns at once when `performance.getEntriesByName("wayford:preview-input", "mark")` is empty, as it is on mount, after a persona link, the evidence toggle or Back: `performance.measure` with a missing start mark throws. Otherwise it runs `performance.measure("wayford:preview-redraw", "wayford:preview-input")`, clears the mark and logs `preview redraw 1.8 ms` with `console.info`. The mark is kept from the first input since the last commit, so a coalesced drag reports its worst latency. A static render runs no effect, so tests log nothing.
