# s2-01 — LLM adapter: spec

Task: `tasks/s2-01-llm-adapter.md` · Branch: `feature/s2-01-llm-adapter` · Date: 2026-09-30
Status: approved 2026-09-30

## Goal

One function any package can call, `complete({ role, messages, schema, seed })`, that returns a zod-validated object from an OpenAI-compatible `/chat/completions` endpoint on the role's model, with retries and the cost of every call. A fake with the same signature means no test ever calls a real model.

## Constraints that bind

- "Plain `fetch` to `/chat/completions`, no SDK": we control exactly what the model receives. The Actor's request body carries "the messages the caller passed and nothing the caller did not" (reviewer note). No `if (provider)` outside the adapter (`AGENTS.md`).
- Structured output: JSON Schema from `z.toJSONSchema()`, sent as strict `json_schema` where the endpoint accepts it, JSON mode as the fallback, every answer re-parsed with zod. One repair round carrying the zod error, then a typed failure. The repair round cannot loop.
- Retries: exponential, at most 3, only on network errors, 429 and 5xx. Every attempt is logged with role, model, attempt and outcome. A retry never re-sends a partial response. A timeout on every call (`.claude/skills/pr-review/references/lenses.md`, "Calls").
- Config: four roles, each a model id and a temperature, plus base URL and key. Each role also gets a reasoning effort, because the team's model ladder picks models by effort. The adapter receives its config and never reads `process.env`. The parser fails with a readable message on a missing key or a non-`https` base URL; plain `http` is allowed for localhost only.
- Cost comes from `models.yaml`, in USD per million input and output tokens. An unknown model id is an error, not zero cost.
- Every request sends the role's temperature. `seed` is sent only when the caller passes one. Both come back as `Sampling` from core (`docs/PLAN.md` A20, F5 AC1).
- The key never lands in logs, errors or fixtures, and tests never read the real `.env` (lenses, "Secrets").
- Out of scope: prompts and loops, streaming, tool calls, images, cost on the dashboard, and Jev's `decide`. s2-05 adds `decide` next to `complete`.

## Design

Four modules in `packages/agent/src/`, one feature each, plus the smoke script. The adapter reuses `LlmRole`, `LLM_ROLES`, `Cost`, `Sampling` and `WayfordError` from core. The tests use core's `ActorResponse` as the Actor-shaped schema.

### `llm-settings.ts`: the parser

```ts
// Module-private: OpenRouter's documented `reasoning.effort` values.
const Effort = z.enum(["max", "xhigh", "high", "medium", "low", "minimal", "none"]);
export type RoleSettings = {
  model: string;
  temperature: number;                 // in [0, 2], Sampling's range
  effort?: z.infer<typeof Effort>;     // absent: the body carries no `reasoning` field
};
export type LlmSettings = { baseUrl: string; apiKey: string; roles: Record<LlmRole, RoleSettings> };
export function parseLlmSettings(env: Record<string, string | undefined>): LlmSettings;
```

| Variable | Default | Rule |
|---|---|---|
| `LLM_BASE_URL` | `https://openrouter.ai/api/v1` | `https`, or `http` on `localhost`, `127.0.0.1`, `[::1]`. The rule moves here from io unchanged. |
| `LLM_API_KEY` | none | Required. An empty value counts as missing. |
| `LLM_<ROLE>_MODEL` | see below | A string. |
| `LLM_<ROLE>_TEMPERATURE` | see below | A number in [0, 2]. |
| `LLM_<ROLE>_EFFORT` | see below | One of `max`, `xhigh`, `high`, `medium`, `low`, `minimal` and `none`, all sent as they are. Or `default`, which sends no effort at all, so the model uses its own. `default` is for an endpoint without the field, such as Ollama or direct OpenAI. |

`<ROLE>` is `EXTRACTOR`, `SCOUT`, `ACTOR` or `ANALYST`. As in io's config, an empty value counts as unset and takes the default. `.env.example` therefore lists the role lines commented out, with their defaults, and never as empty assignments.

The defaults come from the "While we build" column of the "How we use it" table in the team's model ladder: "Wayford — Model ladder for AI testing", Tomasz Nowakowski, 2026-09-25, a Claude Docs document at `https://claude.ai/artifact/6bmGiwefknnd2fVUJjktJ2`. The link is cited without its share key. Every role runs on GPT-6 Luna:

| Role | Model | Effort | Temperature | Why (the ladder's reasons) |
|---|---|---|---|---|
| extractor | `openai/gpt-6-luna` | `high` | 1 | Runs once per task. |
| scout | `openai/gpt-6-luna` | `max` | 1 | Runs once per app version. |
| actor | `openai/gpt-6-luna` | `high` | 1 | Runs for every persona × seed and drives the bill. |
| analyst | `openai/gpt-6-luna` | `max` | 1 | Runs once per series. |

Why Luna: it is the ladder's "While we build" pick for all four roles. Among the ladder's paid models, it has the lowest Artificial Analysis cost per task, as the ladder reports it: $0.03 at `high` (index 32) and $0.07 at `max` (index 37). Those are Artificial Analysis figures, not our own measurement.

OpenRouter's list on 2026-09-30 confirms $0.10 in and $0.50 out per million tokens, and effort values `max`, `xhigh`, `high`, `medium`, `low` and `none` (default `medium`). It also confirms `seed` and strict structured output at the model level. Not every host has them (Risks, "Unpinned hosts").

Deliberate departure from `AGENTS.md`. While we build, the Analyst differs from the Actor by effort only, where `AGENTS.md` ("AI through one OpenAI-compatible API") puts a strong model on the Analyst. The strong models are the ladder's "For real results" column, priced in `models.yaml`, so escalating is config only (the ladder's "Switch by config only"):

- `LLM_ANALYST_MODEL=anthropic/claude-opus-5.5`
- `LLM_SCOUT_MODEL=openai/gpt-6-sol`
- `LLM_EXTRACTOR_MODEL=openai/gpt-6-sol`

`.env.example` keeps these three lines on Luna until week 3, so a stray run cannot bill Sol or Opus 5.5 (build, from the PR review). Week 3 puts the models above there.

Temperature is 1 on every role. Luna is an OpenAI reasoning model and OpenRouter lists no `temperature` for it, so the task's rule for such a role applies. `Sampling` records the value sent, as core's contract says ("sent, not applied"). The same goes for a role on a direct OpenAI reasoning model. It is config, not a code branch, so there is still no `if (provider)`.

A failed parse throws `WayfordError("invalid_llm_settings", …)`, one line per offending variable, the way io's `loadConfig` reports. Values are never echoed.

### `models.ts`: the price table

```ts
export const ModelPrice = z.object({
  input: z.number().nonnegative(),       // USD per million input tokens, OpenRouter's list price
  output: z.number().nonnegative(),      // USD per million output tokens, OpenRouter's list price
  jsonSchema: z.boolean().default(true), // false: the endpoint gets JSON mode, not strict json_schema
}).strict();
export function loadModelPrices(): Record<string, ModelPrice>;   // reads packages/agent/models.yaml
export function priceOf(prices: Record<string, ModelPrice>, model: string): ModelPrice; // unknown id → WayfordError("llm_unknown_model")
export function costOf(price: ModelPrice, tokensIn: number, tokensOut: number): Cost;
```

`models.yaml` holds the ladder's defaults and escalation models, plus one local model. Prices are OpenRouter's list prices on 2026-09-30:

| Id | In / out, $ per 1M | Ladder |
|---|---|---|
| `openai/gpt-6-luna` | 0.10 / 0.50 | tiers 2 and 3: every default |
| `openai/gpt-6-sol` | 2.00 / 10.00 | tier 4: Scout and Extractor escalation |
| `anthropic/claude-opus-5.5` | 4.00 / 20.00 | tier 4: Analyst escalation |
| a local Ollama model | 0 / 0, `jsonSchema: false` | the emergency fallback `docs/PLAN.md` names |

Calls are not pinned to one OpenRouter host (the user's decision at gate 1). Luna's hosts differ in price and parameters: Risks, "Unpinned hosts".

Notes on the table:

- **Opus 5.5.** No host takes a `seed`. Its reasoning is always on, and its efforts are `max`, `xhigh`, `high`, `medium` and `low`. Only its Azure hosts take `temperature`. The file's comment on the entry says so.
- **Luna and Sol above 272k.** Both charge more from 272k prompt tokens: Luna 0.20 / 0.75, Sol 4.00 / 15.00. This is not modelled; a comment on each entry says so (Risks).
- **Ollama.** Its entry is the one user of the JSON-mode path today.
- **Free models.** The ladder's tier-1 free Qwen and an off-ladder free Nemotron are priced at 0 for $0 smoke runs (build, see the decision log).
- **Models left out.** The ladder's bake-off candidates, until someone uses them. Adding one is a line in this file, at OpenRouter's current price: two of the ladder's candidate prices are already stale.
- **Header.** The file's header names the source and the date.

### `llm.ts`: `createLlm` and `complete`

```ts
export type ChatMessage = { role: "system" | "user" | "assistant"; content: string };
export type CompleteRequest<S extends z.ZodObject> = {
  role: LlmRole; messages: readonly ChatMessage[]; schema: S; seed?: number;
};
export type Completion<T> = { value: T; model: string; cost: Cost; sampling: Sampling };
export type Llm = {
  complete<S extends z.ZodObject>(request: CompleteRequest<S>): Promise<Completion<z.output<S>>>;
};
export type LlmDeps = {
  logger: Logger;                        // pino; the caller passes a child with its runId
  fetch?: typeof fetch;                  // tests inject; default globalThis.fetch
  sleep?: (ms: number) => Promise<void>; // tests record the backoff instead of waiting
  timeoutMs?: number;                    // per attempt, default 300 000
};
export class LlmError extends WayfordError {
  readonly cost: Cost;                   // tokens already spent when the call failed
}
export function createLlm(settings: LlmSettings, deps: LlmDeps): Llm;
```

`createLlm` loads the price table and runs `priceOf` for all four roles, so an unknown model id fails before any call. An `Llm` is cheap to build (one small YAML read), and its logger is fixed when it is built. So a caller builds one per run, with that run's child logger, and parallel runs never share log lines. A boot check is one more `createLlm` call at startup.

The data flow of one `complete`:

1. **Sampling.** `Sampling.parse({ temperature, providerSeed: seed })`, with `providerSeed` present only when `seed` was passed. A seed outside `Sampling`'s range throws, since only a bug can pass one.
2. **Body.** Exactly `{ model, messages, temperature, seed?, reasoning?, response_format }`, where `messages` are the caller's, unchanged. `reasoning` is `{ effort }` when the role has an effort. It comes from config, never from a provider branch in code. `response_format` is `{ type: "json_schema", json_schema: { name: "response", strict: true, schema } }`, or `{ type: "json_object" }` when the model's `jsonSchema` is false. `schema` is `z.toJSONSchema(request.schema)` with `$schema` dropped and every `oneOf` renamed `anyOf`, since strict modes accept only `anyOf` (`packages/core/src/action.ts`). The rename is safe because every answer is re-parsed with the zod schema, which rejects whatever the looser `anyOf` lets through. Nothing else is rewritten: a provider that rejects a keyword answers 400, which surfaces as a typed failure naming the provider's message.
3. **Send**, `POST {baseUrl}/chat/completions` with `authorization: Bearer <key>` and `AbortSignal.timeout(timeoutMs)`. Up to 4 attempts, meaning the first plus 3 retries, with backoff of 1 s, 2 s, then 4 s. Retry happens when `fetch` or reading the body rejects with a network error, and on 429 and 5xx. Any other non-2xx fails at once. So does our own timeout: OpenRouter stops billing an aborted request only when it streams, and this one does not. A reasoning call that hits 300 s may still be generating and billed, so a retry would spend the same tokens again, where no usage would ever record them. The body is read whole with `text()` before anything uses it, so a retry always re-sends the same complete request and never a partial answer. A 2xx whose body is not a chat completion (`choices[0].message.content` and `usage.prompt_tokens`/`completion_tokens`) fails as `llm_bad_response`, with no retry.
4. **Parse.** `JSON.parse(content)`, then `schema.safeParse`. A null content counts as `""` and fails here.
5. **Repair**, once, when step 4 fails. The same body, with messages `[...caller's, { role: "assistant", content }, { role: "user", content: <the parse error, then "Answer again with only the corrected JSON object."> }]`. The zod error is rendered by `z.prettifyError`. Steps 3 and 4 run again. The code is straight-line, answer then repair, with no loop.
6. **Result.** On success, `{ value, model, cost, sampling }`: `model` is the configured id, the one priced, and `cost` sums `costOf` over every 2xx of both rounds. `usage.completion_tokens` already includes reasoning tokens, which bill at the output rate (OpenRouter, "reasoning tokens"). The table is flat, which makes the cost an estimate (Risks). Failed attempts return no usage, so they add nothing. A second parse failure throws `LlmError("llm_invalid_output")` carrying the cost of both rounds. A transport failure throws `LlmError("llm_request_failed")` carrying the cost spent so far.

One log line per attempt: `{ role, model, effort?, round: "answer" | "repair", attempt, outcome, status?, tokensIn?, tokensOut? }`, at `info` for `ok` and `warn` otherwise. `outcome` is one of `ok`, `http_<status>`, `error_in_body_<code>`, `network`, `timeout`, `bad_response`. No message content and no key. The effort is in the log line because the run record has no field for it yet (Risks).

Errors, all in one place:

| Thrown as | Code | When | Carries cost |
|---|---|---|---|
| `LlmError` | `llm_request_failed` | Retries used up on a network error, 429 or 5xx; any other non-2xx at once; our timeout at once, saying the provider may have billed it. The message names the status and the provider's error text, cut to 300 characters. | yes, the spend so far |
| `LlmError` | `llm_bad_response` | A 2xx whose body is neither a chat completion nor an error (build). An error inside a 2xx is read as its code instead: a 429 or 5xx is retried, anything else is `llm_request_failed`. | yes |
| `LlmError` | `llm_invalid_output` | The repair round's answer fails too. The message holds the prettified zod error, and `cause` holds the `ZodError`. | yes, both rounds |
| `WayfordError` | `llm_unknown_model` | `createLlm`, when a role's model is missing from `models.yaml`. | no call was made |
| `WayfordError` | `invalid_llm_settings` | `parseLlmSettings`. | no call was made |

### `fake-llm.ts`: the fake

```ts
export type FakeAnswers = Partial<Record<LlmRole, unknown[]>>;
export type FakeLlm = Llm & { calls: CompleteRequest<z.ZodObject>[] };
export function fakeLlm(answers: FakeAnswers, temperatures?: Partial<Record<LlmRole, number>>): FakeLlm;
```

Each call records the request, seed included, and takes the next canned entry for its role:

- An `Error` entry is thrown.
- Any other entry is parsed with the request's schema. A mismatch throws `LlmError("llm_invalid_output")`, the code the real adapter uses, so callers' failure paths are testable.
- An empty queue throws a plain `Error` naming the role: that is a broken test, not a model failure.

The result is `{ value, model: "fake", cost: { tokensIn: 0, tokensOut: 0, usd: 0 }, sampling }`. `sampling` is built the way `complete` builds it: the role's temperature from `temperatures` (1 when unset, the parser's default for every role), plus `providerSeed` when a seed was passed. So a test can check that "the configured temperature" arrives (s2-03).

### `smoke-llm.ts`: the smoke script

`pnpm --filter @wayford/agent smoke:llm` runs `tsx src/smoke-llm.ts`. It reads the root `.env` with Node's `process.loadEnvFile`, if the file exists, and a real environment variable wins. The path is resolved from `import.meta.url`, as io's `ENV_FILE` is, because pnpm starts the script in `packages/agent`.

It parses the settings and makes two calls. For each it prints the parsed object, then `cost: <in> in, <out> out, <usd> USD (<model>, effort <effort>, <ms> ms)`. The elapsed time is measured with `performance.now()`, is printed only, and gives the first real figure for sizing the timeout. The two calls:

1. The box: role `extractor`, `z.object({ capital: z.string() })`, a one-line question.
2. A schema probe: role `actor`, core's `ActorResponse`, and a two-line message that lists two refs and asks for one action as JSON. This proves Luna's strict mode, at the Actor's `high` effort, accepts `const`, `pattern`, `exclusiveMinimum` and the nested `anyOf` now, not in s2-03. It is not the Actor prompt, which stays out of scope.

It is the only file in `src` that reads `process.env`.

### io

`packages/io/src/config.ts` drops `LLM_BASE_URL`, `LLM_API_KEY` and the loopback rule, and `config.test.ts` drops their tests. The rule and its tests move to agent. Its comment "This is the only place `.env` is read" becomes "the only place io reads `.env`".

io does not call `parseLlmSettings` at boot yet: the first io caller of the adapter (s4-01) does. Wiring it now would make `pnpm dev` refuse to start without a key, for work that needs none. s4-01's task file is not this task's to edit, so the PR body and the summary say s4-01 now owns that boot call.

## Decision log

| Question | Taken | Why |
|---|---|---|
| Shape of the adapter | A factory, `createLlm(settings, deps)`, returning `{ complete }`. The fake returns the same `Llm` plus `calls`. | The adapter receives its config (task). `Llm` is the seam that s2-05 extends with `decide`. |
| Token counts and USD | Core's `Cost`: `{ tokensIn, tokensOut, usd }`. | The run record already uses it. A second shape would be a DTO beside a core schema. |
| Cost of a failed call | `LlmError extends WayfordError`, with a `cost` field. | The tokens were spent. Core's `Cost` says a step with no planned action is billed in the run's total, so s2-03 needs the number. Dropping it would make "30 runs for 1.20 USD" an under-count. It is still a `WayfordError` with a `code`. |
| When to use JSON mode | Per model, `jsonSchema: false` in `models.yaml`. | Deterministic. It needs no probe call and no "retry after a 400", which would clash with "do not retry 400". |
| What JSON mode adds to the messages | Nothing. The caller's prompt states the answer format. | The Actor's body carries only the caller's messages (reviewer note). |
| Schema rewriting | Drop `$schema`, and rename `oneOf` to `anyOf`. Nothing else. | The rename is the one rewrite `action.ts` already names. A general strict-mode sanitiser is out of proportion; a rejection surfaces as a typed 400. |
| "At most 3" retries | 3 retries after the first attempt, so 4 attempts, with backoff of 1, 2 and 4 s. `Retry-After` is ignored. | The same count as STACK's "max 3". Honouring `Retry-After` is not needed for one key. |
| A 2xx that is not a chat completion | `llm_bad_response`, no retry. | It is neither a network error, a 429 nor a 5xx, and the task allows retries on those only. |
| Timeout | 300 s per attempt through `AbortSignal.timeout`. It is not retried; it fails as `llm_request_failed`. | The lens asks for a timeout on every call. `max` effort on an Analyst-sized prompt can run for minutes, so 60 s would cut real calls. A non-streaming request is still billed after we abort it (OpenRouter stops billing an aborted request only when it streams), so retrying a timeout would pay twice, off the record. |
| Logger | pino's `Logger`, required in `deps`, fixed per instance. A caller builds one `Llm` per run. | pino is STACK's one logger, and the run's child logger carries the `runId`, so parallel runs never share one. Required, because the adapter must log every attempt. |
| Reported model id | The configured id. | It is the one priced and the one `modelIds.actor` records. OpenRouter's `model` field can name a provider variant. |
| Env names and defaults | `LLM_<ROLE>_MODEL`, `LLM_<ROLE>_TEMPERATURE` and `LLM_<ROLE>_EFFORT`, defaulted in the parser. | A fresh `.env` needs only the key. |
| Default models (revised at gate 1) | The model ladder's "While we build" column: Luna on every role, effort `high` for the Actor and the Extractor, `max` for Scout and the Analyst. | The user asked for the ladder's picks. The ladder compiles OpenRouter prices with Artificial Analysis scores and cost per task. While we build, the Analyst differs from the Actor by effort only, a deliberate departure from `AGENTS.md`'s "strong model there". The strong model is the escalation line in `.env.example`. |
| Temperature on the Luna defaults | 1 on every role. | Luna takes no temperature (OpenRouter lists none). The task sets a role on an OpenAI reasoning model to 1, and `Sampling` records it as sent. |
| How the effort is sent | `reasoning: { effort }`, OpenRouter's field, sent only when the role has one. | The ladder needs `max`. OpenRouter documents `max` for `reasoning.effort`, but its OpenAI-style `reasoning_effort` stops at `xhigh`. OpenRouter is the locked endpoint (`docs/PLAN.md`, "Locked decisions"). The field is set by config, never by a provider branch. |
| How to send no effort | The value `default`. An empty value stays "unset, take the default". | io's config treats an empty value as unset, and `.env.example` ships empty assignments. So `LLM_ACTOR_EFFORT=` must not silently drop the ladder's effort. `none` is a real effort (reasoning off), not "send nothing". |
| Pinning the OpenRouter host (the ladder's rule 3) | Not pinned: the user's decision at gate 1. No `provider` field is sent. | The spec proposed a `host` per model in `models.yaml`, sent as `provider: { order: [host], allow_fallbacks: false }`. The user approved the spec without it. What unpinned calls risk is under Risks, "Unpinned hosts". `provider.require_parameters` would not replace a pin: no Luna or Sol host takes `temperature`, which every request sends, so no host would qualify. |
| Long-prompt prices | Not modelled. A comment on the Luna and Sol entries gives the rates from 272k. | No caller crosses 272k before the Analyst (week 4). The ladder puts an Actor call at about 8k tokens (250k over 30 steps). The table also ignores cached-input rates, so it is an estimate either way. The Analyst task adds a tier if its prompt gets there. |
| Which ladder models are priced | Luna, Sol and Opus 5.5, plus the local Ollama model. ## Risks

- **`.env.example` is denied to the Read tool in this session.** If writing it is denied too, the user applies the diff by hand.
- **Default models age.** Prices and ids are from 2026-09-30, and Luna's price is eight days old: the ladder says to re-check it before the pitch.
  - A model OpenRouter retires fails the smoke run. A new id is a one-line change in `models.yaml` plus the default.
  - `openai/gpt-6-luna` is the id the ladder pins, and OpenRouter serves it as `openai/gpt-6-luna-20260922` today. If OpenRouter moves the id to a later snapshot, results can shift with no config change.
- **Unpinned hosts.** OpenRouter serves one model id from several hosts, at different prices and with different parameters. Its endpoint list on 2026-09-30 shows seven for Luna, and Sol has the same pattern:

  | Luna hosts | Price, in / out $ per 1M | `seed`, strict output |
  |---|---|---|
  | OpenAI, Azure | 0.10 / 0.50 | yes |
  | Azure US, Azure EU | 0.11 / 0.55 | yes |
  | Amazon Bedrock | 0.11 / 0.55 | no `seed`, no `response_format`, no structured outputs |
  | the `flex` and `fast` tiers | 0.05 / 0.25 and 0.20 / 1.00 | yes, but an unpinned call never reaches them |

  Unpinned, OpenRouter balances each call across the default-tier hosts, weighted by price, and silently drops what a host lacks. So:
  - **Bedrock.** A call routed there loses its strict schema and its seed. The zod re-parse and the repair round still guard the answer, and `Sampling` still records what was sent.
  - **Regional hosts.** A call there bills 10% above `models.yaml`.
  - **Detection.** Each `ok` log line names the host and snapshot that answered (`host`, `served`), so the smoke output shows it (build).

  If this bites, the ladder's rule 3 is the fix: a `host` per model sent as `provider.order`, with fallbacks off.
- **Effort is not on the run record.** Core's `Sampling` is strict, `{ temperature, providerSeed? }`, so a run cannot store the effort it was sent. The adapter logs it on every attempt. The PR body links a follow-up issue proposing an optional `effort` on `Sampling`. That is a core change needing one reviewer, and this task does not touch core.
- **The cost is a flat estimate.** Cached prompt tokens bill at `input_cache_read`, and `models.yaml` does not carry that rate: Luna's is $0.01 per million, against $0.10. The Actor re-sends a growing prompt prefix, so its real bill can be lower than the recorded cost. A call of 272k prompt tokens or more is the one case the other way: it bills above the recorded cost. No caller reaches that size before the Analyst.
- **`max` effort is slow and verbose.** The ladder puts Luna at `max` at about $0.08 a run, against $0.05 at `high`. First measurement, the smoke run of 2026-09-30 at `high` (build):
  - **Successful attempts.** 2 to 6 s each.
  - **A failed attempt.** An HTTP 525 took about 55 s to come back.

  So 300 s leaves room for `max` effort, and `max` itself is not measured yet.
- **Strict-mode keyword support differs by provider.** A caller's `min(1)` becomes `minLength`, which some strict modes reject with a 400. The smoke schema has one plain field; s4-01 and s2-03 hit this first and see a typed failure naming the keyword.
- **Worst-case latency.** Each of the 4 attempts has its own 300 s timeout. A timeout ends the call, but a 429, 5xx or network error that arrives late is still retried. So one round can take up to 4 × 300 s + 7 s, about 20 minutes, and a call with a repair round twice that. That takes a provider that answers errors only after minutes, and it is accepted for the adapter. The "agent hangs in front of the judges" trap is handled by the backup recording (`AGENTS.md`). A whole-call deadline can come with the first caller that needs one.
- **OpenAI's JSON mode requires the word "JSON" in the messages.** This is the caller's prompt; the Ollama path does not need it.
