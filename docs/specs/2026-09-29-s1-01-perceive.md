# s1-01 — Perceive: the page measurement, thresholds, soft bands and the seed: spec

Task: `tasks/s1-01-perceive.md` · Branch: `feature/s1-01-perceive` · Date: 2026-09-29
Status: approved 2026-09-29

## Goal

`PageMeasurement` exists as a core schema with a hand-measured fixture of `/deliveries`, and one pure function, `perceive(measurement, profile, runSeed)`, turns it into the step's `FullObservation`, so the Actor, the preview and the sweep all get their observation from the same code.

## Constraints that bind

- "Zero LLM in this layer" (`AGENTS.md`): no model, no network, no clock, no `Math.random`. "Every random number comes from `hash` in core, keyed by the run seed and the element key" (task). "The profile seed only draws the avatar" (`docs/PLAN.md` A20).
- "Perception: resolved once per element, deterministic within a run" (`AGENTS.md`), so one `rolled` per element, `hash(run seed, key)`, shared by all its soft rules (`docs/RULES.md`, "The roll").
- RULES arithmetic, exactly:
  - `>=` passes, and a hard cut never degrades.
  - The band's floor is `threshold × (1 − softness)`; in the band an element is `degraded` when `rolled < position`, otherwise `invisible`.
  - The worst state wins.
  - Decisions are listed in pipeline order, then rule id.
  - V2 records its side, and only `below` counts in `belowFoldCount` (since #118, only when perception leaves the element shown).
- `PageMeasurement` holds no threshold, state, ref or roll. "Controls, and text blocks: headings, paragraphs, list items"; a label's text is measured on the control it names (#117); P4 is for controls only (RULES "What is measured", issue #49).
- `./perceive` reaches only its own modules and `@wayford/core`: no Node built-in, no Playwright (`docs/STACK.md`, "Package import rules").
- Masked name: a pure function of the run seed, the key and the name. At least one character is masked, never all.
- Monotone: for a fixed run seed, raising any threshold never makes any element more visible.
- One alphabetical export line in core's `index.ts`. No core change outside the new measurement module: "If `Observation` or the random functions miss something, stop and report: the fix belongs in an issue" (Out of scope).
- Open PRs #112 (the mask's own draw) and #113 (monotonicity per rule, sweep test on Vera with the caps unset) edit this task file. Neither is merged. The design meets the task file as it is on `main` and as both PRs would leave it.

## Design

### Core: `packages/core/src/measurement.ts` (new)

Reuses `AriaRole`, `Metrics` (`observation.ts`), and `Bbox`, `HttpUrl`, `Viewport` (`primitives.ts`).

```ts
/** A control is something a person operates (link, button, checkbox); a text block is read. */
export const ElementKind = z.enum(["control", "text"]);

export const MeasuredElement = z.object({
  key: z.string().min(1),   // elementKey(...) from core, over the landmark ancestors
  kind: ElementKind,
  role: AriaRole,
  name: z.string(),         // a control's accessible name, a text block's visible text
  bbox: Bbox,               // CSS px, viewport coordinates (see below)
  metrics: Metrics,         // measured, never a threshold
}).strict()
  // refine: a text block carries no targetPx (P4 is controls only, RULES "What is measured")
  // refine: key ends in `//${role}:${name}`, so role and name cannot drift from the key

/** Where the viewport sits on the page: `window.scrollX`, `window.scrollY`, in CSS px. */
export const ScrollOffset = z.object({ x: z.number(), y: z.number() }).strict();

export const PageMeasurement = z.object({
  url: HttpUrl,
  title: z.string(),
  viewport: Viewport,
  scroll: ScrollOffset,
  elements: z.array(MeasuredElement),  // measurement order; refs follow it
}).strict();
```

Coordinate space, stated in the schema doc: every `bbox` is in CSS pixels in **viewport coordinates**, as `getBoundingClientRect()` and Playwright's `boundingBox()` give them, with the origin at the viewport's top-left. The viewport is `[0, viewport.width) × [0, viewport.height)`, and an element's position on the page is `bbox + scroll`. So V2 is decided from `bbox` and `viewport` alone. `scroll` says where on the page the step was: the preview can lay the page out from it. With viewport coordinates, the Actor's `at x,y` line matches its `Viewport: W x H` line, and a click coordinate a harness takes from a bbox is the one `page.mouse` uses. `FullObservation` has no scroll field, and #119 decided it gets none: a stored step's boxes are viewport positions, and the page position exists only in the measurement, which is not stored.

### Filter: `@wayford/filter/perceive`

```ts
// packages/filter/src/perceive.ts, the browser-safe entry
export function perceive(
  measurement: PageMeasurement,
  profile: Pick<Profile, "perception">,
  runSeed: Seed,
): FullObservation;
```

The type says the profile seed is never read. A full `Profile` is accepted. Per element, in measurement order:

1. **V2** (stage 1). If `bbox.x >= viewport.width`, add `{ stage: "viewport", rule: "V2", side: "right" }`. If `bbox.x < 0` and `bbox.x + bbox.width <= 0`, add the same with `side: "left"`. Otherwise, if `bbox.y >= viewport.height`, add it with `side: "below"`, and if `bbox.y < 0` and `bbox.y + bbox.height <= 0`, with `side: "above"`. Partial overlap counts as inside ("elements intersecting the viewport"). As approved, the spec checked the vertical only; #116 added the sides. An element gets one side, and the horizontal wins, since the Actor scrolls only up and down.
2. **P1** `contrast`, **P3** `fontPx`, **P4** `targetPx` (controls only). Each rule applies when the profile sets that threshold and the element has that metric. It is checked on every element, including those V2 cut, because "every rule an element fails is recorded":
   - `value >= threshold`: no decision.
   - hard cut (`softness` absent or 0): `invisible`, no `rolled`.
   - soft cut: `rolled = hash(runSeed, key)`, computed once per element and only when a soft rule fails, and stored on every soft decision. Below `floor = threshold × (1 − softness)` the state is `invisible`. In the band, with `position = (value − floor) / (threshold − floor)`, the state is `degraded` when `rolled < position`, otherwise `invisible`.
3. `state = worstState(decisions)` (core). Decisions are pushed V2, P1, P3, P4, which is already pipeline order, then rule id (`decisionOrder` in `observation.ts`).
4. A shown element (`visible` or `degraded`) gets the next ref, `e1..eN`. A `degraded` one gets `maskedName = maskName(runSeed, key, name)`.

Header: `url`, `title` and `viewport` come from the measurement. `stepIndex` is 0: `perceive` does not know the step, so the Actor loop sets it on the result (`{ ...full, stepIndex }`), and `runResultFromEvents` already rejects an observation whose `stepIndex` differs from its step's (`run.ts:578`). `hiddenCount` is 0, since no attention rule is in scope. `belowFoldCount` counts the V2 `below` elements none of whose P1, P3 and P4 decisions is `invisible`; one that perception removes keeps its V2 decision and is not counted (#118). There is no `screenshotPath`. `bbox` and `metrics` are copied, not shared, so a caller cannot change the measurement through the result.

The output is not parsed with zod: the function stays fast, and tests parse it instead. The input is typed, not re-validated, the same way `toActorObservation` treats its input.

**The mask** (`packages/filter/src/mask.ts`). This follows #112's "The mask": the share comes from its own draw, never from `rolled`. Every number is a `hash` of the run seed and the element key.

- `share = hash(runSeed, key + ":mask")`.
- Maskable characters are the name's non-whitespace code points (iterated by code point, so no lone surrogates). There are `n` of them.
- `n >= 2`: `k = 1 + floor(share × (n − 1))`, so `k` runs from 1 to `n − 1`.
- `n = 1`: that one character is masked.
- `n = 0`: the name is returned unchanged.
- Which `k` are masked: the maskable character at code-point index `i` draws `hash(runSeed, key + ":mask:" + i)`. The `k` lowest draws are masked, ties by index.
- Each masked character becomes `▒` (U+2592), as in `observation.json`, so the length is kept.

**Band arithmetic** (`packages/filter/src/band.ts`): the one function that turns value, cut and a lazy roll into no decision, `invisible` or `degraded`, plus the stored `rolled`.

**Entry and barrel.** `packages/filter/package.json` exports `"./perceive": "./src/perceive.ts"`. `src/index.ts` becomes `export * from "./perceive.js";`. The placeholder `measuredMetrics` and its test are removed; only that test used it.

**Browser-safety guard.** Two checks:

- `src/perceive-imports.test.ts` starts from the file `package.json` maps `./perceive` to. It follows every `import`/`export … from`, side-effect `import "…"` and dynamic `import("…")` through relative modules, and fails on any other specifier except exactly `@wayford/core`. Its walker is also tested on in-memory sources containing `node:fs` and `@wayford/core/fixtures`, so the test can be shown to fail.
- `tsconfig.perceive.json` typechecks `src/perceive.ts` and what it reaches, with the bare base config (no DOM, no Node types). The main `tsconfig.json` gets `types: ["node"]` for the tests and the bench, which read `@wayford/core/fixtures` (`node:fs`). This is the same two-program pattern as `packages/target-app`.

**Bench.** `packages/filter/scripts/bench-perceive.ts` runs under `tsx` as `pnpm --filter @wayford/filter bench:perceive`. It warms up, then times 100 calls with `performance.now()`, cycling the four persona fixtures over run seeds 1 to 100 on `measurementFixture`. It prints the average in ms against the 5 ms budget. It never fails: it is a script, not a test.

## Decision log

| Question | Taken | Why |
|---|---|---|
| Coordinate space of `bbox` | viewport coordinates, CSS px; `scroll` recorded on the page | the Actor's `at x,y` then agrees with its `Viewport` line even after a scroll, and the `Observation` header has no scroll to relate page coordinates to (review finding 3); Playwright's `boundingBox()` and `page.mouse` use this space; the page position is `bbox + scroll` in the measurement, which a stored step does not keep |
| Fixture viewport | 1280 × 720, scroll 0 | Playwright's default and "Desktop Chrome", what `s1-02` and `s2-02` get without asking; nothing is below the fold there, so the V2 box uses derived measurements |

## Risks
