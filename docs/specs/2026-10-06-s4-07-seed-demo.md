# s4-07 — `seed:demo`: the demo's data in one command: spec

Task: `tasks/s4-07-seed-demo.md` · Branch: `feature/s4-07-seed-demo` · Date: 2026-10-06
Status: approved 2026-10-06 (auto)

## Goal

`pnpm seed:demo` fills the database with everything the dashboard, the report and the sweep screens show in the demo. It prints how many runs it made, how long it took and what it cost.

## Constraints that bind

- **F11:** one command seeds 3 personas, 2 tasks, 10 runs per persona per task, and one sweep per axis. The dashboard looks populated afterwards.
- **A20:** a run set uses the same seed list for every persona. A sweep reuses the seed set at every value.
- **A22, ADR 0001:**
  - A run set uses one backend, and nothing falls back to the other.
  - The gate passed, so the default is Jev.
  - Jev's confidence is stored and never acted on.
- **The task's Constraints:**
  - The default backend is `jev`. `--backend llm` is the fallback.
  - `--fake` needs no key. It fakes the backend the real command runs: Jev on a fake `decide` that answers from the page it is shown, so each step stores a `decision` drawn through `drawOption`. The Analyst is faked too.
  - `--fake` and `--backend llm` do not combine.
  - A task with no `runs/ground-truth/<task>.json` gets a warning naming `pnpm --filter @wayford/agent scout`. `seed:demo` does not run Scout.
  - The run sets, the Analyst and the sweeps are one function. The command calls it with the full set, and the test calls it with a reduced one.
  - It refuses a database that already holds runs, unless `--reset`, which empties runs, reports and sweeps first.
  - One summary at the end, pasteable: runs by outcome, wall time, total cost, cost per run.
- **Out of scope:**
  - Milo and Zoya;
  - scheduling or resuming. A failed seed is rerun with `--reset`.
- **Import rules** (`docs/STACK.md`): io imports core, filter and agent. A module that loads agent's runtime or Playwright stays out of io's barrel (s4-03, "The barrel").
- **Determinism** (`docs/CONVENTIONS.md`):
  - No `Math.random`.
  - The fake Jev is a pure function of the request it is sent.
  - The draw is `jevActor`'s own, on the run's decision stream.
- **Words** (`docs/DEMO.md`): the summary prints our measured numbers only, never Jev's published figures.

## Design

### What runs

`DEMO_PLAN`, the full set the command runs:

- **Run sets:** Ada, Kai and Vera on `task_next-parcel` and `task_past-order`, seeds 1 to 10. That is 60 runs.
- **Analyst:** on both tasks, on the run sets' backend.
- **Sweeps,** both on `task_past-order` with seeds 1 to 10, using `s4-05`'s ranges:
  - Vera on `contrast` from 1.5 to 4.5 by 0.5: 7 values;
  - Kai on `maxElements` from 16 to 4 by 2: 7 values.

  That is 140 runs.

In all, 200 runs, 2 reports and 2 sweeps.

### `packages/io/src/seed-demo.ts`: the one function, the fakes, the store helpers

The module loads agent's runtime (`jevActor`) and filter's routes, so it stays out of io's barrel, like `sweep-cli.ts` and `chromium.ts`. Nothing runs on import.

As built (build: the branch review, `simplify` and the merge with s4-06 shaped the last three types):

```ts
export type DemoSweep = Omit<SweepInput, "seeds" | "backend">;  // the plan's seeds and backend are the seed's
export interface DemoPlan {
  personas: readonly Profile[];   // Ada, Kai, Vera
  tasks: readonly Task[];         // task_next-parcel, task_past-order
  seeds: readonly Seed[];         // 1..10, the run sets' and every sweep's
  sweeps: readonly DemoSweep[];
}
export const DEMO_PLAN: DemoPlan;
export function plannedRuns(plan: DemoPlan): number;          // refuses a bad range via `sweepPlan`
export function plannedDevices(plan: DemoPlan): DeviceKind[]; // the run sets' and the sweeps' personas

/** The Analyst's deps (db, llm, groundTruthDir, jevModel, axe, logger), its routes read off `walks`. */
export interface SeedDemoDeps extends Omit<AnalystDeps, "routes"> {
  runner: Runner;                 // io's runner, on the backends the command picked
  backend: ActorBackendName;      // what every run set and sweep runs on, and the reports read
  walks: ReadonlyMap<DeviceKind, readonly WalkedRoute[]>;  // walked on `plannedDevices(plan)`
  say: (line: string) => void;    // one progress line, for stderr: phases, each sweep value
}

export interface DemoSummary {
  backend: ActorBackendName;
  models: string[];               // the Actor models the stored runs name, each once
  /** Every run this call started, run sets and sweeps, by outcome. A run never stored is `missing`. */
  outcomes: Record<RunOutcome | "missing", number>;
  setRuns: number;                // outside any sweep; the sweeps' runs are their values' `runIds`
  runsUsd: number;                // summed over the stored runs; the Analyst's is each report's own
  reports: Report[];
  sweeps: Sweep[];
  wallMs: number;
}

export async function seedDemo(deps: SeedDemoDeps, plan: DemoPlan): Promise<DemoSummary>;
export function summaryText(summary: DemoSummary): string;
```

`seedDemo` runs three phases in order. Each phase waits for the one before it.

1. **Run sets.** `runner.start(task, plan.personas, plan.seeds, { backend })` is called for each task, one after the other, so both sets share the runner's five slots in one FIFO. It then waits until every run has ended, through `sweep.ts`'s `ended`, which is now exported. Each ended run is stored by then, or its save has failed and been logged.
2. **Analyst.** `analyseAndStore(analystDeps, task.id, backend)` runs for each task, one after the other (PR review). Each is one call, and they are independent, but a failed call ends the seed, and a second call still in flight would go on billing after the command has closed the browser and the store.
   - `analystDeps` is the deps themselves with `routes: routeFactsFrom(walks, targetAppJargon)`. Since s4-06 they carry `axe`, an `AxeLookup`. The command builds it on the app it serves and the browser it shares (`axeLookup` over `axeScanner`), so each page the runs stood on is scanned once and stored (build, merge with s4-06).
   - `ok: false` cannot happen after phase 1 unless every run of a task failed to store. If it does, it throws `WayfordError("seed_demo_no_report", error)`.
   - The Analyst runs before the sweeps, so a report reads the run set alone, and its `leftOut` counts no sweep runs.
3. **Sweeps.** `runSweep` runs for each `DemoSweep`, one after the other. Its deps are `{ db, runner, logger, routeOpen, onValue }`, and its input is `{ ...sweep, seeds: plan.seeds, backend }`.
   - `routeOpen` is `routeOpenFrom(routesFor(walks, task.id, profile.device), targetAppJargon, routeOpenSeeds)`, which gives `undefined` for every profile when the task has no route table (build).
   - `onValue` says one line per value: `sweep      Vera contrast 3.0: 4/10 got through, route open 4/10`.
   - There is no `maxUsd`. The full set costs about 0.1 USD on Jev by s4-05's figures (decision log).

The summary loads every run id the call started: the run sets' `StartedRun` ids, and each stored sweep's `values[].runIds`. It counts outcomes, and `missing` for an id with no record, then sums `cost.usd`. The wall time is `performance.now()` around the three phases. Setup, meaning the build, the serve and the walk, is outside it and is printed apart by the command.

`summaryText` is what the command prints to stdout, so it pastes alone. Each sweep takes two lines: its header with its id, then `sweep-cli.ts`'s boundary line (build, after the spec review moved those helpers into `sweep-text.ts`). Every outcome prints, a 0 included. The numbers below are illustrative:

```
seed:demo on jev, typesafe/jev-1.13
runs       200: 151 success, 41 gave up, 6 budget exceeded, 2 error
           60 in the run sets, 140 in 2 sweeps
reports    task_next-parcel, task_past-order
sweep      Vera contrast, 1.5 to 4.5, swp_…
boundary   3.0 (rate 40%)
sweep      Kai maxElements, 16 to 4, swp_…
boundary   12 (rate 0%)
wall time  6m 12s
cost       0.0912 USD: runs 0.0850 USD, Analyst 0.0062 USD
per run    0.0004 USD
```

- A sweep with no boundary reads `no boundary up to <last value>`.
- A sweep whose boundary stopped at an errored value reads `no boundary: <value> had errors`.
- These are `sweep-cli.ts`'s own words. Its `shown`, `percent`, `boundaryLine` and `wallTime` move into a new `sweep-text.ts`, and both commands import them from there, so a boundary reads the same in both printouts (spec review).
- A `missing` count is printed only when it is above 0.

**Store helpers,** which the command calls before `seedDemo`:

- `storedCounts(db): Promise<{ runs: number; reports: number; sweeps: number }>`.
- `emptyStore(db, runsDir?): Promise<void>`:
  - deletes every row of `runs`, `reports` and `sweeps` in one transaction;
  - then, when `runsDir` is given, removes `<runsDir>/<id>/` for each run id it deleted. A `RunId` is `run_[a-z0-9-]+`, so the path stays inside `runsDir`.
  - `runs/ground-truth/` and `runs/calibration/` are never touched. Tasks, profiles and the stored axe-core scans are kept.
  - The command passes `runsDir` only when `DATABASE_URL` names the default database. Every database's runs write into the one `runs/`, and a copy's run ids are the original's, so a reset of a copy keeps the folders and says so (build, PR review).
- `runFoldersFor(databaseUrl, runsDir): string | undefined`: `runsDir` when `databaseUrl` resolves, through `sqliteFilePath`, to the same file as `DEFAULT_DATABASE_URL`, and `undefined` otherwise. The command passes its answer to `emptyStore` (PR review).
- `groundTruthWarnings(dir, tasks): Promise<string[]>`:
  - one line per task with no ground-truth file, naming `pnpm --filter @wayford/agent scout`;
  - it reads each file through `readGroundTruth`, before anything is served or run. A file that cannot be read throws as the read failed. One that is not JSON, fails `GroundTruth` or holds another task's ground truth throws `invalid_ground_truth`.

### `--fake`: Jev and the Analyst, answering from what they are shown

```ts
/** What `--fake` runs on: no key, no network. */
export const FAKE_JEV_MODEL = "fake-jev";
export function fakeDemoBackends(): RunnerOptions["backends"];  // jev: the fake Jev; llm: throws
export function fakeDemoLlm(): Llm;                             // the fake Analyst; also serves the fake Jev's decide
export function fakeJevAnswer(request: DecideRequest);        // its type inferred: `fakeLlm` checks it with `choiceAnswer`
export function fakeAnalystAnswer(request: CompleteRequest<z.ZodObject>);  // inferred: checked against the schema sent
```

**The fake Jev** is the real `jevActor` with a fake `decide`:

- `fakeDemoBackends` returns `jevActor({ settings, llm: () => fakeDemoLlm() })`, with the settings built inside it as `parseLlmSettings({ LLM_API_KEY: "fake-key", LLM_JEV_MODEL: FAKE_JEV_MODEL })`. The key is never sent: the `llm` override means `createLlm` is never built.
- The options, the draw on the run's decision stream, the `decision` record and the 255-option guard are therefore the real backend's. Only Jev's probabilities are faked.
- A fake run's `modelIds.actor` is `fake-jev`, so no screen names Jev's real model on fake data, and `backendOf` reads it as Jev by its `decision`.
- `test-app.ts` has its own `FAKE_JEV_MODEL`, with the same value, for io's tests. The two stay apart on purpose: test support must not load `seed-demo.ts`, and `seed-demo.ts` must not import test support.
- `@wayford/agent/fake`'s header lists its users, and `seed:demo --fake` joins them, as a comment-only change. The command uses it as a data mode, not a test.

`fakeDemoLlm().decide(request)` answers through `fakeLlm({ actor: [fakeJevAnswer] }).decide(request)`. That is agent's own fake, built once per call, so `choiceAnswer` checks every answer against the options sent. `fakeJevAnswer` reads three things:

- **The goal:** the task fixture whose `Your goal: <goal>` line the state holds.
- **The page:** the state's `URL: ` line. History lines start `- On`, so only the page has one.
- **The options:** each click option's words, `Click [e3], the link "Deliveries"`, parsed into a role and a quoted name.

The steps toward each goal:

- for `task_past-order`, the steps of filter's `TARGET_APP_ROUTES` (routes A, B and C);
- for `task_next-parcel`, `/` "Your account" then `/account` "Delivery address", the path calibration's fake follows.

A click option is a hit when its role is a step's role on this page and its name reads as the step's name through the mask. Reading through the mask means the same length in code points, and every character equal or `▒`, as `sweep.browser.test.ts` reads it. So:

- a degraded link is followed;
- a gone one is never offered;
- a renamed one (K1, K4, K2's `[unfamiliar term]`) is not a hit.

Per route only the latest step that is a hit counts, so an open menu's "Past orders" wins over "More options".

The probabilities:

- **With hits:** 0.9 shared evenly by the hits, and 0.1 shared evenly by every other option. The draw then strays now and then, which gives the Jev panel a real spread and the runs some variance.
- **With none:** `give_up` 0.5, `back` 0.3, `scroll_down` 0.2, and 0 elsewhere.
- `choice` is the first option with the highest probability, and `confidence` is that probability.

The goal is never read beyond picking the task: the fake knows the routes, and the persona reaches it only through the observation, as a real Jev does.

**The fake Analyst:** `fakeDemoLlm().complete(request)` answers through `fakeLlm({ analyst: [fakeAnalystAnswer] }).complete(request)`, so the answer schema checks it. Any other role throws.

- It writes one recommendation per draft key the answer schema asks for, the keys read off `request.schema` as `analyst.browser.test.ts` reads them. Each says it was written by `seed:demo --fake`.
- It writes at most one hypothesis:
  - on the first run in the case's "Runs" section whose header (`run <id>: <persona>, seed <n>, <outcome>, <k> steps, …`) has an outcome other than `success` and at least one step;
  - citing that run's last step, with no rules;
  - titled and worded as written by `seed:demo --fake`.

  The Analyst's own checks then keep it, so the report screen gets a hypothesis on real evidence. With no such run, it writes no hypothesis.

### `packages/io/src/seed-demo-cli.ts`: the command

`pnpm seed:demo [--fake | --backend llm|jev] [--reset]`. The root script runs `pnpm --filter @wayford/io seed:demo`, and io's script runs `tsx src/seed-demo-cli.ts`. The steps run cheapest first:

1. **Arguments,** through `parseArgs` after `scriptArgs`:
   - `--fake` with `--backend llm` is a usage error, exit 2;
   - `--backend` is read with `readBackend`, and absent means `jev`. That differs from the sweep CLI's `LLM_ACTOR_BACKEND` default: the task says the default is Jev.
2. **Config:** `loadConfigFromEnvFile()`.
   - Real: `settings = parseLlmSettings(process.env)`, which fails without a key. Then `createLlm(settings, { logger })` builds the Analyst. It checks every role's price, so an unpriced model fails here.
   - Real: the estimate, `estimateUsd(priceOf(loadModelPrices(), actorModelOf(settings, backend)), runCount, DEFAULT_MAX_STEPS)`, printed and never refused (decision log). `runCount` comes from `sweepPlan` over `DEMO_PLAN`, which also refuses a bad range before anything is served.
   - Fake: no settings are read. The fake backends and the fake Analyst are built, and `jevModel` is `FAKE_JEV_MODEL`.
3. **Database:** `migrateDatabase`, `openDatabase`, then `storedCounts`. When any count is above 0 and there is no `--reset`, it refuses with exit 1: `the database already holds 60 runs, 2 reports and 2 sweeps; rerun with --reset to empty them first`.
4. **Ground truth:** `groundTruthWarnings(RUNS_DIR/ground-truth, DEMO_PLAN.tasks)` prints each warning to stderr.
5. **Serve and walk.** First `exitOnTermination()`, before Chromium launches, as `sweep-cli.ts` calls it: Playwright's handlers otherwise keep a SIGTERM from ending the process. Then the target app is served on 5174 (`serveOnFixturePort`), and `walkRoutes(plan devices)` runs at the same time when a plan task has a route table, as the sweep CLI does.
6. **Reset:** with `--reset`, `emptyStore(db, runFoldersFor(DATABASE_URL, RUNS_DIR))` runs now, after every refusal and after the serve succeeded, so a failed start never empties anything.
7. **Runner and seed:**
   - The runner is built as `sweep-cli.ts` builds it: `sharedBrowser` and `sharedChromium`, the backends (real `actorBackends(settings)` or `fakeDemoBackends()`), `defaultBackend: backend`, `TARGET_APP_DEFAULTS`, `targetAppJargon`, `RUNS_DIR` and the logger.
   - It then runs `seedDemo(…, DEMO_PLAN)`.
8. **Output:** `summaryText` goes to stdout. Progress lines (`say`) and pino logs go to stderr, so stdout pastes alone. The logger's level is `process.env.LOG_LEVEL`, read after `.env` is loaded, else `warn`; `config.LOG_LEVEL` cannot tell the two apart, since it defaults to `info`. `jevActor` logs every decision at `info`.
9. **Close:** the browsers, the app and the database close in `finally`.

The exit code is 0 when the seed completed and no run errored or went missing, and 1 otherwise. On a failure it prints the line through `printFailure`, then `rerun with --reset`.

### Changed elsewhere

- `sweep.ts`: `ended` is exported, so `seedDemo` waits on a run set the way a sweep waits on a value.
- `sweep-text.ts` (new) takes `shown`, `percent`, `boundaryLine` and `wallTime` from `sweep-cli.ts`, which imports them back.
- Comments that name the importers, now stale, are updated:
  - `server.ts` and `chromium.ts` list the modules that load agent's runtime;
  - `analyst-routes.ts` lists its importers;
  - `fake-llm.ts`'s header lists the fake's users.

### Data flow

```
seed-demo-cli ─ args, config, counts, ground truth ─┐
  serve 5174 + walkRoutes ─ reset ─ createRunner ───┤
                                                    ▼
seedDemo: runner.start × tasks → ended → analyseAndStore × tasks → runSweep × sweeps → summary
            │ runActor → jevActor(fake or real decide) → drawOption → saveRun
            └ Analyst: routeFactsFrom(walks) + llm (fake or real) → saveReport;  runSweep → saveSweep
```

## Decision log

| Question | Taken | Why |
|---|---|---|
| Where the command lives | `seed-demo-cli.ts` beside `seed-demo.ts` | the CLI loads `.env` and serves on import, so its test could not import it. `sweep.ts` and `sweep-cli.ts`, and `analyst.ts` and `analyse.ts`, split the same way |
| Order of the phases | run sets, then the Analyst, then the sweeps | the report then reads the run set alone and counts no sweep runs as left out. The sweeps need nothing from the report |
| Concurrency | both run sets in one queue. The two Analyst calls one after the other (PR review). The sweeps one after the other | the runner's five slots are the limit either way. Two sweeps at once would only fill the tail of each value, and a failing one would leave the other running against a closing browser. Two Analyst calls at once had the same flaw: one failing left the other billing against a closed browser and store, its spend never printed. One after the other costs one call's wait and prints the reports in task order |
| The fake Jev | the real `jevActor` with `decide` faked through agent's `fakeLlm`, probabilities 0.9 on the hits and 0.1 spread, give-up and back when nothing is a hit | the options, the draw, the record and its checks stay the real code's, so `--fake` data is real-shaped. The spread gives the Jev panel a distribution and the runs variance. A fake that always walked the route would make every persona's rate 0% or 100% |
| Hits through the mask | as `sweep.browser.test.ts` reads them: same length, every character equal or `▒` | a degraded element is offered masked, so a fake that needed the exact name would make degraded mean gone. The bound test showed that difference matters |
| The fake's model id | `fake-jev` on `modelIds.actor` | no screen should name Jev's real model on data Jev never saw. `backendOf` reads the run as Jev by its `decision` either way |
| The fake Analyst's words | recommendations and one hypothesis on real evidence, each saying `seed:demo --fake` wrote it | the report screen (`s3-08`) needs every finding type on real-shaped data, and nobody should mistake fake text for a reading |
| The refusal | any run, report or sweep stored refuses, not runs alone | a stale report or an orphaned sweep would show on the demo screens beside the new data. It is the same refusal one step wider |
| `--reset` and run files | it deletes the rows, then each deleted run's folder under `runs/`, by id | 200 runs' videos per seed otherwise pile up with every rehearsal. A `RunId` cannot leave `runs/`, and `ground-truth/` and `calibration/` are never named |
| When `--reset` empties | after every refusal and after the app is served | a start that fails, for example on a busy 5174, leaves the old data as it was |
| A cost guard | none. The estimate is printed only | the task names no limit. The full set is about 0.1 USD on Jev by s4-05's measured sweeps, against a 50 USD cap. The printed estimate still shows a misconfigured model before the runs |
| The default backend | `jev`, not `LLM_ACTOR_BACKEND` | the task's constraint, and ADR 0001's gate. The race keeps the LLM through `LLM_ACTOR_BACKEND` |
| Wall time | the three phases, from the first run started to the last sweep stored | that is the pitch's "N runs in M minutes". The build, serve and walk are setup, printed on stderr |
| Total cost | runs plus the Analyst; per run, the runs alone | "N runs for X USD" needs the run cost. The Analyst's cost is real spend, so the total holds it |
| Exit code | 1 when a run errored or went missing, after the summary | a rehearsal should notice a run that broke. "A failed seed is rerun with `--reset`" |
| Logs | stderr at `warn` unless `LOG_LEVEL` is set; progress lines on stderr; the summary alone on stdout | `jevActor` logs every decision at `info`, which is 800 lines here |
