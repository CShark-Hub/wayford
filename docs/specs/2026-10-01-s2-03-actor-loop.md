# s2-03 — Actor loop: observe, act, record: spec

Task: `tasks/s2-03-actor-loop.md` · Branch: `feature/s2-03-actor-loop` · Date: 2026-10-01
Status: approved 2026-10-01

## Goal

One command runs one persona on one task with one run seed against the target app. The loop observes through the filter, asks the model for one action, acts, records evidence and emits every `RunEvent`, and leaves a `RunResult`, a `webm` and a `trace.zip` under `runs/<run id>/`.

## Constraints that bind

- "The Actor must be our own loop" (`AGENTS.md`). Each step is `collect`, `perceive`, `toActorObservation`, `renderObservationForModel`, then the model, which "gets nothing else from the page" (task).
- "The persona is a filter, not a prompt." The template is identical for every persona; no persona name, trait, threshold or impairment reaches it (F5 AC6).
- The history names every element "as the Actor read it, its masked or renamed name, never the name in the evidence" (task). One function renders it; `s2-10` truncates it there (M1).
- One seam, the Actor backend: goal, Actor-facing observation text and rendered history in, an `Action` and optional narration out. `s2-06` adds Jev behind it.
- A ref the observation lacks gets one retry carrying the error, then the step is wasted (`stepWasted`, both answers as parsed, the step's cost); never a Playwright crash (task, `WastedRunStep`).
- The page settles before each `collect`: `document.fonts.ready`, and no CSS animation or transition running (task).
- The cursor moves to the element's box first and the action lands at that point (task, F5 AC7).
- Ends: `giveUp` ends `gave_up`; a step cap from config ends `budget_exceeded`, checked at the end of every step, wasted ones included, after the success check (F5 AC5). Success is the task's `SuccessCondition`, checked after every action, never by asking the model.
- Every event passes `RunEvent`; the `RunResult` written is `runResultFromEvents` of the events emitted; a crash ends with `runFailed` and the partial step stored (task).
- No dice, no budget, no provider seed, no `actorSampling`, no memory truncation: all `s2-10` (Out of scope). Every `actionPlanned` therefore has `performedAction` equal to `proposedAction` and `dice: []`.
- No test calls a real LLM (`docs/CONVENTIONS.md`). No new dependency (`docs/STACK.md`).

## Design

Scope: the task file as merged in #139 (13 boxes). Everything `s2-10` adds has one marked place here (see "Hand-off to s2-10").

### `actor-loop.ts`: `runActor`

```ts
export const DEFAULT_MAX_STEPS = 20;

export interface RunActorOptions {
  browser: Browser;             // the caller's: runActor never launches or closes it
  profile: Profile;
  task: Task;
  seed: Seed;                   // the run seed (A20)
  params: TargetAppParams;
  runsDir: string;              // files go under <runsDir>/<runId>/
  backend: ActorBackendFactory;
  logger: Logger;               // pino; the run logs on logger.child({ runId })
  runId?: RunId;                // newId("run") when absent; s4-03 passes the one it minted
  onEvent?: (event: RunEvent) => void;
  maxSteps?: number;            // DEFAULT_MAX_STEPS when absent
}

export function runActor(options: RunActorOptions): Promise<RunResult>;
```

**Before any event.** (build) `runActor` rejects with no event only where no run can be started: a `maxSteps` that is not a positive integer or an empty `runsDir` (`WayfordError` `invalid_run_input`), `startUrlFor(task, params)` throwing `invalid_target_app_params`, a backend factory that throws, or a `runStarted` that fails `RunEvent.parse` (a bad run id, task id, profile id or seed). The run id is minted, the logger made and the backend factory called with `{ logger }` first. Everything else about the inputs is the run's own failure: s4-03 returns a run id before the run starts, and a rejection would leave that id with no events.

**Start.** `t0 = Date.now()`. `runStarted` (step 0, timestamped `t0`, with the ids, the seed, `startUrl` from `startUrlFor` and `modelIds: { actor: backend.modelId }`) is built and parsed. From here on, one `try` catches every failure (below): it delivers `runStarted`, then `checkSuccessCondition` when `task.success` passes its schema (a pattern that cannot match ends the run `invalid_success_condition` before a context, a video and a trace are opened for it; build, from the simplify pass), then `openRunContext({ outputDir: <runsDir>/<runId> })`, whose `invalid_run_context` covers a profile or task that fails its schema, then `watchSuccess(page.context(), task.success)`.

**Each step `k`**, from 0:

1. Observe. `page.url()` must parse as `HttpUrl`, else `WayfordError` `off_http_page` (see "Other landings off http(s)" in the decision log). Inside `retryOnNavigation`: `run.restorePointer()` (build), `settle(page)`, then `collect(page, { isMobile: run.isMobile })`. Then `full = { ...perceive(measurement, profile, seed), stepIndex: k }` and `shown = toActorObservation(full)`. Emit `stepObserved`.
2. Ask. `turn = actorTurn(task.goal, shown, history)`; `first = await backend.answer(turn)`. When `checkActionRef(first.response.action, shown)` fails, `second = await backend.answer({ ...turn, retry: { refused: first.response, ref } })`. When that fails too, emit `stepWasted` with `[first, second]` and the summed cost, push `{ observation: shown, wasted: true }` to the history, and go to step 6. A retry that is accepted is acted on; the refused first answer goes to the log at `warn` and its cost stays in the step's.
3. Plan. Emit `narration` when the accepted narration is non-empty. Emit `actionPlanned` with the action as both proposed and performed, `dice: []` and the step's cost. (`s2-10` puts B1 here.)
4. Act. `arrival = performAction(run, action, shown)` puts the input in (see `act.ts`). Then (PR review) `arrival.wait()`, the navigation the action started, and, inside `retryOnNavigation`: (build) `run.restorePointer()` puts the real pointer back on the point the last action pressed, which the run context keeps, so the hover state is decided now and not by Chromium's own timer after a navigation or a scroll, and the step's screenshot and the next observation see the same one; `settle(page)`, `urlAfter = page.url()`, (PR review) `met = success.met(page, urlAfter)` on the document the screenshot shows, and `run.screenshot(k)`. Emit `actionPerformed`. If the arrival, the settle, the success check or the screenshot throws, `actionPerformed` is emitted with `urlAfter` and no screenshot, then the error ends the run. Push `{ observation: shown, proposed: action }`.
5. End checks, in this order: `met` ends `success`; a `giveUp` ends `gave_up`.
6. Cap: `k + 1 >= maxSteps` ends `budget_exceeded`.

**End.** `endMs = Date.now()` when the ending is decided. `run.close()` (once). Emit the terminal event at the last observed step's index (0 when none), with `timestamp` from `endMs`, `durationMs` from `endMs − t0` (rounded, below), the run's cost, and `videoPath`/`tracePath` when close succeeded. Fold with `runResultFromEvents`, write `<runsDir>/<runId>/result.json` (two-space JSON and a final newline), return the result. Once `runStarted` is out, `runActor` rejects only when the fold or the write fails, a bug, or when `onEvent` throws on the terminal event (below).

**Failures.** Any throw inside the `try` ends the run with `runFailed`: `run_start_failed` from `openRunContext` (no steps, no paths), `off_http_page`, `page_not_settled`, `font_failed`, `invalid_measurement`, Playwright errors, an `LlmError` (its `cost` joins the run's), a plain `Error` from a fake, an `onEvent` that throws on any event before the terminal one. `error` is `<code>: <message>` for a `WayfordError`, `<name>: <message>` otherwise, the whole message on one line through `oneLine` (build, from the simplify pass: zod's issue list and the adapter's schema miss put their reason after the first line), and `<code or name>: no message` when it is empty (build: `runFailed.error` must not be empty), at most 500 characters; the full error and stack go to the log. `durationMs` is `Math.round(Math.max(0, endMs − t0))`. The step in progress stays as far as its events went. If `close` rejects, the terminal event is `runFailed` with no paths: `run_close_failed: the run ended <outcome>, then saving its recording failed: <reason>`, or, when the run was already failing, its first error with `; saving the recording failed too` appended.

**Events.** Built, passed through `RunEvent.parse` (a failure is a bug and fails the run), appended to the run's own list, then given to `onEvent` synchronously, in order, never awaited. (PR review) An `onEvent` that throws before the terminal event ends the run like any other throw, `runFailed` with its own error, and still gets the terminal event. The terminal event is given to `onEvent` last, once `result.json` is written, and in a `finally`, so a failed write still delivers it; a listener that throws on it makes `runActor` reject with its error and leaves the record on disk: never swallowed into a log line (`docs/CONVENTIONS.md`, "Errors"). Timestamps are `new Date(Date.now()).toISOString()` at emission, `runStarted`'s is `t0` and the terminal event's `endMs`; nothing decides on them.

**Files.** Everything goes under `<runsDir>/<runId>/`: s2-02's `<label>-seed<seed>-<runId>.webm`, `.trace.zip` and `-step-<n>.png`, plus `result.json`. Stored paths (`screenshotPath`, `videoPath`, `tracePath`) are relative to the run's own directory, with `/` separators, so a run folder can move as a whole. s4-03 resolves them against `<runsDir>/<runId>`. Core's fixtures write `runs/run_vera-hard-1/step-0.png`; that form needs the repository root, which `runActor` does not know (decision log).

**Cost.** A step's cost is the sum of its answers' costs (each with the adapter's repairs and retries); the run's adds the `cost` of every `LlmError`. The sum is a four-line local function in `actor-loop.ts`: `llm.ts` keeps its private `addCost`, and the public barrel stays as it is.

### `actor-backend.ts`: the seam

```ts
export interface ActorTurn {
  goal: string;
  observationText: string;       // renderObservationForModel(observation)
  history: string;               // renderHistory(steps)
  retry?: { refused: ActorResponse; ref: ElementRef };
}
export interface ActorAnswer { response: ActorResponse; cost: Cost }
export interface ActorBackend {
  readonly modelId: string;      // modelIds.actor, known before the first call
  answer(turn: ActorTurn): Promise<ActorAnswer>;
}
export type ActorBackendFactory = (run: { logger: Logger }) => ActorBackend;

export function actorTurn(goal: string, observation: Observation, history: readonly HistoryStep[]): ActorTurn;
```

The factory runs once per run, after the run id exists, so the backend's `Llm` gets the run's child logger (`LlmDeps`). (PR review) The turn carries no `Observation`: it also holds each box's size and unrounded position, which the text does not show, and ADR 0001 gives Jev the LLM's input and nothing more. s2-06 adds what its options need, with its first reader. `actorTurn` takes no profile: the persona reaches a backend only through the observation (and, from `s2-10`, M1). The ref check and the retry live in the loop, so every backend obeys "one retry, then wasted"; a backend only phrases the retry.

### `llm-actor.ts` and `packages/agent/prompts/`

```ts
export function llmActor(options: { settings: LlmSettings; llm?: (logger: Logger) => Llm }): ActorBackendFactory;
export function actorMessages(turn: ActorTurn): ChatMessage[];
```

`modelId` is `settings.roles.actor.model`; `llm` defaults to `(logger) => createLlm(settings, { logger })`. Each answer is `complete({ role: "actor", messages: actorMessages(turn), schema: ActorResponse })`, sending no seed (`s2-10`), and returns `{ response: value, cost }`. Messages: `[system, user]`; with `retry`, `[system, user, assistant: JSON.stringify(refused), user: retry text]`. The three files are read once at module load and trimmed. Placeholders are filled in one pass of `/\{\{(\w+)\}\}/g`, and an unknown name throws, so page text that spells `{{history}}` is never expanded.

`actor-system.md`, the constant system message (`{{maxWaitMs}}` from core's `MAX_WAIT_MS`):

```
You are using a website in a web browser to get one thing done.

Each turn you get your goal, what you have done so far, and the page you are on now. The page is listed one element per line: a ref in square brackets, the element role, its name in quotes, and where it starts on the screen, as x,y in pixels from the top left corner. A line that ends with "partly legible" is an element you can only partly read, so its name may be missing letters. The last lines may say how many more elements are not listed, or how many more are further down the page.

Refs belong to the page you are on now, and every page gives them out again. Use only a ref from the page you are on now.

Answer with one JSON object with two fields:
- "narration": one or two short sentences in your own words: what you see and why you act.
- "action": exactly one of these:
  - {"type": "click", "ref": "e1"} to click an element
  - {"type": "type", "ref": "e1", "text": "..."} to click a text field and type the text into it
  - {"type": "scroll", "direction": "down"} or {"type": "scroll", "direction": "up"} to move the page
  - {"type": "back"} to go back to the page before
  - {"type": "wait", "ms": 1000} to wait, for at most {{maxWaitMs}} ms
  - {"type": "giveUp"} to stop, when you think you cannot get it done here
```

`actor-turn.md`:

```
Your goal: {{goal}}

What you have done so far:
{{history}}

The page you are on now:
{{page}}
```

`actor-retry.md`:

```
There is no [{{ref}}] on the page you are on now. Answer again with a ref from that page, or with an action that needs no ref.
```

`doubleClick` is not offered: double clicks are B1's to produce (`s2-10`). Strict `json_schema` still lists it, so a model may propose one; it is then performed as proposed, with `dice: []`. No example element name appears: any name could collide with a fixture's hidden element. All of this text, the history lines and the adapter's repair text were checked against the 20 banned substrings: no hit (it avoids "several", "overall", "personal", "readable", "metadata", "revision", "insight", "ruler", "hidden").

### `history.ts`: the one history renderer

```ts
export type HistoryStep =
  | { observation: Observation; proposed: Action }
  | { observation: Observation; wasted: true };
export function renderHistory(steps: readonly HistoryStep[]): string;
```

A step holds the Actor-facing `Observation` it showed, never the `FullObservation`, so the renderer cannot reach an evidence name: the task's rule is a type fact. Output: `Nothing yet.` for no steps; otherwise one line per step, oldest first, `- On <url>: you <move>.` with the PROPOSED action, so `s2-10`'s B1 never shows as "you double-clicked". The target is named by its role and the name shown at that step (masked or renamed), looked up by the proposed ref, never by the ref itself: refs are renumbered per page, and the fixture's wasted step reuses a stale `e3`. Moves: `clicked <role> "<name>"`, `double-clicked …` (model-proposed only), `typed "<text>" into <role> "<name>"`, `scrolled down`/`up`, `went back`, `waited <ms> ms`. A wasted step: `- On <url>: you pointed at something that was not on that page, so nothing happened.` No narration, no step numbers. Page strings and typed text go through the same control-character rule as core's `oneLine`, and names are JSON-quoted as `renderObservationForModel` quotes them.

### `act.ts`: acting

`actionPoint(box, viewport)`: the centre of the box clipped to `[0, width) × [0, height)`, unrounded; when the clip is empty, the box centre clamped into the viewport. The box is the one the persona saw at this step; the element is never re-located by role or name.

`performAction(run, action, shown)` puts the input in and returns an `Arrival` (PR review); the run context keeps the point an action pressed (its cursor's), and `RunContext.restorePointer()` puts the real pointer back there (build, from the simplify pass: one owner of that point):

- `click`, `doubleClick` and `type` first `await run.moveCursor(point)` (s2-02's 250 ms hold), then `page.mouse.click` or `page.mouse.dblclick` at the point; `type` clicks, then `page.keyboard.type(oneLine(text))` (no clearing, no Enter: PR review, a line break typed as is pressed Enter and submitted the form, while the history told the model it typed a space).
- `scroll`: `window.scrollBy({ top: ±Math.round(0.8 × innerHeight), behavior: "instant" })`, passed to `page.evaluate` as is: it nests no function, so `tsx`'s `keepNames` leaves it alone. No cursor, no wheel.
- `back`: `page.goBack({ waitUntil: "commit", timeout: 0 })` (PR review: by default it waits for `load` on Playwright's own timeout, outside the `Arrival`; up to the commit, the `Arrival` waits for `load` and `within` bounds the rest). Not `history.back()` in the page: its navigation can destroy the evaluate's context before the answer comes back, which failed CI and 3 runs in 60 under load on Linux. It returns `null` at the start page, and nothing happens. `wait`: `page.waitForTimeout(ms)`. `giveUp`: nothing.
- (PR review) The input itself races a Node timer of `ACTION_TIMEOUT_MS = 30_000`: the mouse and every evaluate wait as long as the page's main thread is busy. A page that does not take it throws `page_not_settled`, with no `actionPerformed`, since nobody knows whether it landed.

Every action but `giveUp` runs inside a navigation watch, armed before the input: a page `request` listener (navigation requests of the main frame) and a main-frame `framenavigated` listener. The loop calls `arrival.wait()` inside `land`'s `try`, so a page that never arrives still records where the action landed (PR review: the load wait had sat in `performAction`, and a page that never fired `load` lost its `actionPerformed`). When neither listener fired, wait `NAVIGATION_QUIET_MS = 100` on a Node timer; none means no navigation. Otherwise wait up to `ACTION_TIMEOUT_MS` for the commit, then up to as long again for `load` (`waitForLoadState("load", { timeout: 0 })` raced with a Node timer); either expiry throws `page_not_settled`. (build, from the simplify pass) A navigation request that fails (a `requestfailed` listener) with no commit within the quiet window after it is taken as none at once: a `mailto:` or `tel:` link, a download or a 204 fails its request within about 20 ms and never commits, while a network error's own error page commits about 25 ms after its failure. (PR review) A navigation still pending at the deadline is not taken as none: it was logged so, and then the next call into the page waited for its commit with no bound. Never `waitForLoadState` straight after `mouse.click`, and never a Playwright wait expected to time out: `trace.zip` records each expiry as a failed action.

### `settle.ts`

`settle(page, timeoutMs = SETTLE_TIMEOUT_MS)`, `SETTLE_TIMEOUT_MS = 3000`: one `page.evaluate` of a source string carrying the `__name` shim, as `cursor.ts` does. In the page: (build) when `document.readyState` is not `complete`, wait for `load` against the deadline (a script navigation's new document can answer while it still loads); race `document.fonts.ready` with the deadline; then loop over `document.getAnimations()` entries whose `playState` is `"running"`. None running: if a `FontFace` has status `"error"`, fail with `font_failed` naming the families; otherwise settled. Else `Promise.allSettled(running.map((a) => a.finished))` raced with the deadline, one `requestAnimationFrame`, and check again. At the deadline, `page_not_settled` names what still runs, an animation that never ends included, or says the page or its fonts are still loading. The page writes the reason itself and returns `null` or `{ code, why }` (PR review: a six-kind union and a switch in Node only formatted it, and an early exit for an endless animation only made a failing run fail 3 s sooner).

`retryOnNavigation(page, attempt)`: when Playwright reports a destroyed execution context or a detached frame, wait for `document.readyState === 'complete'` with `page.waitForFunction` and try again, three attempts in all. (build, from the simplify pass) It also notes the document, `performance.timeOrigin`, before and after each attempt: a new document that commits between `settle` and `collect` throws nothing, so a changed origin counts as a navigation too, and a third attempt that still sees one throws `page_not_settled`. Every measurement then comes from one document, settled before it was read. (build) Not `waitForLoadState("load")`: the destroyed context's error can reach Node before Playwright has seen the navigation, and `waitForLoadState` then answers at once from the old document, so the retry ran on the old page again (measured during the build); `waitForFunction` polls in the page and follows it to the new document. It wraps observe and the post-action capture, so a script navigation later than the quiet window is measured on the new page instead of crashing the run. (PR review) Each attempt, the wait before it and both notes included, races a Node timer of `SETTLE_TIMEOUT_MS + 5000` and throws `page_not_settled` when it runs out: every call into a page whose main thread never yields waits, and so does one into a page whose navigation has not committed. The bound had sat around the settle alone, and the first note of the document waited with none.

### `success.ts` and `url-glob.ts`

`url-glob.ts`: `globToRegExp(glob)`, our implementation of Playwright 1.63's documented glob dialect: `*` is `[^/]*`, `**` is `.*`, `**/` and `/**/` stand for whole segments, `{a,b}` alternates, `?` and `[ ]` are literal, a backslash escapes, and nested or unmatched braces throw. It matches the whole URL string, case-sensitively.

`checkSuccessCondition(condition)` (run after `runStarted` and before `openRunContext`, build): a `urlMatches` or `requestObserved` pattern must compile and start with `*` or with `http://`/`https://`, since our contexts set no `baseURL` and a relative pattern could never match; else `WayfordError` `invalid_success_condition`, saying to write it as `**/…`, and the run ends `runFailed`.

`watchSuccess(context, condition)` returns `{ met(page, urlAfter): Promise<boolean> }`:

- `urlMatches`: the compiled glob tested on `urlAfter`, the URL the step stores, so success can be re-derived from the record.
- `selectorPresent`: `document.querySelector(selector) !== null` in the page (plain CSS over the top document; `page.locator` would accept other engines and pierce shadow roots). An invalid selector throws and ends the run.
- `requestObserved`: one `context.on("request")` listener, armed after the start page has loaded, counts a request whose method equals the condition's and whose full URL the glob accepts. Redirect hops count. (PR review) So does a request a page sends by itself after that, a poll or a lazy fetch, even before the first action: the pattern must name a request that only an action sends.

### `run-one.ts`: the CLI

`pnpm --filter @wayford/agent run:one -- --persona prof_ada --task task_next-parcel --seed 1`. It drops the one leading `--` pnpm forwards, then `node:util` `parseArgs` (strict): `--persona` and `--task` are fixture ids, `--seed` a `Seed`. It loads the root `.env` with `process.loadEnvFile` when present, as `smoke-llm.ts` does, then `parseLlmSettings`. It serves a fresh production build with `serveTargetApp({ port: 5174 })`, so the observation's `URL:` line, the prompt and the recorded `startUrl` read the fixtures' origin in every run (a taken port fails with "stop pnpm dev or the target-app preview"), launches Chromium (with smoke-run's install hint), and calls `runActor` with `TARGET_APP_DEFAULTS`, the task fixture unchanged, `runsDir` = the repository's `runs/` (found from the file's own URL) and `llmActor({ settings })`. Logs go to stderr. Stdout: a header (run id, persona, task, seed, start URL, model), one line per event as it arrives (observed URL and shown count, narration, the action and its cost, the landed URL, wasted refs), then outcome, steps, duration, tokens, USD and the absolute paths of `result.json`, the webm and the trace. Exit 0 when the run finished, whatever the outcome; 1 for `runFailed` or a failed setup; 2 for usage.

### Hand-off to `s2-10`

A `memorySteps` parameter on `renderHistory` with a count line that names nothing it dropped; B1 between the accepted answer and `actionPlanned` (step 3); an injectable `now()` replacing `Date.now()` for the timestamps and B3, checked at the top of a step and right after `actionPlanned`; the provider seed computed in `llm-actor.ts` from a `seed` added to the factory's input, and `sampling` on `ActorBackend`, copied to `runStarted.actorSampling`.
