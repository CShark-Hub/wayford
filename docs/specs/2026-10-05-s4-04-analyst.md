# s4-04 — Analyst and the report API: spec

Task: `tasks/s4-04-analyst.md` · Branch: `feature/s4-04-analyst` · Date: 2026-10-05
Status: approved 2026-10-05

## Goal

`POST /reports/:taskId` reads one run set's worth of a task's stored runs, the latest per persona and seed on one backend, across every persona, and stores a `Report`. The per-persona numbers and the `deterministic` findings are built in code. One `analyst` call writes a recommendation for each of those findings and up to five `hypothesis` findings, which code checks before storing. `GET /reports/:taskId` returns the stored report.

## Constraints that bind

- "Code decides what is true; the model only words it" (task). The numbers and the `deterministic` findings are code's: one per persona and closed route, giving where it closed, the rules, and the measured value against the threshold. The model writes recommendations and up to five hypotheses.
- "Every finding cites a stored step, and evidence is checked in code." A finding whose evidence names a run or step that does not exist is dropped and logged (F8 AC2).
- "Provenance comes from the profiles … The model names rule ids only" (F8 AC5).
- "The Analyst sees all runs of all personas for the task at once, in one call on the `analyst` role" (F8 AC4). The digest is built in code: per run, the persona and the outcome; per step, the page, the action and the narration. A Jev run has no narration, and the digest says so.
- "Scout is context, not a verdict." When Scout did not reach the goal, the report says so first.
- "The model writes into fields, never prose for the page" (A9). Structured output, validated with the core schemas.
- One run per persona and seed, on one backend (A22). Older runs of a seed, runs on the other backend and sweep runs are left out, and the report counts each.
- "A closed route with no run on its page is no finding." Such a closure is listed by name instead.
- The route-open number is `routeOpenSeeds` (s1-06), for the hard goal only. Any other goal has `null`, which a screen reads as "—" (F8 AC6).
- `AGENTS.md`: the Actor never reads Scout's output. Here the Analyst reads it, which is allowed. Jev's confidence stays out (ADR 0001, decision 6; task, Out of scope).
- No test calls a real LLM (`docs/CONVENTIONS.md`). No new dependency. Import rules as in `docs/STACK.md`: io imports core, filter and agent.
- Out of scope: the report screen (`s3-08`), findings across tasks, report history, Jev's confidence.

## Design

### Data flow

```
POST /reports/:taskId { backend? }          analyse -- --task <id> [--backend]
            └──────────────┬──────────────────────────┘
                     analyseAndStore(deps, taskId, backend)          io/analyst.ts
   TaskId.parse · loadTask(db) ?? taskFixtures.find · listRuns(db, {taskId}) · readGroundTruth
                           │
             selectRuns(runs, backend, jevModel)                     io/analyst-runs.ts
             → chosen runs, leftOut { olderRuns, otherBackend, sweepRuns }
                           │
   per persona: facts(taskId, profile, seeds) → { open, closings } | undefined
                (injected; the walk and filter's ./routes live in io/analyst-routes.ts)
             personaResults(...)                                     io/analyst-runs.ts
             closureFindings(...) → drafts + unevidencedClosures     io/analyst-closures.ts
                           │
             analystCase(...) → one user message: goal, Scout, numbers, drafts, digest
                                                                     io/analyst-digest.ts
             llm.complete({ role: "analyst", schema: answerFor(drafts) })   one call
                           │
             assemble: recommendations onto drafts; hypotheses checked
             (evidence, rules, provenance, personas) → Report.parse   io/analyst.ts
                           │
                     saveReport(db, report)                          io/db/reports.ts
```

### Core: `packages/core/src/report.ts`

```ts
/** Agent's `ActorBackendName`, spelt here: core imports nothing from the workspace. */
export const ReportBackend = z.enum(["llm", "jev"]);

/** Scout's line (`GroundTruth`): reached in N steps, not reached in N attempts, or no file. */
export const ScoutLine = z.discriminatedUnion("status", [
  z.object({ status: z.literal("reached"), steps: z.number().int().positive(),
             modelId: z.string().min(1), recordedAt: z.iso.datetime() }).strict(),
  z.object({ status: z.literal("notReached"), attempts: z.number().int().positive(),
             modelId: z.string().min(1), recordedAt: z.iso.datetime() }).strict(),
  z.object({ status: z.literal("noGroundTruth") }).strict(),
]);

/** One seed of a persona's run set: the run the report read, how it ended, the routes left open. */
export const ReportSeed = z.object({
  seed: Seed, runId: RunId, outcome: RunOutcome,
  /** Route ids the filter left open in this seed, in walk order; null without a route table. */
  openRoutes: z.array(z.string().min(1)).nullable(),
}).strict();

/** One persona's two numbers and the runs behind them. */
export const PersonaResult = z.object({
  profileId: ProfileId,
  runs: z.number().int().positive(),
  errors: z.number().int().nonnegative(),
  successes: z.number().int().nonnegative(),
  /** Seeds whose filtered observations left at least one route open; null without a route table. */
  routeOpenSeeds: z.number().int().nonnegative().nullable(),
  /** Median `durationMs` over the successful runs; null without a success. */
  medianSuccessMs: z.number().nonnegative().nullable(),
  /** One per seed, by seed. */
  seeds: z.array(ReportSeed).min(1),
}).strict().superRefine(/* counts and nulls agree with `seeds`; seeds unique */);

/** A route the filter closed that no step of the persona's runs shows: listed, not a finding. */
export const UnevidencedClosure = z.object({
  profileId: ProfileId, routeId: z.string().min(1),
  page: z.string().startsWith("/"), role: AriaRole, name: z.string(),
  rules: z.array(RuleId).min(1),
  /** In how many of the persona's seeds the route closed there. */
  seeds: z.number().int().positive(),
}).strict();

export const Report = z.object({
  taskId: TaskId,
  backend: ReportBackend,
  /** When the Analyst ran. A timestamp only. */
  analysedAt: z.iso.datetime(),
  /** The `analyst` role's configured model. */
  analystModelId: z.string().min(1),
  runCount: z.number().int().positive(),
  cost: z.object({ runs: Cost, analyst: Cost }).strict(),
  scout: ScoutLine,
  personas: z.array(PersonaResult).min(1),
  findings: z.array(Finding),
  leftOut: z.object({ olderRuns: N, otherBackend: N, sweepRuns: N }).strict(),
  unevidencedClosures: z.array(UnevidencedClosure),
}).strict().superRefine(/* below */);
```

`Report`'s refine checks what one document can check:
- `runCount` is the sum of the personas' `runs`, and the profile ids are unique;
- every finding is about `taskId`;
- every evidence ref names a run in the personas' `seeds`;
- every finding's `personaIds`, and every closure's `profileId`, is a persona of the report.

Whether a step exists can't be checked here, because the report holds no steps. `analyst.ts` checks it against the stored runs. One line goes in the barrel, `export * from "./report.js";`, after `random`.

Fixture: `fixtures/reports.json`, read as `reportFixtures: Report[]`, with `reportFixture(taskId)`. It holds two reports:
- `task_past-order` on Jev, with Ada, Kai and Vera on seeds 1 to 3, shaped like the real route table (RULES):
  - Vera's P1 on "Order archive" (`wcag22`) and Kai's A1 on it (`folk`, so soft) are its `deterministic` findings;
  - it also has one `measurement` and one `hypothesis`;
  - Vera's P4 closures of routes B and C are its unevidenced closures;
  - Scout reached the goal in 2 steps.
- `task_next-parcel`, with no route table (every `routeOpenSeeds` is `null`), no ground truth, and one hypothesis.

### Filter: `routeClosings`, `packages/filter/src/route-table.ts`

```ts
/** Where one route closed in one seed: its first cut step, and what cut it. */
export interface RouteClosed {
  seed: Seed;
  routeId: string;
  page: string;
  role: AriaRole;
  name: string;
  /** The cut element's decisions whose own state is `invisible`, in pipeline order. */
  decisions: ElementDecision[];
}

/** Per seed, in the order of `seeds`, every route of `walked` the filter closed for `profile`. */
export function routeClosings(
  walked: readonly WalkedRoute[], profile: PerceiveProfile,
  seeds: readonly Seed[], options?: PerceiveOptions,
): RouteClosed[];
```

The function reads `closingStep` and `routeInSeed`, the same rule `routeOpenSeeds` reads. So a route is in `routeClosings` for a seed exactly when it is missing from that seed's `open`. `StepResult` gains the decisions behind its `rules`, and `judge` returns them. `routeSummary` and `routeOpenSeeds` don't change.

One more pure export: `hasRouteTable(taskId): boolean`, the check `routesFor` already makes first, which `routesFor` now calls. It lets io skip the walk for a goal with no route table.

`routes.ts` re-exports `routeClosings`, `RouteClosed` and `hasRouteTable`.

### io: choosing the runs, `analyst-runs.ts`

```ts
/**
 * The backend a stored run ran on: Jev when `modelIds.actor` is Jev's model (ADR 0001, decision
 * 1) or a step carries a `decision`, so a run from before a pinned-version bump still reads as Jev.
 */
export function backendOf(run: RunResult, jevModel: string): ReportBackend;

/** The latest run per persona and seed on `backend` that is no sweep run, and what was left out. */
export function selectRuns(runs: readonly RunResult[], backend: ReportBackend, jevModel: string):
  { chosen: RunResult[]; leftOut: Report["leftOut"] };

/** The chosen runs by persona, in `profileFixtures` order, each by seed; throws `unknown_profile`
 *  for a run of an unbundled profile. (simplify) */
export function byPersona(chosen: readonly RunResult[]): PersonaRuns[];

/** One `PersonaResult` per group; a persona absent from `facts` has no route table. */
export function personaResults(groups: readonly PersonaRuns[],
  facts: ReadonlyMap<ProfileId, RouteFactsOf>): PersonaResult[];
```

- `listRuns` returns runs newest first, so the first run met per persona and seed is the latest. Sweep runs are counted first, then runs on the other backend, then older runs of a seed already chosen.
- The median follows web's `stats.ts`: over the successful runs' `durationMs`, the mean of the two middle values for an even count.

### io: deterministic findings, `analyst-closures.ts`

```ts
/** A deterministic finding before the Analyst writes its recommendation. */
export interface Draft { key: string; finding: Omit<Finding, "recommendation">; closing: RouteClosed }

export function closureFindings(input: {
  taskId: TaskId; profile: Profile; runs: readonly RunResult[];  // the persona's chosen runs
  closings: readonly RouteClosed[]; seeds: number; scout: ScoutLine;
}): { drafts: Omit<Draft, "key">[]; unevidenced: UnevidencedClosure[] };

/** The provenance of `rule` for `profile`: copied from its threshold, or `folk`. */
export function provenanceOf(rule: RuleId, profile: Profile): ProvenanceId | undefined;
```

- **Grouping.** Closings group by route and closing step (page, role, name). Each group is one finding about that persona, with `seeds` counting the seeds it closed in.
- **Evidence.** A step counts when all of these hold:
  - the step is in one of the persona's chosen runs;
  - the `urlBefore` pathname is the group's page;
  - its `fullObservation` holds an element with the group's role and name;
  - every such element is `invisible`;
  - one of them carries a decision of the group's rules.

  No evidence means no finding: the group becomes an `UnevidencedClosure`.
- **Title.** Written in code: `The link "Order archive" on /deliveries is cut by P1 for Vera in 7 of 10 seeds`.
- **Rules.** The union of the rules of the group's seeds, in pipeline order, as `routeCell` merges them.
- **Detail.** Written in code. It names the route, then one clause per rule, read from the first seed whose decisions carry it:
  - P1 to P4: the metric, the measured value truncated as the filter truncates it, and the decision's threshold, plus the band floor from the profile's softness when soft;
  - A1 and A3: the cap;
  - V2: the side.

  When Scout did not reach the goal, the detail ends: "Scout, with full vision, did not reach the goal either: this may be the feature, not the persona."
- **Basis.** One entry per rule, with `provenanceOf`:
  - P1 and P2 copy `perception.contrast.provenance`, P3 copies `fontPx`'s, and P4 copies `targetPx`'s;
  - A1, A3, K1, K2, K4 and V2 give `folk`;
  - a perception rule whose threshold the profile does not set gives `undefined`, and the entry is dropped.
- **Persona.** `personaIds` is `[profile.id]`. The finding id comes from `newId("finding")`.

### io: the case the Analyst reads, `analyst-digest.ts`

```ts
export function analystCase(input: {
  task: Task; scout: ScoutLine; personas: readonly PersonaResult[];
  drafts: readonly Draft[]; runs: readonly RunResult[];
  backend: ReportBackend;   // (simplify) every chosen run is on it, so no per-run guess
}): string;
```

Persona labels and Scout's line come from `analyst-text.ts`, so the case and the printed report share one wording. What the Actor read is looked up in `toActorObservation(step.fullObservation)`.

The message has five sections: the goal, Scout's line, the per-persona numbers, the findings to recommend for, and the runs. Scout's line reads "reached the goal in N steps: the feature works", "did not reach the goal in N attempts", or "no ground truth".
- **Findings.** Each draft as `key`, persona, title and detail.
- **Runs.** A header per run: id, persona label and id, seed, outcome, steps, seconds. A Jev run's header adds "Jev run: no narration".
- **Steps.** One line per step: index, path, then the performed action with the element's name. Two variants:
  - when the Actor read the name masked or renamed, the line gives both names, the real one first;
  - a wasted step reads "no action: every answer named an element not on the page".

  The narration follows, quoted, when there is one.
- **Left out.** Jev's probabilities and confidence (ADR 0001, decision 6).

### io: the call and the assembly, `analyst.ts`

```ts
/** What the route table says for one persona over its seeds. */
export interface RouteFactsOf { open: RouteOpenSeed[]; closings: RouteClosed[] }

/** The route facts of a persona on a task; undefined for a task with no route table. */
export type RouteFacts = (taskId: TaskId, profile: Profile, seeds: readonly Seed[]) =>
  Promise<RouteFactsOf | undefined>;

export interface AnalystDeps {
  db: Db; llm: Llm; routes: RouteFacts;
  groundTruthDir: string; jevModel: string; logger: Logger;
}

export type Analysis = { ok: true; report: Report } | { ok: false; error: string };

/** Read, analyse, store. `ok: false` for an unknown task or no runs on the backend. */
export function analyseAndStore(deps: AnalystDeps, taskId: TaskId, backend: ReportBackend):
  Promise<Analysis>;

/** The analysis alone, over runs already chosen. Not exported (simplify): only
 *  `analyseAndStore` calls it. */
function analyseTask(input: {...}): Promise<Report>;

/**
 * `GroundTruth` from `<dir>/<taskId>.json`; undefined when there is no file. A file that fails
 * `GroundTruth` throws `WayfordError("invalid_ground_truth")`, the `ZodError` on `cause`.
 */
export function readGroundTruth(dir: string, taskId: TaskId): Promise<GroundTruth | undefined>;

export const ANALYST_PROMPT_FILE: string;   // analyst-prompt.md, read once at load
```

`RouteOpenSeed` and `RouteClosed` are imported as types only from `@wayford/filter/routes`, so `analyst.ts`, and the barrel through `app.ts`, load neither Playwright nor Vite. The functions behind them run in `analyst-routes.ts` (below).

- **The answer schema** is built per call, so it has one required key per draft:

  ```ts
  z.object({
    recommendations: z.object({ d1: z.string(), d2: z.string(), … }).strict(),
    hypotheses: z.array(z.object({
      title: z.string(), detail: z.string(), recommendation: z.string(),
      evidence: z.array(z.object({ runId: z.string(), stepIndex: z.number().int() }).strict()),
      rules: z.array(z.string()),
    }).strict()),
  }).strict()
  ```

  Types and `required` only, as `ExtractorAnswer` has, so every strict `json_schema` mode accepts it. The adapter's repair round brings a missing key back.
- **Recommendations.** Each draft takes its recommendation. A blank one gets a fallback built from the closing rule, such as "Raise its contrast to at least 3:1 against its background.", and is logged.
- **Hypotheses.** Taken in order, at most five; any beyond that are logged.
  - Its evidence must name runs the report read and steps those runs have. Otherwise the finding is dropped and logged.
  - `personaIds` are the profiles of the runs it cites.
  - Its basis comes from `RuleId.safeParse` on each rule. Each cited persona with a provenance (`provenanceOf`) gives one entry, and duplicates are removed. A rule that is unknown, or that no cited persona gives a provenance for, is dropped and logged.
  - Then `Finding.safeParse`. A failure, such as a blank title, drops the finding and logs it.
- **Order.** Findings are ordered: `deterministic` by persona order, then `hypothesis` in the model's order. `measurement` findings come with s4-06, which widens `Draft` to take them.
- **The report.** `Report.parse` over the whole document. `cost.runs` is the sum over the chosen runs, and `cost.analyst` is the call's `cost`.
- **The task.** Read from the database (`loadTask`), else from `taskFixtures.find`. Neither: `ok: false` (404). The ground-truth file is read only once the task is found, so only a valid, known `TaskId` reaches a file path.
- **No runs.** No chosen run: `ok: false` (404). The error names the runs on the other backend: "no runs of task_x on jev; 12 on llm".
- **Unknown persona.** A chosen run whose profile is not bundled throws `WayfordError("unknown_profile")`.

### io: the prompt, `analyst-prompt.md`

- **The setup.** The prompt tells the model it reads a set of recorded runs of software agents on one goal in a web application. It receives the goal, a full-access baseline run's result, the per-persona numbers, the findings computed from the page, and every run.
- **The task.**
  - Write one recommendation per listed finding, keyed by its id. Each says what to change in the interface, concretely, in one or two sentences.
  - Write at most five hypotheses read from the actions and narration. Each has a title, a detail, a recommendation, and evidence citing run id and step index exactly as written in the digest. It may name the ids of rules from the listed findings it rests on.
- **The cautions.**
  - Narration is the agent's account after the fact, and some runs have none.
  - Recommend changes to the page, never to the people.
  - Make no claim about real people, and invent no number.
  - When the baseline did not reach the goal, read every finding against that first.
- **The answer.** One JSON object of the given shape and nothing else.

It names no persona label and no trait or impairment word, and a test checks that.

### io: storage, routes, CLI

- `db/schema.ts`: `reports`, with `task_id` text primary key and `document` JSON `Report`. Nothing filters or sorts reports, so no other column. `db/reports.ts`: `saveReport(db, report)` upserts on `task_id` (`onConflictDoUpdate`), and `loadReport(db, taskId)` returns the report or `undefined`. Both go through `parseRow` with `Report`. The migration is `drizzle/0003_*.sql`, generated by `db:generate`.
- `routes/reports.ts`:
  - `POST /:taskId` takes the body `{ backend?: "llm" | "jev" }`, strict, with `jev` the default. It answers:
    - 201 with the `Report`;
    - 400 for a `:taskId` that is not a `TaskId`, or a bad body;
    - 404 `{ error }` for an unknown task or no runs;
    - 502 `{ error }` when the Analyst call fails (an `LlmError`), in which case nothing is stored.

    An invalid ground-truth file is bad stored data, like an `invalid_row`. It reaches `onError`, which logs it and answers 500.
  - `GET /:taskId` answers 200 with the `Report`, 400 for a bad `:taskId`, or 404.
  - The route's backend enum is `z.enum({ llm: "llm", jev: "jev" } satisfies Record<ActorBackendName, ReportBackend>)`, as `routes/runs.ts` spells its own.
- `app.ts`: `AppOptions` gains `routes: RouteFacts`, `groundTruthDir: string` and `jevModel: string`. It mounts `/reports` with `options.llm` (one `Llm` serves every role), `options.db` and `options.logger`.
- `analyst-routes.ts` stays out of the barrel, since it loads Playwright and Vite through `@wayford/filter/routes`. It has two functions:
  - `routeFactsFrom(walks, jargon): RouteFacts` is pure over a walk already taken: `routesFor`, then `routeOpenSeeds` and `routeClosings` with the jargon. The browser test builds its facts this way from its own walk.
  - `routeFacts({ devices, jargon }): RouteFacts` answers `undefined` at once when `!hasRouteTable(taskId)`. Otherwise it walks the target app once per process, on every device given, and keeps the promise. A failed walk is dropped, so the next call walks again. It then answers through `routeFactsFrom`.
- `server.ts` passes three new options:
  - `routes: routeFacts({ devices: profileFixtures.map((p) => p.device), jargon: targetAppJargon })`;
  - `groundTruthDir: join(RUNS_DIR, "ground-truth")`;
  - `jevModel: settings.jevModel`.
- `analyse.ts`: `pnpm --filter @wayford/io analyse -- --task <id> [--backend jev|llm]`. It checks `--task` with `TaskId`, reads `.env` and migrates the database. It builds the `Llm` and `walkedRoutes`, calls `analyseAndStore`, prints `reportText(report)` with the Analyst's cost, and exits 1 with the error on `ok: false`. It skips the `--` pnpm forwards, as `calibrate` does. The script is `"analyse": "tsx src/analyse.ts"`.
- `analyst-text.ts`: `reportText(report)` prints the report as plain text, in this order:
  - the header: task, backend, when analysed, runs and costs;
  - Scout's line, worded as in the case above ("… the feature works" when it reached the goal);
  - one row per persona: runs, got through, route open, median;
  - the findings by type, each with its rules and provenance, `soft` when `isHardFinding` rejects it, its evidence refs and its recommendation;
  - the left-out counts and the unevidenced closures.
- `test-app.ts`: the `testApp` defaults gain `routes: async () => undefined`, `groundTruthDir: <store>/ground-truth` (absent, so no ground truth) and `jevModel: "fake-jev"`.
- `index.ts`: one line, `export * from "./db/reports.js";`.
