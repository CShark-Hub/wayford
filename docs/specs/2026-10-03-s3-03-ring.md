# s3-03 — Ring: several personas on one task, live: spec

Task: `tasks/s3-03-ring.md` · Branch: `feature/s3-03-ring` · Date: 2026-10-03
Status: approved 2026-10-03

## Goal

An arena screen takes a goal in one sentence and three to five personas, starts the runs, and shows them side by side with avatars whose state follows their run events, so the demo shows who gets across and who does not.

## Constraints that bind

- **F6.** "3 to 5 runs start in parallel" (AC1); "Avatar state follows run events: idle, moving, stuck, done, gave up, error. A crashed run (`runFailed`) shows error, never gave up" (AC2); "Finish order and elapsed time are visible" (AC3); "Every persona shows its latest step screenshot. No live video" (AC4). **F3 AC1**: the Extractor "rewrites tasks containing path words … and shows the rewrite".
- **Task constraints.** The preset supplies `startUrl` and `success`, "which never come from the model or the sentence"; the sentence stays editable and goes through `POST /tasks` with `story`, `startUrl`, `success`; the rewrite and stripped words show before the start. "One `EventSource` per run, at most five runs … A comment in the code says so." Avatar state is "a pure function of the events seen so far … N stated in the code … Tested without a browser." "Finish order and elapsed time come from event timestamps, never the local clock." Each tile shows its latest step screenshot and "the latest narration line under a 'narration' label"; a Jev run's line stays empty. "No motion: each avatar state is a static variant of the avatar from s3-02." "Every control has an accessible name."
- **Built against what merged, not stubs** (`tasks/BOARD.md`, week 3): io's `POST /tasks` (`packages/io/src/routes/tasks.ts`: 201 `{ task, rewritten }`, 422 `{ error, goal, survived }`, 400/415/502 `{ error }`), `POST /runs` (`routes/runs.ts`: body `{ taskId, profileIds, seeds }`, 202 `{ runs: StartedRun[] }`, `StartedRun = { id, profileId, seed }`), `GET /runs/:id/events` (SSE, `event:` the type, `id:` the index), `GET /runs/:id/steps/:index/screenshot` (serves a live run's screenshot from its `actionPerformed`). Reuse s3-04's client in `packages/web/src/api/` (`subscribeToRunEvents`, `screenshotUrl`, `parseResponse`).
- **Contracts.** `RunEvent`, `Task`, `TaskId`, `ProfileId`, `RunId`, `Seed`, `SuccessCondition`, `Profile` from `@wayford/core`. web may not import io (`docs/STACK.md`, "Package import rules"), so io's two response bodies get their own zod schemas in `src/api/runs.ts`, built from core's.
- **Words** (`docs/DEMO.md`, "Words we do not use"): narration is the agent's, "quote it, don't diagnose it". No state is drawn as a mood on the face.
- **Function first** (`tasks/BOARD.md`, week 3): the shell's tokens and components; week 4 decides the look. Input register: persona colour as the one accent.
- **Stack.** No new dependency. Tests render with `renderToStaticMarkup` and stub `fetch` and `EventSource` with `vi.stubGlobal`, as s3-04 does: no jsdom, no testing-library.
- **Out of scope.** Live video, animation and Framer Motion, the dashboard and run detail, target-app parameters from the arena.

## Design

Logic in pure `.ts` modules, views in `.tsx` that render from props, and one screen file that holds the React state and the side effects. Every acceptance box is then a test of a pure function, or a static render of a view at a given state.

### Reaching io: `src/api/runs.ts` (extended)

```ts
/** The body of io's `POST /tasks` (`TaskRequest` in `packages/io/src/extractor.ts`). */
export type TaskRequest = { story: string; startUrl: HttpUrl; success: SuccessCondition };

/** io's answer to `POST /tasks`: 201 is accepted, 422 is refused. */
export type Extraction =
  | { ok: true; task: Task; rewritten: boolean }
  | { ok: false; error: string; goal: string; survived: string[] };

/** `POST /api/tasks`. 201 and 422 parse into `Extraction`; any other status rejects with io's `error` text. */
export async function extractTask(request: TaskRequest): Promise<Extraction>;

/** One run as io's `POST /runs` hands it back (`StartedRun` in `packages/io/src/runner.ts`). */
export const StartedRun = z.object({ id: RunId, profileId: ProfileId, seed: Seed }).strict();

/** `POST /api/runs` with `{ taskId, profileIds, seeds }`. 202 parses `{ runs: StartedRun[] }`; anything else rejects with io's `error` text. */
export async function startRuns(request: { taskId: TaskId; profileIds: ProfileId[]; seeds: Seed[] }): Promise<StartedRun[]>;
```

Both send `Content-Type: application/json` (io answers 415 otherwise). Any answer they do not accept (for `extractTask` anything but 201 and 422, for `startRuns` anything but 202) rejects with `io answered <status>: <error>` when the body carries io's `{ error }`, and `io answered <status>` when it does not, so the panel can show why: a 502 names the failed model call, a 404 the unknown task or profile. `parseResponse` drops the body of a non-OK answer, so both read the status first and call it for the accepted body only.

### The goals: `src/bundled-fixtures.ts` (extended)

`bundledTasks: Task[]`: core's `tasks.json` read at build time through the existing `@core-fixtures` glob, validated with `Task`, as the profiles and the measurement are. The target app's `GOALS` is a copy of that file in that order (`packages/target-app/README.md`, "Goals"; `src/goals.test.ts` checks it), so it is the source of the two presets.

### The start panel: `src/arena/panel-state.ts` and `src/arena/start-panel.tsx`

```ts

```

`StartPanel({ state, profiles, onAction, onCheck, onStart })` renders, top to bottom, inside one `<form>`-free `<section aria-labelledby>`:

1. **Goal**: a radio group (`<fieldset>` with a `<legend>`), one radio per preset labelled with its label and sentence, and its success condition in monospace (`URL matches **/deliveries/archive`), so the deterministic condition shows next to the sentence.
2. **Sentence**: a `<textarea>` with a visible label, then a "Check the goal" button (disabled while checking or when the sentence is blank). Under it, the check:
   - accepted: "The personas get: *goal*", then "Taken out: Deliveries, Order archive" (or "Nothing taken out"), and "Rewritten from your sentence" when `rewritten`;
   - refused: io's line that the goal still names the way after a repair, the words that survived, and the goal it got to;
   - failed: the message, in a `role="alert"` line.
3. **Personas**: a `<fieldset>` of checkboxes, one per profile, each labelled by the persona's name with a small avatar beside it. At five chosen, every unchosen box is `disabled`, and a line says "At most 5 personas: each run holds one of the browser's connections to io". Below three, the same line says how many more are needed.
4. **Seed**: a number input with a visible label, one seed for every persona (A20).
5. **Start**: a "Start the race" button, `disabled` while `startBlocker` returns a reason, with that reason as its `aria-describedby` text. No copy on the panel says "disabled": `router.test.tsx` bans the word from what the screen says (below).

### The race: `src/arena/avatar-state.ts`, `src/arena/race.ts`, `src/arena/race-view.tsx`

```ts
// avatar-state.ts
export const AVATAR_STATES = ["idle", "moving", "stuck", "done", "gaveUp", "error"] as const;
export type AvatarState = (typeof AVATAR_STATES)[number];
/** Judged steps in a row that left the page as it was make a persona stuck (revised in PR #151's review). */
export const STUCK_STEPS = 2;
/**
 * The state after `events`, the run's events so far in stream order, and where a stuck persona
 * stayed (the page's path). Pure, folded once. First match wins:
 * 1. `runFinished`: `success` is done, `gave_up` and `budget_exceeded` are gave up. `runFailed` is error.
 * 2. Stuck: the last `STUCK_STEPS` judged steps all left the page as it was. A step left the page as
 *    it was when the next step's observation is the same page as its own (all of `FullObservation`
 *    but `stepIndex` and `screenshotPath`) and it typed nothing (a `type` changes a value the
 *    observation does not carry). A step is judged once the next observation has arrived.
 * 3. Moving: at least one `actionPerformed`.
 * 4. Idle.
 */
export function avatarView(events: readonly RunEvent[]): { state: AvatarState; stuckOn: string | undefined };

// race.ts
/** What a tile shows, folded from one run's events so far. Pure. */
export type RunView = {
  state: AvatarState;
  /** Latest event timestamp less `runStarted`'s; `undefined` before `runStarted`. Never the local clock. */
  elapsedMs: number | undefined;
  /** The text of the latest `narration` event; `undefined` when there is none (a Jev run). */
  narration: string | undefined;
  /** The step of the latest `actionPerformed` that carries a `screenshotPath`. */
  screenshotStep: number | undefined;
  /** From the terminal event: the outcome, its timestamp, and `runFailed`'s error. */
  ended?: { outcome: RunOutcome; at: string; error?: string };
};
export function runView(events: readonly RunEvent[]): RunView;

/** The runs that have ended, shortest elapsed time first (revised in PR #151's review); a tie shares a place and keeps the start order. */
export function finishOrder(runs: readonly StartedRun[], views: ReadonlyMap<RunId, RunView>): { run: StartedRun; place: number; state: AvatarState; elapsedMs: number | undefined }[];

export type RaceSnapshot = { events: ReadonlyMap<RunId, readonly RunEvent[]>; streams: ReadonlyMap<RunId, StreamStatus> };
/**
 * One `subscribeToRunEvents` per run (so one `EventSource` each), folding every event into a new
 * snapshot handed to `onChange`. Returns the function that closes every stream.
 */
export function followRace(runs: readonly StartedRun[], onChange: (snapshot: RaceSnapshot) => void): () => void;
```

`RaceView({ goal, seed, runs, snapshot, profiles })` renders a heading with the goal and the seed, then one `<article aria-labelledby>` tile per run in start order, each with the persona colour as its top border:

- the persona's `Avatar` with `state={view.state}`, and the name as the tile's heading;
- the state in words, with its ground: "Moving"; "Stuck: the last 2 steps left /settings as it was"; "Done"; "Gave up" with the stored outcome (`gave_up` or `budget_exceeded`); "Error" with `runFailed`'s message; "Waiting" for idle; and when the stream failed for good before the run's end, "Stream lost: last seen <state>" with the avatar plain and dimmed;
- elapsed time from `view.elapsedMs` (`formatSeconds`, s3-04's);
- the latest screenshot, `<img alt="<name>, after step N">` on `screenshotUrl(runId, step)`, or "No screenshot yet";
- "Narration" as a label, then the latest line in quotes, or an empty line.

Under the tiles, "Finish order" as an `<ol aria-live="polite">`: place, persona, end state, elapsed. It is the one live region, so a screen reader hears each run end, not every step of five runs.

### The avatar's state variants: `src/avatar/avatar.tsx` (extended)

`Avatar({ profile, className?, state? })`. Without `state`, the markup is byte for byte what it is today (F1 AC4, its existing tests). With one, the `<svg>` carries `data-state="<state>"`, idle included, so a test reads every tile's state off its avatar; every state but idle draws a badge in the top-left corner, `<g data-part="state">`: a circle and one glyph (moving an arrow, stuck two pause bars, done a check, gave up a flag, error an exclamation mark); the title gains one sentence ("Run state: stuck."). The face never changes: a mood would diagnose the persona, which the demo's words rule out. All coordinates literal, so the markup still depends only on its props.

### The screen: `src/screens/arena.tsx`

Route `/arena`. `useReducer(panelReducer, initialPanel())`. "Check the goal" calls `extractTask(taskRequestOf(state))` and dispatches the answer tagged with the preset and sentence it was for, so an answer to an edited sentence is dropped. "Start the race" calls `startRuns(runsRequestOf(state, bundledProfiles))` and on 202 dispatches `startSucceeded` and switches to the race with the `StartedRun[]`; a `useRace(runs)` hook runs `followRace` in an effect and closes the streams on unmount. "New race" returns to the panel, keeping its state. The panel's profiles are `bundledProfiles`, the list io's `POST /runs` looks ids up in.

`src/router.tsx` adds `arenaRoute`; `src/shell.tsx` adds "Arena" between Preview and Runs.

### Data flow

Preset + sentence → `POST /api/tasks` → `Task` (rewrite, stripped words shown) → personas + seed → `POST /api/runs` → `StartedRun[]` → one `EventSource` per run → `RaceSnapshot` → per run `runView` → tile (avatar state, elapsed, screenshot URL, narration) and `finishOrder` → the list.

## Risks

- **Connections.** Five SSE streams over Vite's HTTP/1.1 proxy leave one connection for screenshots and the rest; images may lag behind the events. Acceptable for the demo; HTTP/2 is not on the table.
- **The real-key box** costs money: three runs of up to 20 steps each (`DEFAULT_MAX_STEPS`, `packages/agent/src/actor-loop.ts`; the time budget is `s2-10`'s, not merged). It needs the user's go-ahead.
- **Stuck on a quiet page.** Two steps that change nothing the filter can see read as stuck, even when something the observation does not carry changed (a hover state, a value set without typing). The tile says what was counted ("the last 2 steps left /deliveries as it was"), so the reader can judge.
