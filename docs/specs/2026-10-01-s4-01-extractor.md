# s4-01 — Extractor: spec

Task: `tasks/s4-01-extractor.md` · Branch: `feature/s4-01-extractor` · Date: 2026-10-01
Status: approved 2026-10-01

## Goal

`POST /tasks` turns a user story into a `Task` whose goal states an intent without a route through the interface, and shows what it stripped, or refuses and says why.

## Constraints that bind

- "A task must not contain the solution": the Extractor "must actively strip paths out of user stories" (`AGENTS.md`). `docs/PLAN.md` F3 AC1: it "rejects or rewrites tasks containing path words ... and shows the rewrite".
- "The model proposes, the schema decides." The model, role `extractor`, proposes a goal and what it removed; `Task.parse` runs core's path-word and stripped-path checks. One repair round when that fails, then `422` (task).
- `rewritten` is true when the stored goal differs from the trimmed story. The model is always asked (task).
- `sourceStory` holds the story verbatim, `strippedPaths` what was removed, both on the `Task` (task). "Verbatim" means trimmed: `Task.sourceStory` trims, so the stored story is the trimmed one.
- The success condition comes from the request, never from the model (task; `packages/core/src/task.ts`, `SuccessCondition`).
- Validation at the edge with `@hono/zod-validator` and the core schemas, "no second set of DTOs" (task, `docs/STACK.md` "API").
- The prompt is a template file a test can read. It names no persona and no impairment (task).
- One id generator in core for every `ID_PREFIXES` entry: the prefix plus a lowercase ULID, passing the core id schema, with no `Math.random` (task, `docs/STACK.md` "Ids", `docs/CONVENTIONS.md` "Determinism rules").
- No test calls a real LLM: io's tests use `fakeLlm` from `@wayford/agent/fake` (`docs/CONVENTIONS.md` "Tests").
- io reads `.env` in one place only, and importing io starts nothing (`packages/io/src/config.ts`, `index.test.ts`). s4-01 owns the boot call to `parseLlmSettings` (`docs/specs/2026-09-30-s2-01-llm-adapter.md`, "io").
- Out of scope: storing tasks (s4-02, week 3), proposing a success condition, a task input screen in `web`.

## Design

### Core: the id generator, `packages/core/src/id.ts`

```ts
import { ID_PREFIXES } from "./primitives.js";

export type IdEntity = keyof typeof ID_PREFIXES; // "profile" | "task" | "run" | "step" | "finding" | "sweep"

/** `<prefix>_<ulid>`: `newId("task")` → "task_01k6h3q8z1x7v2c9m4n5p6r7s8". */
export function newId(entity: IdEntity): string;
```

- **The ULID** is 26 characters of Crockford base32 in lowercase, `0123456789abcdefghjkmnpqrstvwxyz`.
  - **Time.** The first 10 characters encode `Date.now()` as a 48-bit big-endian number, so ids sort by creation time to the millisecond. This is a timestamp, which the determinism rules allow; no decision reads it.
  - **Randomness.** The last 16 characters are 16 bytes from `crypto.getRandomValues`, each masked to 5 bits, which gives 80 random bits. 256 is a multiple of 32, so each character is uniform.
- **Typing `crypto`.** It is a global in Node and in every browser. Core is compiled with no DOM and no Node types, though: filter's `tsconfig.perceive.json` compiles core's barrel, which is how `TextEncoder` broke there before (`random.ts`). So `id.ts` reads `crypto` through one local cast, `globalThis as unknown as { crypto: { getRandomValues(array: Uint8Array): Uint8Array } }`, inside the function.
- **No monotonic mode.** Two ids from the same millisecond have no fixed order between them. Nothing sorts ids within a millisecond.
- **Barrel.** One line in `packages/core/src/index.ts`, `export * from "./id.js";`, after `finding`.

### Core: one export from `task.ts`

```ts
/** Which of the stripped screen names a sentence still carries, as whole terms. */
export function strippedPathsIn(sentence: string, strippedPaths: readonly string[]): string[];
```

`Task`'s `superRefine` already computes this list inline, and its `wholeTerm` helper stays private. The function is the same expression lifted out, and the refinement calls it, so the behaviour does not change. The `422` names the screen names that survived with the same matcher that refused them. The file's own header gives the reason: the stripper and the schema "cannot drift apart".

### io: the Extractor, `packages/io/src/extractor.ts`

```ts
import { HttpUrl, SuccessCondition, type Task } from "@wayford/core";
import type { Llm } from "@wayford/agent";

/** The body of `POST /tasks`, built from core's schemas. */
export const TaskRequest = z
  .object({
    story: z.string().trim().min(1).max(2000),
    startUrl: HttpUrl,
    success: SuccessCondition,
  })
  .strict();
export type TaskRequest = z.infer<typeof TaskRequest>;

export type Extraction =
  | { ok: true; task: Task; rewritten: boolean }
  | { ok: false; error: string; goal: string; survived: string[] };

/** The prompt template, a file so a test can read what the model is told. */
export const EXTRACTOR_PROMPT_FILE: string; // packages/io/src/extractor-prompt.md

export function extractTask(llm: Llm, request: TaskRequest): Promise<Extraction>;
```

The model's answer schema is module-private:

```ts
const ExtractorAnswer = z.object({ goal: z.string(), strippedPaths: z.array(z.string()) }).strict();
```

It carries no keyword beyond types and `required`, so every strict `json_schema` mode takes it (s2-01 Risks: a `min(1)` becomes `minLength`, which some strict modes reject). The `Task` schema then decides on the answer.

The data flow of one `extractTask`:

1. **Id.** `newId("task")`, minted once, so a repaired answer keeps the same id.
2. **Ask.** `llm.complete({ role: "extractor", messages, schema: ExtractorAnswer })`, where `messages` is two messages:
   - **System.** The template file, verbatim.
   - **User.** The story, verbatim.

   No seed is sent. The model never sees `startUrl` or `success`: the success pattern is full of screen names (`**/deliveries/archive`), and the goal must not pick them up.
3. **Assemble.** The candidate is `{ id, goal, startUrl, success, sourceStory: story, strippedPaths }`:
   - `goal` is the model's.
   - `startUrl` and `success` come from the request.
   - `strippedPaths` is the model's list, each entry trimmed and empty ones dropped, so a stray `""` is not a `422`. It is always present, `[]` when nothing was removed.
4. **Decide.** `Task.safeParse(candidate)`. On success the result is `{ ok: true, task, rewritten: task.goal !== story }`. `story` is already trimmed by `TaskRequest`, and `Goal` trims the goal, so the two compare as the task asks.
5. **Repair, once**, when step 4 fails. A second `complete` with `[...messages, { assistant: JSON.stringify(answer) }, { user: <repair text> }]`. The repair text is built in code: `Your answer did not pass the task check:` plus `z.prettifyError` of the `Task` error, ending `Rewrite the goal so it says only what the person wants, and answer again with only the JSON object.` Steps 3 and 4 then run again. This round is the Extractor's own and separate from the adapter's: the adapter repairs an answer that misses `ExtractorAnswer`'s shape, inside one `complete`, while this round repairs an answer the `Task` check refuses. The code is straight-line, with no loop.
6. **Refuse**, when the repaired answer fails too. `{ ok: false, error, goal, survived }`:
   - `goal` is the trimmed goal of the last answer.
   - `survived` lists what the goal still carries: `pathWordsIn(goal)`, then `strippedPathsIn(goal, strippedPaths)`, without case-insensitive duplicates ("settings" and "Settings" once).
   - `error` reads `The goal failed the task check after one repair round:` followed by the prettified `Task` error. The wording is neutral because the same branch also covers a failure that is no route at all, such as an empty goal, for which `survived` is `[]`.

An `LlmError` from either `complete` propagates; the route maps it.

### io: the prompt, `packages/io/src/extractor-prompt.md`

Plain text, sent as the system message unchanged. It has no placeholders, because the story goes in its own user message. `extractor.ts` reads it once, at module load, so a missing file fails at boot. `index.test.ts` checks only that importing io reads no `.env` and starts no server, which this read does not do. It says:

- **When to change nothing.** When the story names no route through the interface, return it unchanged, character for character, whatever its person or phrasing ("I want to see what I ordered three months ago" stays first person). This is the task's "a story that already states a clean intent comes back unchanged with `rewritten: false`".
- **What to write otherwise.** One sentence: what the person wants, in their own words. When something had to be removed, write it in the second person, as in "you want to see what you ordered three months ago", the shape the task fixtures use.
- **What to remove.** Every route through the interface:
  - names of screens, pages, sections, tabs, menus and buttons;
  - the words button, click, menu, settings, tab and their forms;
  - steps and arrows ("go to", "open", "then", "->", "→").
- **What to keep.** The person's own words for what they want ("old orders", not "order archive").
- **The answer.** One JSON object, `{"goal": ..., "strippedPaths": [...]}`, listing every screen name and path fragment removed, as written in the story, or `[]`. The word "JSON" is in the prompt, which OpenAI's JSON mode needs (s2-01 Risks).

It names no persona, no impairment and no capability.

### io: the route, `packages/io/src/routes/tasks.ts`

```ts
export type TasksRouteOptions = { llm: Llm };
export function tasksRoute({ llm }: TasksRouteOptions): Hono;
```

`POST /` is `zValidator("json", TaskRequest, hook)`, then `extractTask(llm, c.req.valid("json"))`.

| Case | Status | Body |
|---|---|---|
| Extracted | `201` | `{ task: Task, rewritten: boolean }` |
| Refused after the repair round | `422` | `{ error, goal, survived }` |
| Body fails `TaskRequest` (no `success`, a bad URL, an unknown key) | `400` | `{ error }`, `z.prettifyError` of the zod error, from the hook. No model is asked. |
| Body is not JSON at all | `400` | Hono's own plain text, "Malformed JSON in request body". Its `json` validator throws before the hook runs. The status is right; one body shape for every 400 is not worth an `onError` here. |
| The model call failed (`LlmError`) | `502` | `{ error: "<code>: <message>" }`. The adapter's messages hold no key and at most 300 characters of provider text. |
| Anything else | `500` | Hono's default: a bug, not a model failure. |

The `{ error }` key matches the `404` in `routes/runs.ts`.

### io: wiring

- **`app.ts`.** `AppOptions = RunsRouteOptions & TasksRouteOptions`, so `llm` is required. `createApp(options)` mounts `.route("/tasks", tasksRoute(options))`. An io without an Extractor is a misconfiguration the compiler can catch. `app.test.ts` passes `fakeLlm({})` to its three `createApp` calls.
- **`server.ts`.** After `loadConfigFromEnvFile()` has merged the root `.env` into `process.env`, it builds the one `Llm`:

  ```ts
  createLlm(parseLlmSettings(process.env), { logger: pino({ level: config.LOG_LEVEL }) })
  ```

  It passes that to `createApp`. A missing key now fails io's boot with `invalid_llm_settings` and the variable named, as the STACK "Env" row asks. `config.ts`'s comment about the first route that calls the adapter is updated to point here.
- **One `Llm` for the process.** s2-01 builds one `Llm` per run, for the run's child logger. A task is not a run, and the adapter's lines already carry role and model.
- **The io barrel stays as it is.** The Extractor and the route are io-internal, like `routes/runs.ts`.

## Risks

- **The real-key box.**
  - **Reading the key.** `.env` and `.env.example` are denied to this session's read tools, on purpose. The agent does not copy or read secret files. At verify, the user either puts a `.env` in the worktree root, after which the agent runs the stack and the `curl`, or runs the `curl` and pastes the output.
  - **Credit.** s2-01 recorded that the key holder had no OpenRouter credit, and Luna answers a $0 balance with a 402, which this route returns as `502`. The fallback is `LLM_EXTRACTOR_MODEL=qwen/qwen3.8-27b:free` with `LLM_EXTRACTOR_EFFORT=medium` (free Qwen takes `xhigh`, `medium` and `low` only), set for that one command and recorded in the PR.
- **What the check cannot catch.** A screen name the model leaves in the goal and does not list passes: `Task` knows only the seven path words and what the model says it stripped. The reviewer note asks for three real stories to probe this. If one slips through, the fix is in the prompt. A deterministic screen-name detector is a different feature. The verify run tries three stories:
  - the task's own story;
  - a clean first-person story, which must come back unchanged;
  - a story with a screen name and no path word, such as "go to Order history to find the blender I bought".
- **`pnpm dev` now needs `LLM_API_KEY`.** Any printable value boots, because nothing is called at boot. A teammate without a key sees `invalid_llm_settings: LLM_API_KEY: missing`. `.env.example` already marks the key required since s2-01.
- **`@hono/zod-validator`'s hook types under zod 4.** The hook's `result.error` must take `z.prettifyError`. If the types disagree, the hook formats `result.error.issues` instead.
- **A second strict-mode surprise.** If a provider rejects even the keyword-free schema, the `502` carries its message, and the price table's `jsonSchema: false` for that model is the fix, as s2-01 designed.

## Review note

One round with the `spec-reviewer` agent. Verdict "ready after fixes", nothing blocking, two "should" and four nits. All six were taken:

- **Clean first-person stories (should).** The prompt returns any story that names no route unchanged, whatever its person, and uses the second person only for a rewrite. A clean first-person story joins the real-key probes.
- **The key (should).** Verify no longer copies the main checkout's `.env`. The user puts it in the worktree or runs the `curl`.
- **The `422` wording (nit).** It now reads "failed the task check", since an empty goal takes the same branch.
- **Malformed JSON (nit).** The route table names Hono's plain-text `400`.
- **"Verbatim" (nit).** It means the trimmed story, as `Task.sourceStory` trims.
- **The template read (nit).** The file is read once at module load.

No finding was rejected.
